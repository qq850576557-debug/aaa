# 春茉空间设计｜装修项目管理系统

SJD · 本地单人装修项目工作台。React 19 + TypeScript + Vite，保留第一阶段架构、IndexedDB 和 JSON 备份。初始数据为空，统计来自实际记录。

长期路线图、未来数据关系、员工私密信息权限及开发约定统一见 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)。其中规划能力尚未实现；当前本地模式没有真实账号与服务端安全权限隔离。

## 运行与验证

需要 Node.js 22.12+（当前环境使用 24）和 npm。

```sh
npm ci --cache /tmp/chunmo-npm-cache
npm run dev
```

默认端口 5173。`npm run build` 执行 TypeScript 检查并生成 `dist/`；`npm run preview` 用于本地检查生产产物。浏览器测试优先使用 `/usr/bin/chromium`，也可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`；其他环境先执行 `npx playwright install chromium`（Linux 可能需要系统依赖）。

```sh
npm test             # 日历、备份、IndexedDB、分段合并、顺延与排序计算
npm run test:e2e     # Chromium 桌面和触屏交互，使用独立测试浏览器上下文
npm run format:check
npm run build
```

测试见 `tests/workspace.spec.ts`、`tests/stage2.spec.ts`、`tests/review.spec.ts`、`tests/stage3.spec.ts` 和 `src/lib/*.test.ts`。测试会在隔离上下文导入测试记录，不使用或清除用户的浏览器数据。当前 Codex 环境引导界面没有交互端口预览；不要把云端 localhost 地址当作用户电脑可打开的预览网址。

## 浮窗与日期

项目、工种、任务、事项、备忘、采购和导出设置使用无整页遮罩的轻量浮动面板，背景可滚动；仅删除、覆盖和放弃修改使用模态确认；顺延决策使用无整页遮罩的浮动面板。Escape、外部点击、关闭和取消均经过统一关闭逻辑；表单有修改时二次确认放弃，关闭后保留页面及时间轴滚动位置。拖选松开后的 click 属于创建手势，不会误关刚打开的面板。双击时间轴空白日期直接创建一天工期条，无需先填写表单，可以立即拖动和拉伸。鼠标拖选则打开操作位置附近的任务浮窗；视口边缘自动避让，并跟随触发位置滚动和视口变化重新定位，小屏使用紧凑浮窗。日期使用轻量真实 Popover 日历，支持月份跳转、起止范围高亮，也可直接输入 YYYY-MM-DD。

任务的开始、结束和持续天数联动。调整开始日期时保留持续天数，调整结束日期或天数时重新计算；自然日包含首尾，周末正常计算，允许交叉施工，支持跨月和跨年。单项目与任务的合并日期范围最多 3 年，支持 1900—2200 年。

## 工期、分段与顺延

- 单击日期看每日事项；双击空白日期直接创建一天独立任务，名称沿用工种，可立即拖动与拉伸、撤销，双击条编辑。单击或双击已有时间条编辑，拖动整体移动，拖动两端拉伸。短任务可通过时间条或「施工任务」按钮编辑日期；手机使用相同表单作为等价操作。
- 在已有任务编辑浮窗点击「新增时间段」，或勾选「保存后继续创建下一段任务」，会使用同一逻辑任务标识 `groupId`。普通双击新建、复制任务是独立任务，不因名称相同建立关联。
- 拖动或编辑已存在的时间段时，仅将同项目、同工种、同逻辑任务的相邻或重叠段合并；起止取最早与最晚日期，采购和关联事项指向保留段，依赖关系重新映射。不同任务不自动合并。可用页面顶部「撤销」恢复完整操作前状态。
- 表单可设置明确的前序任务。延长任务会先计算完整建议，不立即写入受影响日期。浮窗列出变化范围与新完工日期，提供「顺延后续工期」「仅调整当前工序」「取消本次操作」。顺延保留各任务持续天数，不移动已完成任务或原有交叉施工。
- 未指定依赖时，仅按工种顺序保守建议：原本在前序结束之后、现在被延长覆盖的后续任务；新增任务则检查被新增时间段覆盖的后续工种任务。明确说明推断范围，不假设所有工序串行；用户可仅调整当前或取消。可在表单设置依赖以消除推断歧义。合并任务后依据被合并前序段的原日期判断依赖影响；顺延方案超出支持日期或项目跨度时，禁用该方案并显示原因，仍允许合法的「仅调整当前」或取消。
- 日期超出原计划时，计划起止会扩展以覆盖完整任务范围；取消不留下部分变化，向前收缩任务不会自行缩短原计划边界。后续采购截止日随关联开工自动计算。
- 「撤销」仅作用于最近一次工期或排序操作，保留在当前会话内；其他业务修改、复制项目、备份覆盖会清除该入口，避免撤销误删后续工作。它不代替长期 JSON 备份。

## 工种和颜色

拖动左侧手柄或工种标签的空白区域排序，有 60% 半透明拖影、强调色释放线与高亮。排序不移动任何施工日期。键盘可聚焦手柄按 Alt+↑/↓，或在工种更多菜单选择上移、下移。

工种之间悬停出现行内「+」，列表末尾始终有新增入口；触屏行内入口可直接点。插入仅改变工种排列，不凭空调整任务日期；为新工种安排任务后，根据实际依赖判断顺延。

点击工种色块或图例打开 300px 宽的紧凑锚定面板（色环直径 116px），提供色板、最近颜色、HEX、饱和度、明度和恢复默认。独立色环即时保存，关闭保留当前颜色，「取消并恢复」返回打开前颜色；工种完整表单中的颜色先预览，随表单保存。

## 工作台、事项和采购

项目总览与施工计划整合为「项目工作空间」。点击项目卡片或名称切换当前项目，不隐藏项目列表。卡片支持鼠标拖放、插入线与 60% 透明反馈，以及 Alt+←/→ 排序；以现有 `projects` 数组作为持久顺序，刷新和备份均保留，不再按更新时间打乱。已完工项目在独立历史区域保留全部记录。固定顶部显示选中项目及状态，分区快捷入口可直接定位今日事项、采购风险或时间轴。

施工单行从 100px 压缩到 56px，任务条仍为 36px 高、14px 字号；重叠任务自动增加独立轨道，不压扁文字。时间轴取消固定纵向内滚动，使用页面纵向滚动及独立横向日期浏览。

常用正文与时间轴关键文字提升至 14—16px，统一层级、点击区域和焦点状态。统计为零时显示「暂无」；非零直接显示实际数量。点击卡片按其类别查看项目或提醒。

当前项目摘要之后依次是今日事项、备忘、未来 15 天采购、逾期提醒和施工工期。今日事项显示待处理与已完成数量；事项与备忘支持完成、置顶、编辑、删除和搜索，始终按当前项目隔离。有日期和提醒的记录显示明确日期；所有提醒均为页面内计算，**没有系统推送或关页提醒**。

采购记录包含数量、单位（填写在数量文本）、规格、备注、负责人、状态和可选关联任务。已下单、待采购都纳入尚未到货提醒；已到货排除提醒并保留记录。未关联时用指定截止日期，关联时按开工前 N 天计算；删除关联任务时冻结当前截止日，不删除采购记录。

项目总数包含所有项目。进行中、今日待办和采购/施工风险统计排除已完工与旧归档项目。今日待办按事项日期或提醒日为今天计算并去重；未来 15 天采购为今天至第 15 天（含端点）；截止日早于今天且未完成即逾期。历史项目仍可查看原始未完成记录，不被自动改为完成。

## 已完工项目与旧归档兼容

日常操作使用「标记完工」及侧栏「已完工项目」，替代归档操作。完整保留任务、事项、采购和备忘，支持确认后恢复为进行中，删除需再次确认。

旧数据中的 `archived: true` 不转换、不清除，也不强行改变原状态；统一显示在历史区域，标识为原归档记录。恢复时明确把状态改为进行中并解除旧归档标志，保留原有日期及历史业务记录。

## PNG 导出

导出前选择日期范围、完整宽图或按月、1 倍或 2 倍清晰度（默认 2 倍）。渲染按完整数据绘制，不使用屏幕截图，不受横向或纵向滚动影响。每一天固定 64px，包含项目日期和总工期、月份、星期、工种、图例、全部任务段、任务明细及事项。

短条用 T 编号对应完整明细，避免为了容纳名称缩小字号；备注和长名称在明细中完整换行。每张月度 PNG 都有项目名称和日期范围；跨月任务用延续箭头提示，日期按当月范围裁段，完整任务日期仍在明细中。月度模式生成后逐张点击下载，避免浏览器拦截批量下载。

超过 6000 万像素或任一边超过 32000 像素时明确拒绝，不静默截断或缩小，提示改按月或 1 倍。生成期间显示状态并锁定日期和选项；修改日期、模式或清晰度会移除旧下载结果，需重新生成。反馈在视口顶部附近堆叠，成功约 3 秒消失，错误保留到手动关闭；重要确认由用户处理。过大的事项明细仍可能超过浏览器限制，可选择较小日期范围。

## 品牌素材和字体

第三阶段成功读取用户上传的 `方正启体简体.ttf`，从原字体提取“春茉空间设计”六字为 `public/fonts/chunmo-brand.ttf`（约 5.5KB），通过 `@font-face` 用于桌面、手机品牌名称及 PNG 品牌标题，导出等待字体加载。正文不使用书法字体，保持无衬线字体可读性。SJD 与唯一品牌标语「功能与美，共生」保持不变。

**原始 Logo 图形仍未接入。** 用户已在对话中明确给出图形，但当前工具能下载的第三阶段附件只有需求文本和 TTF，没有可读取的原始 Logo 图片文件。已检查资源目录；`public/brand.svg` 是第一阶段参考稿，绝不作为正式 Logo 展示、导出或重绘替代。字体接入不等于原图接入。

请将原始透明 PNG 或 SVG 作为文件附件提供，或存放到 `public/brand/chunmo-logo.png`（SVG 可用对应扩展名），在 `src/lib/brand.ts` 的 `BRAND_LOGO_SRC` 指向该真实文件后，UI 和 PNG 共用原图。当前值仍为 `null`，页面明确显示「原始 Logo 文件待接入」。已修正未来图片导出的等比缩放，不拉伸原图。

## 人员登记和姓名历史

项目、工种、任务表单中均有施工人员、项目经理、执行设计三类人员登记。可输入、复用历史候选或只清空当前值；项目经理兼容原 `manager` 字段，任务施工人员兼容原负责人 `owner`。工种人员登记会作为该行双击新建任务的默认值，任务仍可独立修改。项目摘要提供紧凑人员区和编辑入口。

历史候选在输入框下方显示；悬停或键盘聚焦显示「×」，触屏直接显示。删除前确认受影响项目，仅移出候选库，绝不删除或修改已有登记。未改动的既有姓名不会因再次保存备注而重新加入。历史库保存在同一份 IndexedDB 数据的可选 `nameHistory` 中，人员保存在各实体的可选 `personnel` 中，完整纳入 JSON 备份。

## 数据保存与安全

数据只在**当前浏览器、设备、网站源（协议、域名和端口）**的 IndexedDB `chunmo-workspace` 中，不上传 GitHub 或服务器，不跨设备同步。清除网站数据、隐私模式、浏览器驱逐或设备故障可能丢失；换端口/域名不是同一个数据空间。请定期下载 JSON 备份。本地版使用单个编辑标签页，尚不支持多标签页并发冲突处理。

保存串行执行，显示读取/保存状态和失败原因；失败保留内存数据，可重试或紧急备份。读入失败禁止覆盖原数据，关闭前仍有未保存数据会触发浏览器提示。

「数据与备份」下载完整 JSON；恢复前校验版本、字段、日期、重复 ID、项目/工种/任务/前序关系，拒绝循环依赖和无效关联，并展示全量覆盖范围，确认后用 IndexedDB 事务保存。最大文件 20 MB，恢复前务必备份。JSON 包含地址、姓名和备注，应妥善保管。

第二、三阶段继续使用版本 1，不改变数据库名、存储方式或已有实体 ID。只添加可选的任务分段与依赖、事项任务关联、采购数量规格及人员 `personnel`、姓名历史 `nameHistory` 字段。旧数据缺少这些字段时仍可读取，不需要破坏性迁移，也不在读取时自动重写数据。旧数据没有姓名库时，界面从已有姓名提供候选，首次保存人员或删除候选时才持久化姓名库；显式空库不重新从旧登记导入。新字段的备份需使用当前或更新应用恢复，旧版严格校验器可能拒绝新字段。
