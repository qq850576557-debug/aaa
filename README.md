# 春茉空间设计｜装修项目管理系统

SJD · React 19 + TypeScript + Vite 装修项目工作台。保留原 IndexedDB 本地模式，新增可选 Node.js + PostgreSQL 云空间：真实账号、服务端负责人权限、版本冲突保护与 SSE 同步。默认仍打开本地空间，不自动上传或清空已有数据。

长期路线图、未来数据关系、员工私密信息权限及开发约定统一见 [PROJECT_GUIDE.md](PROJECT_GUIDE.md)。规划与已实现能力须分别查看；本地模式仍没有服务端权限，云空间的实际能力与限制见 [阶段 B 运行和验收](docs/phase-b-cloud.md)。云端在开发/测试数据库验证，尚未部署阿里云。

本地功能原验收见 [统一整改与15天版本历史验收](docs/history-validation.md) 为准：新增项目级完整历史和事务式恢复，集中人员档案与分配，三字段采购录入。此前 [第四阶段报告](docs/phase4-validation.md) 保留为历史验收记录。

## 云端开发入口

云空间需要独立开发/测试PostgreSQL、初始负责人创建及API进程。准确命令、Windows安全密码输入、双浏览器测试、数据导入与权限边界见 [阶段B运行文档](docs/phase-b-cloud.md)。原本地模式依旧可只运行Vite。

## 运行与验证

需要 Node.js 22.12+（当前环境使用 24）和 npm。

```sh
npm ci --cache /tmp/chunmo-npm-cache
npm run dev
```

默认端口 5173。`npm run build` 执行 TypeScript 检查并生成 `dist/` 及 `dist-api/server.mjs`；`npm run preview` 用于本地检查生产产物。浏览器测试优先使用 `/usr/bin/chromium`，也可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`；其他环境先执行 `npx playwright install chromium`（Linux 可能需要系统依赖）。

```sh
npm test             # 日历、备份、IndexedDB、分段合并、顺延与排序计算
npm run test:e2e     # Chromium 桌面和触屏交互，使用独立测试浏览器上下文
npm run format:check
npm run build
```

测试见 `tests/workspace.spec.ts`、`tests/stage2.spec.ts`、`tests/review.spec.ts`、`tests/stage3.spec.ts` 和 `src/lib/*.test.ts`。测试会在隔离上下文导入测试记录，不使用或清除用户的浏览器数据。当前 Codex 环境引导界面没有交互端口预览；不要把云端 localhost 地址当作用户电脑可打开的预览网址。

## 浮窗与日期

项目、工种、任务、事项、备忘、采购和导出设置使用无整页遮罩的轻量浮动面板，背景可滚动；仅删除、覆盖、版本恢复、放弃修改和明确变更采购期限使用模态确认；顺延决策使用无整页遮罩的浮动面板。Escape、外部点击、关闭和取消均经过统一关闭逻辑；表单有修改时二次确认放弃，关闭后保留页面及时间轴滚动位置。拖选松开后的 click 属于创建手势，不会误关刚打开的面板。双击时间轴空白日期进入采购录入，自动继承项目和最晚采购日期，不创建施工任务。鼠标拖选则打开操作位置附近的任务浮窗；视口边缘自动避让，并跟随触发位置滚动和视口变化重新定位，小屏使用紧凑浮窗。日期使用轻量真实 Popover 日历，支持月份跳转、起止范围高亮，也可直接输入 YYYY-MM-DD。

任务的开始、结束和持续天数联动。调整开始日期时保留持续天数，调整结束日期或天数时重新计算；自然日包含首尾，周末正常计算，允许交叉施工，支持跨月和跨年。单项目与任务的合并日期范围最多 3 年，支持 1900—2200 年。

## 工期、分段与顺延

- 单击日期看每日事项；双击空白日期新增采购，施工任务通过明确入口或拖选创建，已有条的双击不打开编辑窗口，拖动整体移动、两端拉伸；右键打开轻量菜单，可编辑详情或确认删除。下方「任务详情与多段管理」提供独立详情入口，手机/键盘也可使用。
- 在已有任务编辑浮窗点击「新增时间段」，或勾选「保存后继续创建下一段任务」，会使用同一逻辑任务标识 `groupId`。明确入口新建、复制任务是独立任务，不因名称相同建立关联。
- 拖动或编辑已存在的时间段时，仅将同项目、同工种、同逻辑任务的相邻或重叠段合并；起止取最早与最晚日期，采购和关联事项指向保留段，依赖关系重新映射。不同任务不自动合并。可用页面顶部「撤销」恢复完整操作前状态。
- 表单可设置明确的前序任务。延长任务会先计算完整建议，不立即写入受影响日期。浮窗列出变化范围与新完工日期，提供「顺延后续工期」「仅调整当前工序」「取消本次操作」。顺延保留各任务持续天数，不移动已完成任务或原有交叉施工。
- 未指定依赖时，仅按工种顺序保守建议：原本在前序结束之后、现在被延长覆盖的后续任务；新增任务则检查被新增时间段覆盖的后续工种任务。明确说明推断范围，不假设所有工序串行；用户可仅调整当前或取消。可在表单设置依赖以消除推断歧义。合并任务后依据被合并前序段的原日期判断依赖影响；顺延方案超出支持日期或项目跨度时，禁用该方案并显示原因，仍允许合法的「仅调整当前」或取消。
- 日期超出原计划时，计划起止会扩展以覆盖完整任务范围；取消不留下部分变化，向前收缩任务不会自行缩短原计划边界。后续采购截止日随关联开工自动计算。
- 「撤销」仅作用于最近一次工期或排序操作，保留在当前会话内；其他业务修改、复制项目、备份覆盖会清除该入口，避免撤销误删后续工作。它不代替长期 JSON 备份。

## 工种和颜色

拖动左侧手柄或工种标签的空白区域排序，有 60% 半透明拖影、强调色释放线与高亮。排序不移动任何施工日期。键盘可聚焦手柄按 Alt+↑/↓，或使用工种旁上下箭头。

工种之间悬停出现行内「+」，列表末尾始终有新增入口；触屏行内入口可直接点。插入仅改变工种排列，不凭空调整任务日期；为新工种安排任务后，根据实际依赖判断顺延。

点击工种色块或图例打开 300px 宽的紧凑锚定面板（色环直径 100px），提供色板、最近颜色、HEX、饱和度、明度和恢复默认。独立色环即时保存，关闭保留当前颜色，「取消并恢复」返回打开前颜色；工种完整表单中的颜色先预览，随表单保存。

## 工作台、事项和采购

项目总览与施工计划整合为「项目工作空间」。点击项目卡片或名称切换当前项目，不隐藏项目列表。卡片支持鼠标拖放、插入线与 60% 透明反馈，以及 Alt+←/→ 排序；以现有 `projects` 数组作为持久顺序，刷新和备份均保留，不再按更新时间打乱。已完工项目在独立历史区域保留全部记录。固定顶部显示选中项目及状态，分区快捷入口可直接定位今日事项、采购风险或时间轴。

施工单行曾从56px压缩到34px；本轮上线整改恢复到68px以改善人员显示，任务条为 26px 高、14px 字号；重叠任务自动增加独立轨道，不压扁文字。时间轴取消固定纵向内滚动，使用页面纵向滚动及独立横向日期浏览。

常用正文与时间轴关键文字提升至 14—16px，统一层级、点击区域和焦点状态。统计为零时显示「暂无」；非零直接显示实际数量。点击卡片按其类别查看项目或提醒。

当前项目摘要之后依次是今日事项、备忘、未来 15 天采购、逾期提醒和施工工期。今日事项显示当前项目今日及逾期的待处理采购，并保留原有事项；采购与备忘始终按当前项目隔离。有日期和提醒的记录显示明确日期；所有提醒均为页面内计算，**没有系统推送或关页提醒**。

项目内新建每日事项为三字段采购表单：采购内容 / 事项标题、采购截止日期、详细备注。所属项目从上下文继承，显示只读信息。所有新建入口（今日、日期格、未来 15 天、采购管理、事项页）保存到同一份 `purchases`，不复制到 `notes`。今日列表、未来列表、全局统计、提醒中心和日期轴使用相同的截止日及完成判断。完成状态在采购卡片设置；已完成及旧“已到货”均不重复提醒，已下单仍视作未完成。旧数量、规格、负责人、任务关联字段不删除，记录中已有信息继续展示。

普通编辑可提前日期，也可在原定上限内调整，不能晚于原定或明确确认的期限。可选字段 `originalDue` 保存不可被普通编辑覆盖的原始上限；延期需独立“变更原定期限”确认、填写原因，保存 `approvedDue` 和完整 `deadlineHistory`，不替换最初日期。本地模式采用明确确认，不是账号授权；云端采用负责人专用API、服务端原定期限保护及审计。

旧关联采购首次读取时在内存固定当时有效截止为上限；施工提前可带动截止提前，施工推后不会静默推迟采购，仍需明确确认。手动改变关联采购的日期后采用固定采购计划，保留原任务引用作为查询线索，不反向改变施工起止或触发顺延。删除关联时间条时固定当前有效截止并解除引用，采购、备注内容不丢失。

今日采购包含今日到期和逾期未完成项；未来 15 天是今天至第 15 天（含端点）；日期早于今天即逾期。统一显示“今天截止 / 剩余 X 天 / 已逾期 X 天”，根据浏览器当前自然日计算，页面每 30 秒及重新聚焦时刷新，跨午夜无需修改记录。全局统计排除已完工与旧归档项目，按记录 ID 计算，不因同一记录在多个区域展示而重复计数。老 `notes` 保留原类型与内容，不根据同名文本猜测合并成采购；新的采购流程不再增加无关联的平行事项。

项目新建默认“施工中”；旧“筹备中”“进行中”保留可读，界面、筛选、统计和 PNG 统一显示/识别为“施工中”。编辑保存项目或恢复历史项目时使用新状态，不删除旧项目。施工任务自身“进行中”状态不是项目状态，保留原语义。

## 已完工项目与旧归档兼容

日常操作使用「标记完工」及侧栏「已完工项目」，替代归档操作。完整保留任务、事项、采购和备忘，支持确认后恢复为施工中，删除需再次确认。

旧数据中的 `archived: true` 不转换、不清除，也不强行改变原状态；统一显示在历史区域，标识为原归档记录。恢复时明确把状态改为施工中并解除旧归档标志，保留原有日期及历史业务记录。

## PNG 导出

导出前选择日期范围、完整宽图或按月、1 倍或 2 倍清晰度（默认 2 倍）。渲染按完整数据绘制，不使用屏幕截图，不受横向或纵向滚动影响。每一天固定 64px，包含项目日期和总工期、月份、星期、工种、图例、全部任务段、任务明细及事项。

短条用 T 编号对应完整明细，避免为了容纳名称缩小字号；备注和长名称在明细中完整换行。每张月度 PNG 都有项目名称和日期范围；跨月任务用延续箭头提示，日期按当月范围裁段，完整任务日期仍在明细中。月度模式生成后逐张点击下载，避免浏览器拦截批量下载。

超过 6000 万像素或任一边超过 32000 像素时明确拒绝，不静默截断或缩小，提示改按月或 1 倍。生成期间显示状态并锁定日期和选项；修改日期、模式或清晰度会移除旧下载结果，需重新生成。反馈在视口顶部附近堆叠，成功与失败浮动提示均约 3 秒消失，需处理的错误另外保留行内原因和重试入口；重要确认由用户处理。过大的事项明细仍可能超过浏览器限制，可选择较小日期范围。

## 人员登记和姓名历史

左侧「人员管理」统一维护姓名、类别、工种、备注及人员分配，支持新增、编辑、启停和保护性删除。项目、工种和任务用可选 staffIds 关联注册人员，工序编辑只选择已登记姓名，不重复登记资料。删除保留原 ID 与旧关联，避免破坏项目及历史。

原有 personnel、manager、owner 和 nameHistory 不改写，旧文字登记在人员模块可见，可按原姓名建档；未改动的姓名不因保存备注重新加入候选。新档案纳入业务备份、独立全局历史；项目历史只记录本项目的人员关联。本地模块不采集手机号/生日；云端私密API独立鉴权和加密存储，尚无私密资料编辑页面。

## 数据保存与安全

**本地模式**的数据只在**当前浏览器、设备、网站源（协议、域名和端口）**的 IndexedDB `chunmo-workspace` 中，不上传 GitHub 或服务器，不跨设备同步。清除网站数据、隐私模式、浏览器驱逐或设备故障可能丢失；换端口/域名不是同一个数据空间。请定期下载 JSON 备份。本地版使用单个编辑标签页，尚不支持多标签页并发冲突处理。

保存串行执行，显示读取/保存状态和失败原因；失败保留内存数据，可重试或紧急备份。读入失败禁止覆盖原数据，关闭前仍有未保存数据会触发浏览器提示。

「数据与备份」下载完整 JSON；恢复前校验版本、字段、日期、重复 ID、项目/工种/任务/前序关系，拒绝循环依赖和无效关联，并展示全量覆盖范围，确认后用 IndexedDB 事务保存。最大文件 20 MB，恢复前务必备份。JSON 包含地址、姓名和备注，应妥善保管。

第二至四阶段继续使用版本 1，不改变数据库名、存储方式或已有实体 ID。只添加可选的任务分段与依赖、事项任务关联、采购数量规格及人员 `personnel`、姓名历史 `nameHistory`、采购 `originalDue/deadlineMode/approvedDue/deadlineHistory` 字段。旧数据缺少这些字段时仍可读取，不需要破坏性迁移，也不在读取时自动重写数据。第四阶段仅在内存为旧采购补当时有效期限上限，下一次实际修改才随完整数据保存；无法追溯旧版本未记录的最初创建期限，不伪造历史。旧数据没有姓名库时，界面从已有姓名提供候选，首次保存人员或删除候选时才持久化姓名库；显式空库不重新从旧登记导入。新字段的备份需使用当前或更新应用恢复，旧版严格校验器可能拒绝新字段。
