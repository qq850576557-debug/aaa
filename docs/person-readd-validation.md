# 人员自由新增、删除与打卡保留

手动新增人员不再按姓名或资料指纹拦截，同名、同资料及已删除同名档案均不阻止新建。删除后的原身份继续作为内部历史关联保留，在用档案列表移除；新建使用独立唯一ID，不自动合并姓名、不继承或覆盖原打卡。请求ID幂等、CAS、权限、旧身份删除保护和历史恢复规则继续保留。

删除了人员管理“原有登记与历史姓名”区域的渲染、建档入口及专用样式，也删除了前后端资料指纹去重限制和不再使用的工具代码。保留已有 nameHistory、文字登记、任务关联、打卡和历史数据，不做真实记录清理或重分类。

施工人员选择器的可见文案和无障碍标签均去掉ID。同名选项仍以内部ID保存，已分配的删除/停用人员保留状态文字，新的可分配列表不会将已删除人员当作在用档案。人员卡片工种查找失败时也不再把内部键显示为工种名称。

处理旧版残留的“新增人员”草稿：显式新建操作恢复到已提交/已删除身份的旧草稿时保留输入内容、使用本次新建身份，不把旧身份复活。正常保存后清理该输入草稿，避免下次新建带入上次已提交身份；保存中阻止重复点击。业务同步草稿、恢复副本及服务端历史继续保留。

验证：

- 30 个单元测试文件、165 项通过。原资料去重工具及其旧限制测试随实现一起移除。
- 全量真实API回归 81 项通过，包括同资料新ID创建、删除后重新创建、重复请求幂等、原打卡和打卡修改历史逐字保留。
- 原人员/工期/备份浏览器回归 11 项通过。同步更新了已取消地址显示与现有96px工期行高的旧断言，未改工期布局实现。
- 新云端浏览器场景 1 项通过：删除后连续新增同名同资料、刷新后保留、恢复残留旧ID草稿不复活旧身份、打卡保持不变、选择器不展示ID且正确保存新身份。
- 前端、API、部署工具构建及格式、差异检查通过。

验证仅使用隔离测试数据，没有自动部署阿里云、访问生产数据库或删除真实档案与打卡。发布后真实人员列表及打卡需用户核对。
