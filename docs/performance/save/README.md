# 保存性能与页面交互验证

验证日期：2026-11-02。开发分支：`feat/chunmo-project-manager`。优化前基线：`b6a867d0436cc99a1615262b02d87939c13f4506`。

## 真实代码中的耗时来源

1. 原工作空间保存请求携带整个 `base` 和 `data`，修改一条项目备注也上传两份工作空间。样本请求约 267 KB。
2. GET 工作空间已有压缩逻辑，但带签名基线的 PUT 保存响应走 `res.json`，完整业务及历史响应约 1.1 MB，没有使用该压缩逻辑。
3. `graph()` 每次删除再插入所有项目、人员、工种、任务、采购、事项及人员分配投影。样本一次编辑触发 960 次投影行变动，实际涉及 480 个实体的删除和重新插入。
4. 保存路径重复获取已经锁定的工作空间状态；前端在本地落盘前也做重复校验和较重的同步规划。
5. 事项编辑器等待云端结果才关闭；编辑器的可选草稿清理也会延迟工作空间的确认流程。全局几秒钟防抖并非这条保存路径的主要问题。

没有访问阿里云或生产数据库，因此未直接核查用户现场的 5–6 秒耗时。下面是同一测试环境、同一合成数据规模的优化前后实际测量，不代表线上 SLA。

## 测量方法和原始数据

使用生产构建、Chromium、localhost 上的隔离 PostgreSQL 测试库；合成 20 个项目、60 段施工任务、200 条采购和 101 个历史节点。不导入员工数据。优化前从上述基线的独立归档目录构建，优化后从当前代码构建；两个阶段运行同一个 `scripts/save-performance.ts`。

口径：本地反馈从浏览器实际 click 事件计时到首个工作空间日志 readwrite 事务 complete，不含 Playwright 等待按钮的时间；整体耗时还包括收到响应后前端校验及日志收尾。服务器处理从请求体接收完成至 `res.end`；数据库统计包括该请求内的认证、事务、业务和审计 SQL，其中写入为 INSERT/UPDATE/DELETE 累计。数据库时间属于服务器处理的一部分，不能再叠加。浏览器请求时间包含传输、代理及浏览器处理，差值不等同于纯网络延迟。响应仍包含完整业务和保留期内历史，未通过删减历史减小结果。

## 保存机制与多人保护

- 用户编辑先持久化到按工作空间、账号及标签页隔离的 IndexedDB 日志；本地失败时明确报错并阻止不安全的上传。本地事务完成即反馈，下一任务开始后台同步，没有几秒钟的常规提交延迟。
- 工作空间新请求采用 protocol 3，只传变化资源的前后值及服务器签名。未修改的项目、任务、采购等不上传。服务器验证签名绑定的账号、工作空间、资源类型、ID 和原值，再与事务内锁定的最新状态做三方合并。
- 不同字段可合并；同字段冲突保留完整草稿并提示人工核对，不能静默覆盖。仍执行原权限、CAS、关系校验、事务、历史记录、追加审计和 SSE。
- 请求 ID 和实际提交体在发送前一起落盘，响应丢失后原样重试；审计回执在相同事务中保存，重复 ID 不产生第二次业务写入，相同 ID 改写内容被拒绝。
- 断网、服务器及不确定响应错误保留本地记录，带退避自动重试，online 事件提前唤醒。刷新、关页再打开、同账号重新登录后继续恢复。真实权限错误、输入错误和数据冲突保留并暂停相关请求，避免无意义重复写入；重新验证登录后可恢复 401/CSRF 失败请求。
- 事项编辑器在本地队列提交后关闭，后台结果只使用真实服务器记录和版本号。为避免“先排队编辑、马上用旧版本点完成”产生冲突，仅暂时禁用同一待上传事项的重复操作，其他事项和页面仍可使用。
- 云端确认之后才清理对应待同步项，编辑输入快照仍按原安全匹配规则清理。顶部提示合并工作空间和事项队列状态，一项确认不会把另一项尚未完成的上传显示成全部成功。

## UI 与旧数据兼容

- 下载图标保留；顶部手动本地备份文字入口取消。错误场景的紧急导出、输入恢复、待同步日志及原下载能力仍保留。
- 状态位于屏幕顶部居中，明确区分“正在保存到本地”“本地已保存 · 云端同步中”“云端已保存”和“同步失败”。只有真实云端确认后显示成功，约 5 秒自动收起。初次读取云端不冒充一次保存。
- 提醒中心先事项管理、后采购管理；采购按工地独立分组，每组独占一排，220px 方形小卡片在组内换行，操作按钮缩小。长内容可滚动，保留完整文本。
- 原有未归类事项继续在历史业务提醒区域显示，不擅自改变归属或迁移为新事项。

| 旧存储/数据                                             | 本次处理                             | 保留范围                                     |

| workspace_state 业务 JSON 与历史                        | 原结构、原保留规则，继续事务更新     | 项目、工种、施工任务、人员、事项、采购及历史 |

| IndexedDB 工作空间草稿、输入日志、事项 outbox           | 兼容读取，增加可选增量请求和失败信息 | 原账号未确认内容不清空                       |

未新增或改动数据库迁移，没有清库、重建真实数据或自动重新分类。来源和数量核对仅针对合成测试数据：提醒页面切换前后业务状态完全相等；数据库断言无关任务及人员分配 `xmin` 不变；历史、权限及原有迁移兼容用例继续通过。**生产数据数量、内容与生产历史未访问、未核查**，不能以测试库数量代替。

本次未部署阿里云。日后发布应先发布兼容的新后端，再发布前端；旧客户端仍可保存。回滚前端不会清理浏览器日志。已经产生 protocol 3 的未确认请求需要保留支持该协议的后端直到确认完成，不能为了回滚重造请求 ID 或丢弃草稿。
