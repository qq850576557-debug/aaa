# 保存反馈、云端版本与提醒中心验收

日期：2026-11-01。分支：`feat/chunmo-project-manager`；开发基线：`e18a968ae6356e69c292dd7501c30ffc4ae10325`。

## 检查结论与最小改动

原工作空间保存已经使用服务器版本号、签名基线、按字段安全合并、资源隔离、不可变提交回执、本地 IndexedDB 草稿及 SSE 通知。原 `history` 保存15天内按项目/全局范围的前后快照，每次有效修改都有节点，并非每天仅留最后一次。本次复用这些机制，没有替换存储架构或关闭 CAS。

缺口有三处：保存状态和撤销常驻头像附近；旧面板文案仍称本地记录且没有提交版本号映射；独立事项 `record_history` 只有修改摘要，不能还原备注等完整旧内容。提醒中心还在用分散的大块布局。

## 已实现

- 顶栏原保存状态只保留屏幕阅读/自动化使用的隐藏状态，不再占用视觉空间。实际保存请求收到确认后才显示顶部居中“已保存”，约5秒消失；连续确认更新同一提示并延长显示，不堆叠闪烁。保存/恢复进行中显示对应状态，冲突、部分未保存、草稿和失败不会显示整体成功。
- 撤销只随对应工作空间保存显示，仍使用原三方合并检查。事项保存、删除和恢复不会误带上此前工期修改的撤销按钮；5秒后提示与按钮一同消失。
- 首页“新建项目”右侧新增云端历史入口。桌面锚定下拉，窄屏为适应视口的弹出面板；日期分组，展示服务器时间、姓名、提交/事项版本、范围和摘要，区分当前版本。列表分段显示，每次50条，避免一次渲染大量节点。
- 工作空间节点复用原快照，只另存真实提交编号映射。同次提交涉及多个范围时可以有多个节点共享工作空间版本号；事项采用自身版本号，不伪装成同一套全站编号。未知旧编号显示未记录，导入的未核验历史不补造原服务器编号。
- 事项每次实际变化保存完整内容快照。相同内容不增加版本；重复请求返回原回执。升级前只能建立当前实存版本基线；旧版已有摘要仍可查看，但不存在的旧内容不能虚构恢复。
- 查看版本时优先显示可读的项目/人员/工种/任务列表或事项字段，完整原始数据可展开核对。普通成员可查看公开业务历史；恢复和完整恢复前备份下载仅限负责人，服务端独立校验。
- 恢复先捕获当前完整工作空间与当前事项，检查工作空间版本及所选事项版本，事务内执行恢复、保存自动备份及新历史节点。原历史不删除；恢复来源编号保留在工作空间历史或事项恢复回执及审计中，失败整批回滚。恢复使用稳定请求编号，可安全重试。备份写入失败明确返回“本次恢复已回滚”，不能越过备份执行恢复。
- 原历史入口的恢复同样接入自动备份，原“恢复到修改前”语义保留；新入口“恢复此版本”恢复所查看的修改后内容。相同当前内容不产生无意义恢复节点。
- 提醒中心以采购卡片为基准，分采购、事项、其他业务/历史待分类区域。采购继续复用原卡片、截止日期和审批逻辑；事项复用原记录，可在当前页面编辑、完成和二次确认删除。材料核查沿用原授权与原组件。空状态压缩为紧凑提示，按钮与卡片在320px也能换行。

## 数据库与兼容性

增量文件：`server/migrations/013_cloud_versions.sql`。

1. `workspace_history_revision`：现有历史节点与真实提交编号的映射，不复制工作空间历史正文。
2. `record_version`：事项完整版本，主键按工作室、事项、版本唯一；数据库触发器捕获后续写入。仅回填每条旧事项的当前真实版本，不改写原记录，不补造此前的内容。
3. `cloud_restore_backup`：恢复前当前数据与精确重试回执，只追加、不可普通删除或修改。

旧工作空间历史仍按原15天策略维护；事项新写入时清理该事项超15天的旧快照，保留当前基线，不删除当前业务数据。旧审计摘要和恢复前备份不随快照清理。备份长期保留，不自动删除既有备份。工作空间仍保留原有15天内最多10000个有效节点的保护上限；超过上限会明确拒绝本次保存并保留草稿，本轮没有声称实现无限历史或生产高负载扩展。

001—012内容未改。013及最小运行授权只在独立本机测试库应用。生产尚未执行；后续部署须先做可恢复备份，再使用配套迁移及授权流程，完成后启用匹配版本的前后端。旧代码回退仍能读取原业务字段，前提是保留新增表的运行授权。

此入口恢复范围为所选项目、全局人员范围或单条事项；独立材料库存、考核、账号及私密资料继续使用各自原有审计/权限流程，不在这里整体回滚，也不进入公开版本快照。

## 实际测试

- 单元：145项通过。

- 故障注入：只在测试库为自动备份增加临时检查约束，分别阻止事项恢复和工作空间恢复的备份落库；两者数据、快照、历史和审计全部回滚。移除测试约束后相同请求成功，未留下测试约束。
- 增量迁移：旧事项内容、姓名、版本、身份及原有业务行保留，重复迁移幂等；只建立旧事项当前快照。

- 本地浏览器：原历史/采购16个场景最终均通过；复测覆盖其中失败的旧文案断言与工期安全撤销，保留业务及数据完整性断言。
- 部署工具：22项通过；部署工具构建通过。未执行真实部署。
- 前后端类型检查、生产构建、修改文件 Prettier 与 Git diff 检查均通过。仓库未配置独立 Lint 命令，本轮没有虚报 Lint 结果，也没有为此增加依赖。
