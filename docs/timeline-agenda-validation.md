# 时间轴与采购、事项联动验收

日期：2026-11-01。分支 `feat/chunmo-project-manager`，开发基线 `79a1c4ddf835130434ec554f608cf730b5febc8d`。

## 根因与数据归属

采购来自工作空间 `purchases`，事项来自独立的 `work_record`，旧提醒/备忘来自 `notes`。已有 `categorizedAgenda` 提供日期视图，历史迁移映射负责排除旧来源的重复投影。时间轴此前没有读取 `work_record`，仅统计旧 Note 和未完成采购，日期详情也使用旧逻辑，导致新版事项缺标记、已完成记录不可见。

本次扩展共享日期视图返回完整 `items`，时间轴、悬停摘要和日期详情使用同一数据映射，不新增业务表或同步复制记录。采购日期继续使用 `purchaseDue` 的实际期限口径，事项使用 `nodeDate`；带日期的旧备忘也兼容显示。无日期记录不会伪造日期或生成红点。迁移来源的去重及未保存本地草稿保护沿用上一版本。

## 实际改动

- 两种新增类别保存后关闭弹窗、留在发起页面。采购提示“已添加，正在自动保存”，不提前声称云端提交成功；事项在 API 成功后提示已保存。保存失败继续使用现有草稿和重试机制。
- 时间轴日期单个红点改为 7px，包含当天事项、采购及已完成记录。日期表头最小高度桌面 90px、手机 94px，工种行最小高度桌面 96px、手机 104px。没有机械缩放文字。
- 整个日期格悬停或键盘聚焦均可显示摘要，按事项、采购分组，显示标题、状态及当前工地；每组最多四项，其余可点击日期查看。使用 body portal 避免滚动容器裁切，固定位置限于视口，CSS 180ms 渐显/渐隐，延迟移出避免进入摘要时闪烁，支持减少动态效果。触屏点击日期查看完整当天内容。
- 点击日期后的事项、采购可直接在当前页面打开编辑、标记完成，不再先跳到管理页。
- 工种统一显示“施工XX天”；保持按合并后时间段计算的原有天数口径，任务数量仍使用数量文案。
- 记录与采购编辑支持移至当前工作室的其他有效工地。事项沿用同一 ID、版本、创建信息，历史记录项目变更。采购保留 ID、原定期限和审批历史；移动工地时解除原工地的施工任务绑定并采用固定日期，避免留下跨工地任务关联。目标工地不存在、属于其他工作室或版本过期的请求仍拒绝。
- 原版本显式禁止记录/采购换工地，本轮按需求移除此限制；没有扩展账号管理、私人资料或其他模块权限，没有关闭 CAS、审计、CSRF、认证和延期审批校验。

## 验证记录

- 单元测试：145 项通过。
- 完整 API 回归：59 项通过；另新增 1 项真实 API 专项，验证事项/采购换工地、ID 与原期限保留、历史、旧版本冲突以及跨工作室关联拒绝。
- 本地时间轴回归：11 项通过，覆盖桌面/手机滚轮作用范围、任务拖拽/拉伸、时间段合并、提前/顺延以及数据刷新。
- 前后端类型检查和生产构建通过；保留既有大包体积提示。
- 云端模式浏览器回归已通过 28 项，含四人独立编辑、10 个独立账号、断网重试、草稿恢复及同字段冲突保护。修复后桌面/手机联动专项 4/4 通过，包含管理页新增的反向投影、已完成标记、换工地、改日期、删除及刷新。最终格式检查通过。使用本机隔离测试服务和测试数据库，不是生产环境。

首轮浏览器的三个失败均定位为测试适配问题：一项仍期待保存后跳转，新加入的两个联动测试漏建第二个工地。已改为验证原页面可见、表单关闭及已有数据/回执断言保留，并补齐第二工地测试样本，没有删除业务保护断言。随后实际链路测试定位到前端 `savePurchase` 的旧迁移限制也阻止了保存，已修复并补齐单元测试，保留所有期限与审批防伪断言；两个受影响的桌面/手机链路已在修复后重新验证通过。

## 人工验收

1. 在时间轴点击日期，新增采购/事项，保存后仍在原页面，当天显示一个红点；悬停可分别查看两类摘要。
2. 从两个管理页直接新增，再返回项目定位到对应日期，核对标记与摘要。修改日期、工地后原位置消失，新位置出现；删除后刷新不再显示。
3. 在桌面、真实手机及微信内置浏览器复核浮层位置、手指点击日期、长标题和较多记录；真实手机软键盘与 Safari 仍需人工验收。

没有数据库结构迁移，没有部署或操作生产数据库。
