# V1.0 上线整改状态（2026-10-24）

本轮从 `9953716`、干净的 `feat/chunmo-project-manager` 增量修改。阶段 A **部分完成，未整体验收**，不得因此进入正式生产发布。

## 本次实现

- 一级项目工作空间与独立展开箭头、四个二级菜单、独立人员入口。切页保留展开状态；当前没有账号服务，以 `chunmo-local-navigation` 保存浏览器临时偏好，明确不是 user_id 偏好或云同步。
- 人员页面不显示项目统计；桌面人员卡片3–4列，手机单列。履历以 projectId 去重，从现有项目/工种/任务 staffIds 派生分类数量、项目地址、工种、具体任务段与日期，不另存一份姓名或日期。
- 工种与任务编辑复用注册人员选择，施工人员支持多选。工种页只选择已有档案，分配后人员履历同步更新；人员模块原分配入口使用相同 staffIds，工种姓名同步读取。
- 工种单行由34px增至68px，右侧同行同高，条垂直居中；名字和任务天分行，师傅姓名可点选、完整名单有title。清理未使用的三个点菜单CSS。拖放、排序、颜色及采购原联动保留。
- 项目摘要和卡片显示自然日剩余工期，含7天以内、当天完工、逾期、已完工与未设截止的判断。日期变化及跨午夜通过原当前日期hook更新。
- 常规编辑/确认浮窗统一收紧宽度、内边距和75%视口上限；历史查看保留大面板，色环保持100px。没有使用transform缩放。
- 原数据模型、数据库、历史快照和恢复机制不重建，不清IndexedDB。

菜单死样式清理后的16项针对性浏览器测试通过。曾尝试加宽名称区，但实测发现拖放排序及125%缩放拖动回归失败；已撤回该宽度修改，保持原日期轴宽度，只调整标签内部排列。失败断言保留。独立浏览器事件检查确认 drop 携带正确工种 ID 且数据顺序实际更新；进一步事件检查定位到提示位移与move放置操作问题：生产代码固定落点位置并明确设置dropEffect=move。原拖放用例保留原手势及全部顺序/日期断言，临时日志已移除。最终全量复验 **47/47通过**（约1.9分钟），单元测试 **54/54通过**，生产构建、格式与差异检查通过。当前测试无失败；这不等于阶段A全部需求或上线安全验收已完成。
