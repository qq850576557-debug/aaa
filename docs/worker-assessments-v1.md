## 核查和实际实现

本分支原有人员档案、项目/工种/任务分配、真实账号与负责人权限，**没有每日签到表、字段或页面**。经用户确认，本轮同时补齐监理手工记录的轻量签到：待记录、已签到、未签到，不采集签到/签退时间、时长或定位。下班拍照、下班卫生各自三态，独立修改；这些只是监理根据微信群报备作出的记录，不代表网站获取了现场照片。

入口为人员管理中的“师傅日常考核”。日期、项目（含完工）、工种、师傅、考核项及状态可筛选；绿色表示完成、红色未完成、灰色待记录。点击标签用现有轻量浮窗修改；批量选择最多100条，弹层列明日期、师傅、项目和工种，确认具体字段后再保存，取消不写入。

列表候选只来源于真实登记的施工人员及现有项目团队/工种/任务分配。项目团队成员可在该项目的工种中选择记录，监理须核对实际工种；建议先在工种或施工任务分配师傅。旧姓名文本不自动建档或伪造签到。未保存候选标记“尚未保存”，不写入历史、不自动计为未完成、不进入统计。

“师傅考核统计”是人员管理内独立的统计视图，不在主屏堆放大卡片。支持月度、年度、自定义历史范围，按师傅和项目分组汇总已拍照/未拍照/已打扫/未打扫及各自待记录次数，同时展示每日明细和修改历史。完工项目仍可筛选。统计只读取真实保存记录；同一天多个工种按独立考核记录计次，并明确标注口径。没有惩罚、扣款、评分或自动淘汰规则。

服务端CSV导出复用权限和筛选，带UTF-8 BOM，正确引用逗号/引号并中和电子表格公式前缀。一次最多50000条，超过时明确拒绝并要求分批，不静默截断。列表每页1000条，客户端自动取完后统计，不只汇总第一页。

## 权限与安全

| 身份                   | 读取、统计、CSV、修改历史 | 记录/修改    | 授予/撤销记录人权限      |
| ---------------------- | ------------------------- | ------------ | ------------------------ |
| 工作室负责人           | 本工作室全部              | 本工作室全部 | 可以，仅本工作室在用账号 |
| 负责人授权的考核记录人 | 本工作室全部              | 本工作室全部 | 不可以                   |
| 其他员工               | 拒绝403                   | 拒绝403      | 拒绝403                  |
| 未登录/失效账号        | 拒绝401                   | 拒绝401      | 拒绝401                  |

负责人通过“考核记录人授权”指定真实账号，可授权其作为监理统一记录。人员档案里的“监理”名称不是登录授权。授权范围当前是整个工作室，尚无单项目监理ACL；界面明确提示授权范围。考核授权不包含手机号、生日、账号管理等其他权限。普通员工仍可读工作室一般操作记录，但通用审计仅记录考核保存事件及随机操作ID，不包含考核结果、师傅姓名或私有修改历史。未授权员工不能通过业务JSON导出、15天历史、直接考核API或CSV获取考核内容。

所有API经过已有真实认证、Origin/CSRF与有效账号检查；操作人ID、操作时展示名称和时间均由服务器生成，不能在请求中伪造。撤销记录人权限后，每次读取/写入/导出重新校验；页面30秒或重新获得焦点时刷新，已看过的数据无法从人的记忆或外部副本撤回。

## 数据库增量迁移

新增 `006_daily_assessments.sql`，不修改已应用迁移：

- `assessment_recorder`：工作室与获授权账号、授权人、授权时间。
- `daily_assessment`：工作室、日期、师傅ID、项目ID、工种ID、版本、三态结果及首次/最后记录人和时间、当时名称快照。自然唯一键为工作室+日期+师傅+项目+工种，杜绝重复记录。
- `assessment_history`：独立的追加式修改前后值、操作者名称快照和服务端时间；触发器及运行账号SQL权限禁止更新和删除。
- `assessment_submission`：请求ID、主体、请求摘要和结果，抵御双击和网络重试重复提交；同标识不同请求409。

沿用工作室和账号外键。业务对象ID及其当时名称以快照保存，不对会被现有工作空间保存流程替换的 person/project/trade 投影建立级联删除：新记录必须在服务端验证真实对象/分配；已有历史记录即使人员或项目后来移除，仍保留可追溯信息。

写入在事务中验证权限及原始版本，按工作室串行化短写事务与授权撤销；两人同版本修改只成功一方，另一方409，整批失败回滚。相同值不新增修改历史。修改保留首次记录人，更新最后修改人和时间，历史名称不回写。数据及考核历史独立于15天业务版本，恢复旧项目不抹去或回滚考核；CSV是报表，不是可回写备份。

`cloud-provision.ts` 和原生部署授权配置增量加入新表、最小读取/写入及追加权限；006加入显式迁移校验清单。现有加密数据库备份动态覆盖全部表，因此包含考核、修改历史及授权。生产部署前仍须使用现有备份步骤，迁移由受控部署流程执行；本轮没有连接或迁移生产库。

## 使用与人工验收

1. 负责人进入人员管理，确保师傅已登记并分配至项目/工种；进入“考核记录人授权”，核对目标账号后确认。
2. 监理以自己的账号登录，选日期和项目，在每日考核表独立记录签到、下班拍照、下班卫生。对照弹层的具体对象确认保存，刷新复查。
3. 批量选多人，先取消确认验证不写入，再确认保存；检查未选字段不变。
4. 进入“师傅考核统计”，选月度、年度或历史范围，再按师傅或完工项目筛选、查看修改历史及导出CSV。未保存日期不自动生成考核次数。
5. 用未授权员工直接请求考核/导出API应403；撤销记录人授权后同样拒绝。两会话同时编辑同一原版本，应一方成功一方409，而非静默覆盖。
