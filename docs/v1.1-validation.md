# V1.1 界面与账号管理升级

适用分支：`feat/chunmo-project-manager`。本轮没有连接或更改运行中的 ECS，没有清空 IndexedDB 或重建生产数据库。

## 已实现的业务闭环

- 默认进入独立品牌登录页，服务端验证会话成功后才挂载工作台；账号密码登录后直接进入云空间。过期会话锁住工作台，重新登录；未保存草稿只在原页面内存中保留，换账号不能看到旧工作台。生产构建不能用 URL/浏览器存储绕过认证。所有业务 API 继续检查服务端账号、工作室和权限。
- 已登录入口为“账号管理”，自动读取当前会话；中文正式展示名称与登录名/稳定ID分开。负责人可主动将正式名称改为“马春旭”，`studio_owner` 登录名和原ID不变。没有强制首登改密弹窗。
- 自行修改密码验证原密码；负责人可重置员工密码、停用/恢复员工及编辑员工正式名称。8–128位、Argon2id、会话撤销、CSRF、Secure Cookie和限流保留。
- 账号通讯录支持“我的私有备注”，以工作室、作者、目标账号组成复合主键；负责人也不能通过应用 API 阅读他人写的私有备注。服务端不把备注写进审计或业务导出。
- 手机甘特图采用独立网格：名称/天数、师傅、排序操作分区；固定栏162–190px，行高至少124px，触摸按钮/时间块最小44px。保留横向日期滚动、固定工种栏、排序、详情、时间块拖动；桌面基础行高保持68px。底部导航允许触摸横向滚动，不删入口。
- 登录、侧栏和工期PNG共用植物Logo资源与品牌字体，SJD标识保留。`public/brand/chunmo-plant.png` 是基于本次上传图经图像工具提取适配的页面资源，非原始矢量文件；上线前应由负责人目视确认品牌细节，可用正式源文件替换同一路径。

## 兼容迁移与数据关系

`003_accounts_audit.sql` 为可追踪增量迁移，不改001/002校验和：

- `account.display_name` 默认为空，兼容旧账号并回退显示登录名。既有ID、密码哈希、角色、工作室及业务关联不重建。
- `account_note(workspace_id, author_id, target_id, note, updated_at)` 通过工作室/账号复合外键防止跨工作室记录；API固定当前作者身份。
- `audit_event` 增加操作时正式名称快照、对象类别/编号、操作类型、安全修改前后值、涉及字段及简化设备信息。审计与业务提交处于同一事务；新增、修改、删除、导入、历史恢复均由服务端比较真实提交前后数据生成。
- PostgreSQL应用角色没有审计UPDATE/DELETE权限，数据库触发器进一步阻止更新/删除；没有普通用户的审计修改/删除接口。数据库超级管理员仍属于可信运维边界，这不是防超级管理员篡改的外部审计账本。
- 新字段有默认值，旧版本审计INSERT形状兼容。代码回退不执行反向迁移；新名称、备注、审计数据保留。旧版本产生的记录无法具备V1.1完整字段。

审计只记录白名单中可验证的日期、状态、顺序、布尔值和受控关联摘要。自由文本仅标记字段发生变化；对象和关联编号以服务器密钥生成不透明引用，不把任意业务ID当成安全文本。密码、会话、Token、Cookie、密钥、手机号/生日、私有备注、完整表单及原始User-Agent不进入审计。正式展示名中的明显手机号/Token模式也会脱敏。旧审计不能追溯补造设备或修改详情。

设备信息来自请求User-Agent，属于未经硬件验证的浏览器声明。可识别电脑/手机/平板、系统及浏览器；iPhone显示“iPhone（具体型号不可识别）”。某些iPad桌面模式与Mac完全相同，不能可靠区分。支持按操作人、对象类型、操作类型、北京时间日期范围筛选及分页；对象编号是审计引用，不是泄漏自由文本的项目名称。

## ECS 更新（本轮未在服务器执行）

先备份再迁移。`pre-update.sh` 在现有部署锁内调用旧版本加密数据库备份，再以root-only目录归档当前发布版本、Nginx、配置及TLS文件，并核验SHA256；任一步失败停止，不删除旧文件或数据库。这些归档包含私钥，只能由可信运维保管，不能发给员工或提交GitHub。

```bash
sudo -i bash <<'CHUNMO_V11'
set -Eeuo pipefail
cd /opt/chunmo-source
test "$(git branch --show-current)" = feat/chunmo-project-manager
git pull --ff-only origin feat/chunmo-project-manager
bash deploy/native/pre-update.sh
bash deploy/native/deploy.sh
CHUNMO_V11
```

部署器核对批准的迁移清单，执行003及最小权限授权，保留现有 `public-https.json`、内部CA/私钥、原公网HTTPS 15001、localhost8443、Node127.0.0.1:4000和PostgreSQL本机监听。无需重新签发证书、安装Docker、改安全组、全局关闭防火墙或导入本地数据。既有每日加密备份/健康timer保留。备份配额不足会停止，不会自动删除旧备份。

验证数据库备份：`bash /opt/chunmo-staging/current/deploy/native/backup.sh verify /var/backups/chunmo-staging/实际文件.cmbackup`，只创建新的隔离恢复库，不能指向生产库覆盖。更新后需由负责人在已信任内部CA的浏览器中检查公网地址、姓名、私有备注和移动端效果；云端环境不能证明ECS安全组/外部网络可达。

自动部署失败保留既有代码回退机制。人工代码回退应在可信运维窗口：从受保护快照的 `previous-release` 核对旧目录及 `.verified-build`，把 `current` 原子切回该旧目录、原子恢复快照Nginx配置，先用服务账号验证 `nginx -t` 再重启API/Web并检查HTTPS健康。不要删除003字段/审计表，不要将旧数据库备份直接覆盖生产。配置/私钥仅在确有损坏且核对后恢复，不能随意轮换。真实ECS systemd回退仍需管理员执行，本轮只做隔离兼容/恢复测试。

## 验收与限制

真实浏览器测试为Chromium桌面与移动触摸仿真，含320/375/390/430屏宽和CDP触摸拖动，不代表已经在实体iPhone/iPad或Windows Edge上测试。设备型号和品牌图细节保留上述人工确认限制。生产数据库备份、部署、外部网络访问和ECS服务回退均未在本轮远程执行。
