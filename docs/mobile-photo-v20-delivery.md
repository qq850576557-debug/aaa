# 手机拍照 V2.0：PWA批量保存流程交付

## 已实现的流程

拍照入口 → GPS/附近地址弹层 → 确认地址 → 浏览器系统相机入口 → 返回网页自动加水印 → 继续拍摄/网页连续拍摄 → 完成拍摄 → 保存本次照片 → 系统分享 → 用户选择“存储图像” → 用户确认相册已保存后清理对应副本。

- 地址弹层复用V1.3服务端GPS、2公里混合POI、搜索、分页及手动名称签名；未确认地址不调用相机。无有效GPS禁止确认拍摄。
- 确认地址在用户点击事件中直接调用原生文件相机入口（capture=environment）。浏览器可能提供选图或拍完返回网页，不能强制保留在系统相机内连续拍摄。返回后“继续拍摄”需再点一次；“网页连续拍摄”采用保留后置摄像头的getUserMedia，会话内可连续按快门。
- 系统相机内部无法叠加网页实时水印，返回后自动合成；网页连续拍摄提供实时水印预览。预览按实际视频宽高比约束，避免竖屏留黑区域错位；最终水印按照片实际像素生成。
- 授权由iOS/安卓/浏览器管理，已有授权时通常复用，但不能保证“一次授权终身有效”，不重复主动清除或重置授权。
- 固定水印为原始Logo、春茉设计、工地定位、北京时间年月日时分、当前登录姓名。照片文字不加“附近”或“手动”；真实GPS、精度、定位时间、地点来源和POI坐标另存于元数据，不能把人工地点视为建筑位置证明。
- 复用原高清水印处理器及方向处理。原始捕获先可靠暂存，水印生成和持久化成功后用水印图替换该临时原图，不长期双份保存。渲染失败仍保留唯一原始捕获以重试/导出；空间不足时保留当前页面内存副本并提示不要关闭，提供重试及导出，不谎报可靠落盘。
- 以JPEG XMP自定义来源元数据附加真实定位及来源，不更改像素，不输出签名token。系统相册或后续转发是否改写自定义元数据仍需真机验证；PWA无法从相册读回核对。

## 保存状态与错误处理

“保存本次照片”在用户点击事件中直接将已生成的水印File数组交给Web Share，不先执行异步解码或读取导致用户激活失效。文件名唯一且采用JPEG扩展名。

分享返回只显示“已交给系统分享，副本仍保留”，不等同系统相册写入成功。取消、系统拒绝、批量数量/容量限制均保留原副本。可分批分享（每批最多5张），或进入一次性的逐张长按导出界面；该界面是兼容/失败兜底，不是常驻照片管理列表。用户明确点击“已确认存入相册，清理对应副本”后，只清理已分享/已导出的对应水印副本，不误删其它照片或失败原始捕获。

页面退出/刷新后，同账号从暂存恢复本次照片；未处理的原始捕获可继续合成。账号按workspaceId及userId隔离。本地写入失败而仅有内存副本时，阻止普通导航并提醒先导出；强制结束浏览器或操作系统清理仍可能丢失仅内存内容，无法承诺PWA消除系统存储回收风险。

系统相机拍摄耗时导致定位过期，或选入不属于当前定位时刻的旧图片时，不把后来GPS冒充原拍摄GPS；保留原始捕获并提示导出/重新定位拍新照片。

## 旧存储与新流程映射

| 范围                             | 原位置/机制                                      | 新流程处理                                                           |
| -------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------- |
| 历史原图、水印、关联及未同步记录 | chunmo-site-photos IndexedDB与服务器私有照片目录 | 不改写、不删除、不迁移；新入口不展示旧管理列表                       |
| 旧后台上传触发                   | MobileAssistant联网/焦点/定时调用syncPhotos      | 从新版入口移除自动触发；旧队列状态原样保留，未标成成功               |
| 新拍摄待保存内容                 | 无                                               | chunmo-photo-batches临时IndexedDB，仅本机待导出/故障恢复，按账号隔离 |
| 新照片网络路径                   | 旧照片POST/分块/完成上传                         | 不调用；仅地点查询/签名及当前账号信息请求                            |
| 确认清理                         | 原照片管理模块                                   | 仅用户明确确认后的当前新批次具体ID，不影响历史库                     |

新临时IndexedDB不是业务数据库，无服务端表或生产数据库迁移，不增加云端照片目录或付费服务。旧PhotoAssistant及照片队列库保留作历史兼容维护，不挂载到新版主流程。历史V1.1/V1.2/V1.3专用相机UI测试保留为旧版本记录；默认手机测试切换为V2.0新流程及现有事项采购/PWA回归，底层旧照片队列单元测试继续运行。

未盘点生产历史照片数量，不以合成测试数量冒充实际数量。不得删除旧PWA或清除Safari网站数据。回滚可切换入口到旧模块，但不能自动恢复旧上传触发或清理新暂存文件；需先核对两套待处理资料并由用户确认处理方式。

## 验证及边界

- 221项单元测试：包含旧队列、三态及其它原业务；新增临时批次保留/精确清理、账号隔离、原像素字节与XMP来源、水印不含“附近”。
- 8项手机浏览器测试：事项采购与多人@、PWA静态缓存/桌面入口、旧Blob照片及待上传记录不变、地址确认后文件相机调用、两张4000×3000原像素水印输出、批量分享不自动删除、10张网页连续拍摄、分享取消后刷新恢复、手动来源、渲染失败留原始捕获、GPS拒绝、本机配额失败阻止普通退出及重试恢复、不支持分享时导出保图。
- 生产构建及部署工具构建、格式/diff检查通过。

浏览器测试为Linux Chromium手机视口、模拟摄像头/GPS/地点响应和系统分享桩。确认了网页File传递与本机保留语义，没有据此声称真实系统相机、iPhone相册、永久授权或系统分享数量上限已经实机通过。尚需iPhone Safari/PWA真机验证自动打开系统相机、相机返回、实际画质及真实“存储图像”批量保存；安卓也需实机核对平台分享目标。

当前开发分支：feat/chunmo-project-manager。未修改main，未强推，未部署阿里云，未操作生产数据库及历史照片。
