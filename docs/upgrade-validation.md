# 性能、多人@、记录交互与旧数据保护验收

2026-11-01；开发基线`e7062e72fe114c9dd70aafb8011c786efe4b6672`。仅开发分支，未部署阿里云，未读取或修改生产数据库。

## 旧数据处理与长期规则

[数据对应与审批规则](upgrade-data-policy.md)及根目录AGENTS.md明确：UI停用默认保留真实数据。材料资产仅移除菜单、独立页面及跳转入口，原组件、API、表、事件、项目关联和历史均保留，不并入采购。旧事项、提醒、备忘及项目说明继续使用现有来源和分类只读预览，不启动自动生产迁移。无删除、清库、重分类、覆盖或清草稿操作。

升级前可先执行`deploy/native/upgrade-inventory.sql`，无需启用新版API或应用012—014；实际SQL在只有010的旧测试库验证过，台账和原始数据均未改变。它使用数据库强制只读的一致性快照，逐工作室/项目输出，缺失新表不会报错，不把不同工地混合。升级后的负责人也可下载同一类只读清单，包含原始数组/表计数、逐项目计数、事项创建/修改/状态/日期元数据、材料项目分布、旧提醒来源及原始历史节点数。API检查使用只读可重复读快照，不阻塞其他员工保存。对旧列表结构异常、缺稳定ID和未知根字段明确列为待核查；无法确认数量返回空值而非伪装为零，不归一化或改写原文。普通员工不可访问。原文在既有原始备份和旧源预览中保留。服务器无法统计每位员工电脑的未上传草稿，不能把测试数量当成生产实际数量。

## 实现

- 采购仍使用workspace_state.data.purchases与采购履历；事项仍使用work_record，时间轴继续映射已有记录，不增加第三套业务数据。
- 新增事项必须选择有效项目和真实日期，前后端均校验；采购继续沿用项目/日期/期限审批保护。从项目和日期入口带入默认值后可编辑。历史空日期事项可读取和恢复，不在升级时擅自补日期。
- 采购新增可选mentionIds，事项新增mention_ids；原负责人文本完整保留，不凭姓名猜测账号。@支持姓名/账号搜索、多人标签、去重、取消及键盘选择。已选停用账号仍可辨认和取消，不能新选；服务端重新验证有效状态与工作室归属。
- 每个接收者独立站内消息、未读计数和服务端阅读时间。源记录/类别/账号唯一约束与原提交回执共同去重；只通知新增账号，不因普通重复保存、重新添加旧接收人、历史导入或恢复重复发送。取消@或移除原记录不删除已有通知历史。
- 消息角标紧邻账号，点击展开轻量面板；点击消息按稳定ID读取当前记录和项目，标记当前账号已读。原记录已移除时明确提示、保留通知。后台SSE同步，重新登录读取持久化未读，支持仅自己全部已读及更早消息分页。
- 通知和业务保存同一事务；失败不产生半条记录或孤立消息。跨工作室、伪造接收者和停用账号请求均拒绝。采购无效@返回具体资源字段路径，不锁住无关项目自动保存；备份中的外工作室账号关联要求人工核对映射，不静默丢弃。
- 空白新增表单和仅系统带入默认值可自由切换类别，不误报。真实业务修改后确认保护，取消保持原值；确认后保留工地、日期、标题、负责人、@与备注，各类别专属字段保留各自草稿。记录提交中禁止切换，失败保留输入并使用原回执重试，保存不跳页面。
- 维持现有CAS、SSE、权限、事务、审计、历史恢复与持久草稿。新增关联审计使用现有脱敏引用机制；未变的数组不会误报为人员调整。

小数据冷启动提升有限，本机样本还有24 ms差异，不能宣称所有场景都更快。受限网络首次仍约2.37秒，尚未达到2秒内目标。没有通过隐藏加载状态制造提升。

大历史测试用两个生产构建读取完全相同的测试工作室、同一账号和版本：20项目、60任务、20采购、401历史节点，解码内容1,926,471字节；150 ms/1.6 Mbps，各3次：

| 大工作空间读取（不是完整冷启动） |    修改前 |  修改后 |
| -------------------------------- | --------: | ------: |
| 中位数（含网络与JSON解码）       |   9876 ms | 1112 ms |
| 实际传输字节                     | 1,926,471 | 188,004 |

逐次核对完整业务内容、历史和签名CAS基线的规范化哈希完全一致。此测试不是删除历史或缩减响应字段。程序为`scripts/large-workspace-benchmark.ts`，记录`large-workspace.json`。

本机PostgreSQL对该行使用Index Scan：计划执行0.078 ms、规划0.084 ms；含2 MB结果传输及pg驱动JSON解析的5次读取中位数28.060 ms。不是生产数据库耗时。`scripts/profile-workspace-query.ts`有本机测试库硬限制。

有效优化：工作空间GET按客户端能力gzip压缩，identity兼容，不压缩会话/CSRF/私密接口或SSE；验证缓存每次仍先读取并核对数据库当前内容哈希，最多保留4工作室/8 MiB序列化快照，返回克隆、保留校验，避免多次重复解析而不缓存权威版本；账号模块异步加载、复用本次已验证身份先展示，后台仍检查当前会话、通用提交等待本次核验，迟到的读取不覆盖用户已经输入的名称；服务端每次操作仍鉴权。账号面板测量以真实内容呈现为准，并不表示跳过后续写入核验。Native配置启用静态JS/CSS压缩，本机Vite预览的冷启动数值未包含这项Nginx收益。

尝试过首屏整体异步拆分，但实测增加等待，已撤回该方案。未确认服务器硬件不足。阿里云CPU/内存/Swap/磁盘IO/Node占用未采集；提供`sudo bash deploy/native/diagnose-performance.sh`只读脚本供现场检查，不将开发机指标冒充生产指标。

## 兼容迁移与部署边界

新增014_mentions.sql为前向兼容结构，不删旧列，不迁移旧业务记录；已有事项默认空关联，原采购新字段可缺省。旧客户端省略关联时保留已存关系，显式空数组才取消。旧版本快照缺字段时保留现有关联。001—013内容未改。

014及最小授权仅在独立localhost测试库执行。已登记精确迁移白名单；部署使用真实应用角色核验关键列、表、序列与read_at列权限，然后才允许切换版本。通知表应用只能读、追加和更新read_at，不能删除或改原文。生产014/授权仍需可恢复备份与创始人确认；按上次现场截图还需重新核对012、013是否已应用。不执行生产历史分类迁移。

涵盖：@一人/多人、搜索/去重、停用与外工作室账号、逐人已读、SSE/离线重登、稳定来源去重、点击当前归属、通知不可改原文/删除、业务与通知原子失败、无关资源继续保存、跨工作室备份映射拒绝、旧源清单只读、所有原项目/工期/采购/人员/历史/草稿回归，含10个独立账号并发和1440/1280/390/320。

修正了实际测试发现的问题：通知逻辑曾提前加载运行配置导致部署引导失败（拆出纯事务函数）；测试库通知序列授权不足（补齐最小授权及启动守卫）；Escape搜索冒泡误关编辑窗；320px胶囊受挤压；手机标题区被操作按钮挤成窄列（调整窄屏布局、保持原断言）。没有通过放宽安全校验解决。

所有受材料菜单停用影响的原导航断言均改为验证入口不存在；材料库存/核销/分析/历史/CSV及跨项目调拨原断言保留，通过DEV测试专用挂载原组件运行，无产品入口、无生产路由，也不会被生产入口打包。原日期可空的创建步骤按新必填规则填写日期，原并发/数据断言保留。不删除或跳过旧测试。没有独立Lint配置，未声称执行不存在的Lint命令。
