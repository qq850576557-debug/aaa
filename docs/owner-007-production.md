## 执行与验收

在已授权的正式服务器 Workbench root 终端执行固定 SHA 的发布命令。入口 `deploy/owner-release/upgrade-018.sh --deploy <完整发布SHA>` 会持有部署锁并检查当前生产版本、数据库及 roles、基础迁移账本、采购索引与工作区数据、各业务记录数量、服务健康和空间。构建通过后，在 `/var/backups/chunmo-staging` 生成本次加密归档，用现有备份密钥验证完整性，并恢复到新建的 `chunmo_restorecheck_*` 隔离库。终端打印归档路径与恢复结果，这两项由现场执行生成。

018 在同一事务中校验账本、应用 SQL、核对权限和原有业务行数。账本与 schema 已通过时直接复验。迁移提交后保留第二份加密备份，再切换网站及 API。正常完成时，终端打印 `核查 018 状态 ready` 和 `PASS 正式网页/API/数据库部署通过 <完整发布SHA>，业主开放保持关闭。`

上线后用原有内部账号查看项目、事项、采购和卫生值日排班，核对历史记录和当前轮次。再用员工小程序核对登录和拍照工作台。自动验收已检查员工服务健康及未授权请求返回码，内部业务画面和手机拍照需要登录实测。

## 失败与回滚

预检、构建、备份或恢复失败时停止切换。018 事务失败时 PostgreSQL 撤回未提交的变更。切换后验收失败时恢复旧网页和 API 并复查健康，终端会给出失败阶段及回退结果。保留归档、隔离恢复库、已提交的 018 与旧版本。归档如需用于灾难恢复，应单独审批并先恢复到隔离库核对。
