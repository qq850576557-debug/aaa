## 账号名称和权限

- 负责人及员工只可改本人登录账号；正式展示名称与个人备注仍独立管理。
- 3–80个 Unicode 字符。支持汉字、英文字母、数字及分隔符 `_ . @ -`；分隔符不得首尾或连续。拒绝空白、控制字符、零宽/双向字符、易混淆异文字母及表情。
- 客户端与服务端共用校验；NFKC规范化、ASCII字母小写，数据库相同规范键全局唯一。旧合法ASCII账号的历史分隔符形式仍允许登录，不强制重命名。
- 账号与安全显示当前、上次修改、下次允许日期与状态。预览二次确认展示旧/新账号及90天警告；最终确认验证当前密码。
- 沿用上轮明确的**90×24小时**规则，不另建「三个月」计时器。数据库时钟、行锁、不可由运行时重写的修改时间、触发器及唯一约束共同执行；服务端再次校验会话，失败事务回滚。
- 成功后撤销该账号所有会话及SSE，预填新账号重新登录。新账号不改内部ID、密码散列、角色、权限、正式展示名、人员/项目关系或私有备注。正式展示名为空的旧账号仍按原规则回退显示当前登录名。
- 服务端记录旧/新账号、时间、稳定操作人ID和设备类型；不记录当前密码。沿用每账号共享的5次/分钟限流和并发密码校验上限。

## 增量迁移与备份

- `004_login_change.sql`：`login_changed_at`、数据库生成的 `login_key`、唯一约束和保护触发器。已有账号规范化后如冲突，整个迁移事务失败，不自动改名/丢数据，须负责人先处理冲突。
- `005_account_avatar.sql`：独立 `account_avatar` 表，仅保存标准小PNG、版本及时间。私密备注和业务快照不混入头像；完整数据库备份包含头像，普通业务JSON仍不包含账号、头像或密码散列。
- 批准迁移清单、测试角色与原生部署运行时最小权限已同步。既有HTTPS15001、localhost8443、CA/私钥、PostgreSQL和Node本机监听、定时备份配置未修改。
- 项目/任务单条跨度仍最多3年；允许项目多个任务合并范围最多10年，兼容五年浏览及远期分段排期。旧数据格式和身份关系不变。PNG超大范围仍使用已有按月/分段导出。
- **回滚限制**：新增结构兼容旧业务数据，但开始使用中文/新规则登录名后，旧版本登录API不认识这些账号。不能声称直接切回任意旧发行版仍能登录；此时应保留004兼容后端，或在受控维护中处理身份后再回退。不能通过重置数据库绕过冷却。

## 仍需人工确认的事项

- 本轮**未部署 ECS**。负责人确认版本后才可按现有原生流程执行 `pre-update.sh`（数据库与当前版本备份）及 `deploy.sh`。不重新初始化PG，不重新生成CA或改变15001配置。
- 上线后由负责人核对原有账号/项目、设备实际字体与触屏效果，并安全保留备份。实体Safari/iPhone、Windows不同缩放需人工验收。
- 没有可信实际完成日期的历史完工项目不能确认最终提前/延期；系统保留排期预测，不编造完工记录。 新项目也不把「标记完工」的点击时间冒充实际完工日；后续交付记录采集完成前，最终提前/延期只依据已有可靠实际日期。旧版已经自动延长的计划日期原样保留，负责人需要在项目设置中核对，系统不反推或覆盖历史。
- 在线状态是实时连接判定，正常网络断开/重连有数秒传播延迟；单进程设计沿用现有2GB ECS部署，不冒充跨多实例在线集群。

## 手动验收入口

1. 登录测试账号 → 账号管理 → 账号与安全：头像预览/保存/恢复默认；展示名与登录名分别编辑。账号改名使用独立测试账号，确认后需新账号重新登录，不能在真实账号上随意消耗90天额度。
2. 桌面从侧栏切换项目；手机展开顶端项目选择器。分别在备忘、采购及时间轴中切换，核对模块、记录隔离和日期位置。手机顶栏时钟图标可打开15天历史。
3. 时间轴选择「定位日期」到跨年或2030年；双击空白格直接生成任务，拖动或拉伸，核对计划日期未被改写、预计延期更新。工种用手柄拖放/触屏拖动；键盘使用Alt+上下。
4. 三个已登录测试浏览器核对在线人数，关闭其中一个核对减少；只建立账号、不登录时不应增加在线人数。
5. 项目设置和人员编辑只修改可见字段后保存，备份核对旧地址、实际日期、旧类别/文字工种及人员关联仍在；长图使用现有完整/按月导出核对离屏施工。

开发运行与数据库准备继续沿用 [阶段B说明](phase-b-cloud.md)。完整云端预览需要独立开发数据库及后端API；纯Vite静态预览不能冒充登录授权/持久化服务。生产数据只能通过现有受控备份/导入流程迁移，不复制生产密钥到测试配置。
