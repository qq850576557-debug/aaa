# 采购日期手动调整与紧凑编辑框

采购截止日期现在允许在编辑框里手动延期或提前。每次实际保存不同日期都追加记录，保存相同日期不重复追加。原始截止日期及已有期限变更记录保留；旧的明确确认期限流程及权限继续保留。正常日期编辑使用原有工作空间编辑权限。

复用 `deadlineHistory`，手动记录额外保留可选的 `actualFrom`（实际修改前的有效采购日期），避免关联工期计算出来的日期与原有期限约束不同时误判延期/提前。原 `from` 链仍遵循既有约束，旧记录无需重写。采购编辑、卡片日期旁的提示支持悬停渐显与键盘聚焦，按北京时间显示“2026.11.04 延期/提前至2026.XX.XX”。离线多次保存后同步允许追加多条记录；已有记录、原始日期不可通过普通保存篡改。

负责人文字与账号 @ 使用现有合并输入组件，原有 owner 与 mentionIds 字段继续分别保存，不把名字当作账号ID。原有通知投递、权限、CAS、事务和历史机制继续保留。

采购专用编辑框桌面宽度收紧为 380px，合并负责人行并缩短备注区，删除按钮增加左右内边距。窄屏采用单列和自适应宽度，保持其他类型编辑框不变。

验证结果：

- 单元测试：31 个文件、166 项通过。
- 隔离真实数据库/API 全量回归：81 项通过；最终兼容分支调整后额外复核采购原始日期保护、采购生命周期、多次日期调整及旧客户端补记录，共 3 项通过。
- 原采购本地浏览器回归：9 项通过，包括工期关联、采购状态、全量JSON备份与恢复。
- 真实云端浏览器：1440px、390px共 2 项通过，检查延期/提前、刷新后留痕、提示显示、负责人合并、宽度和删除按钮留白。
- 前端/API及部署工具构建通过，格式和差异检查通过。

未删除或重分类旧记录，未修改迁移SQL，未部署阿里云、未访问生产数据库。服务器发布后的真实数据与页面效果仍需用户核对。
