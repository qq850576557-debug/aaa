# 部署安全审计阻断修复

截图中的前端、API 和部署工具构建已经通过，但生产依赖安全审计发现 sharp 的高危漏洞，部署因此在 build 阶段停止。这不代表新版本已经发布；脚本报告未执行数据库重置或向下迁移。

将 sharp 从 `^0.34.5` 升级并固定为 `0.35.5`，同时更新锁文件中的原生平台包及其 libvips 依赖。生产依赖审计从 1 项高危变为 0 项漏洞，保留原有审计阻断机制。没有执行 `npm audit fix --force`。

## 验证

验证环境为 Linux x64、Node.js 24.19.0。sharp 声明支持 Node.js >=20.9.0，满足项目 Node.js 22.12+ / 24 的版本要求；本次未在 Node.js 22 或实际阿里云主机执行测试。

- 单元测试：31 个文件、166 项通过。
- API 集成测试：80 项通过，包括头像上传、图片解码与异常图片拒绝。
- 部署回归：26 项通过。
- 前端、API 和部署工具构建通过。
- 原生模块检查通过：argon2、sharp、esbuild、rollup。
- 在独立临时目录执行全新生产依赖安装，argon2 和 sharp 原生检查通过。
- `npm audit --omit=dev`：0 项漏洞。审计结果反映验证时的漏洞数据库，未来新披露漏洞仍会触发部署检查。

本次仅修改依赖与本文档，没有操作生产数据库、账号凭据或业务记录，也没有自动部署阿里云。

## 服务器更新

已安装更新入口的服务器可重新执行：

```bash
sudo /usr/local/sbin/chunmo-update
```

以更新命令最终输出的 `PASS update <完整SHA>` 判断发布成功；仅看到构建完成不代表发布完成。实际服务器发布、服务健康及页面验收需在更新后核对。
