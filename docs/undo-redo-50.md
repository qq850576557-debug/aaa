# 50步撤销与重做

## 使用与会话边界

顶部撤销、重做图标分别支持Ctrl+Z、Ctrl+Y / Ctrl+Shift+Z，悬停显示快捷键与撤销步数。没有可用操作或正在完成逆向请求时置灰。输入框、文本域和可编辑文本保留原生文字撤销；页面导航、悬停、只读查询不记入业务撤销。

每个账号、工作空间、浏览器页面编辑会话最多50步有效操作。第51步淘汰最旧一步；新有效编辑清除重做分支。刷新、重新登录、切换账号/空间或执行专门的历史恢复/导入会结束旧撤销会话；持久待同步请求不会因此清空。不同员工、不同标签页各自记录自己的操作。

## 数据与保存

- 工作空间沿用原本地优先保存和带签名的差量/CAS机制。撤销栈只保留本次变更资源的前后差量，不恢复整个工作空间，不倒退全局历史。逆向前比较目标当前值，目标资料已有后续修改则拒绝；无关资料使用当前值保留。增删关联仍通过原图关系校验。
- 时间条拖动/缩放与排序复用原提交终点，一次拖拽记一步。表单保存记一次；直接高频文字编辑在同资源750ms窗口内合并为一步，使用最早前值和最新后值生成一个逆向差量。
- 事项以服务器确认的有效变化入栈。每一步逆向先进入原账号持久队列、立即更新当前视图，再通过原版本校验和原回执确认。前序保存/冲突尚未完成时等待或阻止同记录的乱序逆向提交。逆向请求完成前不重复执行快捷键，其他正常编辑仍可保留。
- 删除事项采用软删除；撤销删除、重做新增均恢复原ID，保留创建人员/时间，并追加新的实际操作人员、服务器时间和审计。恢复接口同时校验当前版本及最后删除操作账号，不能恢复其他账号的删除。
- 已确认事项的连续逆向会使用自己的逆向结果更新版本链；不会把自己的版本推进误当成其他人的修改，也不会用这种更新覆盖外部版本。旧GET/重试响应不倒退最新缓存。
- 考核沿用原行级持久意图队列与版本校验，三态逆向只更改对应项目/日期/人员的字段。旧多工种来源存在不同原状态时，逐来源按原ID和版本恢复，不把旧记录物理合并，也不把所有来源改成同一个原状态。
- 断网保留已持久入队的逆向请求，重连使用同一回执重试。刷新后仍续传同一请求；视图从队列恢复待同步预览，冲突后显示服务器有效记录。没有云端确认时，保存状态不能显示新的云端成功时间。

## 冲突及专门流程

多人冲突不自动选择本地覆盖。事项逆向被拒绝后，可在看见当前有效资料的前提下明确选择“保留当前并放弃此步”；重新读取服务器记录确认后，只移除该次被拒绝的逆向回执和会话步骤，不删除业务记录、原始提交回执或审计。其他未同步草稿继续保留。

账号权限、密码、私密资料、历史版本恢复、导入/迁移不进入普通撤销。原有需要负责人确认并追加不可变记录的采购期限审批，以及考核移除/换人的专门更正流程，继续使用其原确认与恢复入口；普通撤销不绕过权限或截断这些记录。采购新增、普通编辑、状态修改和时间轴联动继续通过普通资源差量撤销。

本轮没有SQL迁移，没有连接或修改生产数据，没有部署阿里云，也没有删除真实历史。普通撤销完成仍会成为新的正常业务保存与审计记录，原15天版本历史保持独立。

## 实际验证

- 182项单元测试：50步与第51步、连续重做、文字合并单次写入、新分支、冲突不推进栈、异步保存期间的新编辑、账号/历史恢复会话隔离、旧考核差异及明确放弃失败步骤。
- 83项隔离真实API回归：原权限、并发、审计、历史和数据保存。
- 18个不同浏览器场景分别通过：最终资源差量版本的51次编辑、连续50次撤销/重做、原生文字撤销、快捷键和滚动保持；7项原工期/拖拽/排序/人员/历史回归；6项原自动保存/断网/恢复回归；4项新增云端业务逆向场景。
- 新云端场景包括事项新增/编辑/软删除同ID恢复、两个账号冲突、拒绝恢复他人删除、离线逆向续传、考核三态、采购状态、项目资料与他人后续编辑，以及旧多工种原状态逐来源恢复。关键场景修正后复测，不重复计入数量。
- 前端、API及部署工具构建通过；14个已审阅SQL迁移库存不变。

真实生产人员数据未读取，发布后仍需工作室在实际账号与网络环境验收。以上测试数据均为隔离环境样例，不冒充生产数量。
