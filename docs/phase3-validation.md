## 本次测试中发现并修复的缺陷

1. 备注 textarea 采用嵌套 label，已有内容时精确标签无法可靠定位。改为明确 `id` / `htmlFor`，实际编辑已有项目备注测试通过。
2. 拖放释放依赖之前的悬停状态。改为释放时基于目标行/卡片及鼠标位置重新计算插入位置，校验本次拖动来源；测试等待真正的最终 `dragover`，明确断言插入线对应目标项目。项目拖放专项连续 4 次通过，最终全量再次通过。
3. 首版姓名保存可能把已删除且未改动的既有姓名重新加入。现在只记入本次新登记或改变的角色姓名，保留显式空库，删除不改任何既有记录；旧长姓名保持原值，不截断旧项目数据。
4. 新增任务此前无法建议被其覆盖的后续工种顺延。补上保守建议，同时保留三项明确决策及取消前无写入的约束。浮动预览增加过期快照检查，避免覆盖期间的其他修改。
5. 错误通知由定时消失改为手动关闭，并避免被后续普通提示挤出。

## 数据兼容方案

不升级或替换数据库：仍为 `chunmo-workspace` v1、`workspace/data`。数据格式仍为版本 1。

新增 `Project/Trade/Task.personnel?`（worker/manager/designer）和 `Data.nameHistory?`。旧对象不需要这些字段，读取时不重写；旧姓名作为候选回退显示，第一次登记人员或删除历史候选时才保存姓名库。删除候选不会清空或修改项目/工种/任务中的登记。项目排序使用已有 projects 数组顺序，无须独立 order 字段或迁移。旧版应用的严格校验器可能拒绝新版备份，应使用当前或更新版本恢复。

所有浏览器验收使用 Playwright 独立新上下文和测试项目，未连接用户浏览器配置目录，没有执行 deleteDatabase、clear 存储或覆盖用户业务数据。JSON 恢复仅在这些隔离测试上下文明确确认后操作。

```sh
cd /workspace/aaa

npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

云端内部开发地址 `http://127.0.0.1:5173/`。已核对现有 Vite 进程来自 `/workspace/aaa`，本次浏览器测试访问该服务，实际加载了新人员字段、直接创建与新字体，生产构建也基于当前源代码。当前环境引导界面没有可用的公网端口预览，云端 localhost 不能直接当作用户电脑网址；在本机检出同一功能分支并运行上述命令后，可打开本机 `http://localhost:5173/`。使用相同协议、域名和端口才能读取同一份浏览器 IndexedDB。

## 建议人工复验顺序

1. 先下载自己的完整 JSON 备份，保留当前源，不清理网站数据。
2. 在项目卡片切换自己的项目，核对今日事项、采购和时间轴；拖动卡片排序后刷新确认。
3. 时间轴空白日双击，确认立即出现一天条；拖动条和两端，再用撤销复原。
4. 已有任务新增时间段，移动到相邻日，核对合并后的关联事项和采购；撤销核对恢复。
5. 延长或新增前序任务，分别检查取消、仅当前及顺延的预览与结果。
6. 从项目、工种、任务登记人员；跨项目复用姓名，删除一个正在使用的候选，核对原记录仍在。
7. 打开色环，调整 HEX/色板和恢复默认；确认无整页遮罩、其他工种不受影响。
8. 导出完整长图，在图片查看器按原始比例核对首尾日期、跨月任务、字体和明细；原图 Logo 仍显示未接入说明。
