## 增量设计

沿用同一小程序及 PostgreSQL。原生业主页面和资源放在独立分包，保留员工页面、路由及存储键。业主 API 使用独立的 `/api/mini-owner/v1` 入口、会话和中间件。同一服务可承载此入口，两类请求使用各自的身份校验和数据访问范围。原有员工后台继续用员工 Cookie、CSRF 和内部路由。

| 新增数据                       | 约束与用途                                                                                                                                                                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 业主身份、微信绑定、邀请及会话 | 独立于员工账号和会话表。手机号加密保存，单独使用带密钥的摘要匹配。邀请绑定预授权对象、有效期和一次性凭据。保存微信 AppID 与已验证身份的唯一绑定。会话凭据只存摘要，支持过期及撤销。                                                                                            |
| 项目服务开关、业主多对多授权   | 项目默认关闭，授权为同一工作空间内的明确项目关联。最高负责人管理，有状态和审计。多个家庭成员分别授权，一个业主可关联多个项目。撤销一人或一个项目范围时，保留其他有效关系。                                                                                                     |
| 项目级员工采购协同权限         | 最高负责人默认可管理；普通员工须有该项目的明确采购协同权限。若生产核查同样缺少有效粒度，新增作用域明确的授权关联，默认无授予。权限接入覆盖专用接口和采购旧写入入口，未接入业主协同的采购继续沿用既有规则。                                                                     |
| 采购发布、购买反馈及变更流水   | 以工作空间、项目、现有采购 ID 关联，保存采购责任方、发布状态、对外名称及说明、必要规格和参考资料。反馈单独保存品牌、型号、备注、确认人和时间。版本、幂等回执及追加式事件记录分别标记业主或员工的真实身份。既有 `purchase_action.actor_id` 引用员工账号，业主事件使用独立流水。 |

全量历史保持原状。项目、历史采购及新购默认不可见，明确发布且责任方为业主才进入业主端。撤回、重新发布或修改日期保留购买反馈。撤销项目授权、关闭服务、删除采购或变更所属项目后即时阻止原访问，历史导入／恢复后也须重新明确发布才可重新显示。异常及回滚都从已存流水核对。

采购和项目的关系投影可能被原保存流程物理删除。协同数据以稳定 ID 关联当前投影，在事务内撤回失去主体的发布并保留历史。持久反馈和审计避免依赖会级联清理或阻挡原删除流程的投影外键。

### 接口与校验

| 入口                                                                                      | 权限与数据                                                                                                                                                                                                                |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/mini-owner/v1/auth/login`、`GET /session`、`POST /auth/logout`                 | 首绑需同时核对公司预授权、未消费邀请、`wx.login` 和经微信服务端验证的手机号授权码。同一事务核对身份冲突、消费邀请并签发会话。已绑定时恢复有效会话，必要时用同一微信身份重新验证。敏感日志脱敏，限流覆盖邀请、交换及反馈。 |
| `GET /projects`、`GET /projects/:id/purchases`、`GET /projects/:id/purchases/:purchaseId` | 前缀均为 `/api/mini-owner/v1`。逐次校验会话、授权、项目开关、记录归属和发布状态。响应按字段白名单组装。只提供必要项目资料、对外采购信息及可见状态。                                                                       |
| `POST /projects/:id/purchases/:purchaseId/feedback`                                       | 提交允许的动作、预期版本、请求编号和品牌／型号／备注。后端固定字段，负责身份、状态判断和事务写入。购买者无权变更项目、截止日期、发布及内部采购状态。                                                                      |
| 员工项目设置、采购、提醒中心                                                              | 现有员工 API 内增加授权、预览、发布／撤回、代确认、退回及完成／重开动作，逐项校验。业主摘要和提醒读取使用员工项目权限。链接作为文本保存和复制，服务端不自动打开。参考附件如提供，使用每次访问均重新鉴权的入口。           |

公共业主数据库角色只访问必要的新表和限定查询／受控函数。采购及工序联动日期所需字段来自现有同库事务投影，避免向业主角色授予快照、事项、人员、成本、内部备注的表权限。涉及受控数据库函数时限定调用者、输入与搜索路径。对外接口不返回原始行对象，响应、错误及缓存统一保护。退出或切换身份清理业主缓存及未提交资料，员工照片和草稿保持原命名空间。

微信编码由服务端分别兑换，登录码和手机号授权码各自限期和去重。手机号变化、号码转让或绑定冲突时，由负责人核验并签发新邀请，撤销受影响的旧绑定及会话，保留旧身份的历史。前端提交的手机号不能代替微信验证。

### 状态与一致性

- 对外状态为待采购 → 业主已购买 → 公司确认完成。业主购买只写反馈并停止该项业主待购买提醒，公司的 `待采购 / 已下单 / 已到货 / 已完成` 字段及现有统计定义继续沿用。既有已到货、已完成记录维持内部结束语义，只有明确重开并发布才重新进入业主流程。
- 公司最终确认复用现有采购完成事务。最终确认前，允许修改、撤销、代办或退回。重开需授权及原因。最终确认后反馈只读，任何路径均须检查当前状态。新的日期只改变有效期限及排序。
- 同一事务校验授权、发布状态和版本。协同写入及撤销使用同一项目锁。内部保存先锁工作空间再按顺序锁相关协同项目，业主接口只走受限的项目锁和当前投影查询。所有可能改变公开资格、完成状态或联动日期的内部编辑、删除、恢复和移动路径都进入校验。隔离环境验证锁序和实际运行账号权限。
- 同一账号、采购及请求编号的同内容重试返回已确认回执，变更内容复用编号拒绝。先校验当前权限，再返回回执。家人同改或员工并发确认发生版本冲突时，读取新版本并保留尚未提交的输入，服务端确认前界面保持待提交。
- 复用电脑端 `/api/events` 连接及提醒中心，加入按员工项目权限过滤的协同更新信号。反馈更新不伪造工作空间版本，也不借用员工 @ 提及冒充业主。业主端在打开页面、返回前台和提交后重读白名单内容。

## 微信、上线与验收边界

- 源码及既有交付记录指向现有 AppID 和 `https://chmsj.cn`。已识别的品牌源件包括原始 Logo、品牌字体、正式名称「春茉空间设计」及源码标语「功能与美×共生」。本次附件和仓库中未找到《春茉业主小程序UI原型-V1.3.html》、最终纯白短绒登录参考图。
- Cloud 网络规则未放行微信官网及春茉站点，只读请求返回 403。当前认证、手机号能力／额度／单价、类目、隐私指引、合法域名、微信发布及阿里云运行状态尚待后台核对。阶段三真微信联调前，核对微信公众平台中的上述条目和正式法律文案，确认可用额度或另外审批费用。业主页面不申请拍照、相册或定位权限，员工继续按现有用途申请。官方入口包括 [手机号验证组件](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getPhoneNumber.html)、[手机号服务端接口](https://developers.weixin.qq.com/miniprogram/dev/OpenApiDoc/user-info/phone-number/getPhoneNumber.html) 和 [微信小程序后台](https://mp.weixin.qq.com/)。
- 预计使用核心库的兼容增量迁移。新增表、约束、索引和独立角色权限，保留已有迁移校验值。阶段三、四交付具体 SQL 与表／权限影响清单。阶段五在独立 PostgreSQL 使用生产等价运行角色验证迁移重跑、备份可恢复、旧 API、最小权限、并发及回滚。
- 生产阶段先确认运行 SHA、数据映射、迁移状态、实际运行账号、数据范围及可恢复备份。启用前须审核兼容迁移和固定 SHA。全局／项目开关从关闭开始，先试一个经批准的项目。回退时先关闭入口及写入、保留新增业务记录，检查原有服务后再切旧版代码。已产生的购买反馈和审计流水仍保留在库，恢复备份只按核准方案处理，避免覆盖上线后的写入。
