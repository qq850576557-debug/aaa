# 春茉 V2.1 隔离验收

## 源码与数据

网站以发布候选 `6aef816bd4a4e541dcf6425843050080d288aac4` 的延续分支为基础，小程序合入 `01797e7a1b3467035b6a5d404fef9a526a9f3a5e` 的员工工作台、事项保存及照片目录修复。已部署版本以正式站健康接口的实测 SHA 为准。

019 新增员工手机号指纹、手机号尾号和微信身份指纹，复用现有员工账号、项目权限及员工会话。原有手机号资料无须导入。业主继续使用现有成员、住宅授权、邀请和独立会话。019 无历史回填，保留 016–018 和原业务记录。停用员工、登记离职、更换手机号或解除绑定后，现有员工会话立即失效。离职由最高负责人从员工列表登记。员工首次绑定使用原密码和微信验证的手机号。业主头像在管理列表无服务端图片时显示姓名首字。

## 真机验收

1. 仅升级 `owner-test.chmsj.cn`。使用已安装测试站的 Workbench 流程并指定 `upgrade-purchases.sh --v21 <完整SHA>`。测试站检查版本传承、备份测试库、验证迁移账本和权限，再切换隔离服务。发现版本或配置快照分叉时会停止。故障回退保留 019 和测试数据。手工回退使用同一个脚本的 `--rollback`。
2. 从测试站下载 `/chunmo-owner-test.zip`，或者打开交付的同 SHA 测试包。用开发或体验微信成员在 Android 和 iOS 预览。包固定使用隔离站地址，微信 request 合法域名需含测试站。
3. 用测试员工完成第一次绑定。彻底关闭重开后应直接进入。验证新增及编辑事项并在测试网页核对，另外检查定位、拍照、水印及相册保存。
4. 用测试业主手机号绑定两套已授权住宅。重开无需再授权手机号，验证公开采购、购买反馈和住宅切换。撤掉一个住宅授权时，另一套仍可用。全部撤销后退出该身份。
5. 用同时具备两类授权的测试微信验证身份选择。用普通员工访问管理接口应被拒绝。检查重复手机号、密码错误、会话过期和解除绑定后三类旧访问失败。

## V2.1 补充验收

电脑端账号管理弹窗在 1440×920 视口使用 1120×760 外框，并在窄桌面受 94vw / 90dvh 约束。一级菜单、列表表头与底部操作区保持可见。员工、业主列表各自按搜索和筛选结果每页显示最多 10 条。个人中心仅能读取本人手机号尾号和绑定状态。

设计成果使用候选迁移 `020_owner_design.sql` 和对应角色授权，保留原有数据和授权关系。现有项目首次读取时返回空链接。项目设置保存使用版本校验，每次变更写入审核记录，审核日志记录变更项和发布状态。业主运行角色只能通过检查有效会话和住宅授权的数据库函数读取合规链接。

- 隔离站的 `upgrade-purchases.sh --v21 <完整SHA>` 会在备份后应用测试库的 019 和 020，通过账本校验和角色检查后启用测试 API，并更新网页下载包。实际媒体地址仍须通过 `CHUNMO_OWNER_DESIGN_ORIGINS` 列出已完成微信业务域名校验的 HTTPS 源站。未配置时可以查看「业主设计成果」入口，页面会提示配置业务域名。
- 微信公众平台「开发管理 → 开发设置 → 业务域名」需要登记实际承载效果图或全景图的域名并完成校验。也需让服务端允许列表匹配实际打开的源站。联调实际链接时保留微信域名校验，检查是否有跳转到其他未登记域名。小程序使用原生 web-view。当前环境无法核对具体 AppID 的微信后台域名登记，也没有可用的 iOS 和 Android 真机。
- 真机用员工登录验证头像、部门、职务、事项表单和软键盘。再用业主登录检查两类成果、网址加载失败、前后台同步、切换住宅、撤销住宅授权和没有链接时的状态。示例域名只用作隔离测试夹具。
- 春茉系统按授权发放链接。若设计平台的链接本身允许公开访问，已获得链接的人仍可在系统外分享或访问。私密项目应使用设计平台自己提供的访问限制。
