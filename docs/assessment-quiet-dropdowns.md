# 师傅打卡：静默保存与统一下拉框

本轮仅修改电脑网页交互及测试，沿用原考核记录、队列、权限、CAS、审计、SSE 和撤销机制。未连接生产数据库，未部署阿里云，未新增或执行数据库迁移。

## 交互

- 姓名保持单一可搜索下拉框，去掉姓名旁的叉号、历史按钮和逐行同步提示。选择“暂时不选”恢复灰色“选择师傅”；保留默认三行、添加人员及原工地卡片宽度。
- 首次误选且没有打卡内容时直接换人。已保存内容或历史中曾有打卡内容，即使后来全部改回横杠，换人前仍提示“已有打卡记录，是否确认更换打卡人员？”，提供确认/取消。
- 换人沿用原批量接口，原人员的当天来源软撤回，与新人员记录在同一事务提交；原始状态、人员ID、其他日期、其他工地及操作历史继续保留。选回原人员时恢复其自己的记录，不把其他人的成绩转记给他。并发冲突不强制覆盖；先前尚未同步的打卡需完成同步或处理冲突后换人。
- 签到、拍照、卫生均改成紧凑下拉框，选项为 ✓、×、—。未选师傅时禁用并弱化；横杠仍表示未记录。
- 历史统一移至数据小结中的“历史”按钮，包含原始来源及撤回/恢复审计；仅有撤回历史的人员也可查询，但不计入完成天数。

## 消除保存时的闪动

原界面在每次打卡时切换统计说明，并临时插入“导出待同步副本”按钮；侧栏保存文字高度变化也会挤动上方项目区域。

现在统计说明固定，考核工具栏不随队列变化插入按钮，恢复副本下载放入侧栏保存详情。考核区取消动画及按钮位移效果。侧栏保存区域预留固定高度，“最新保存：”独占一行，完整北京时间放在下一行；上传中保留上一次真实云端确认时间，状态在固定第三行显示。成功后状态行隐藏但保留空间。错误、冲突、重试及待同步恢复信息继续可用。

选人按当前可见人员ID执行，并串行处理本地连续选择；已被服务器确认的预留占位不重复显示，避免另一标签页换人后旧姓名重新出现。普通打卡继续使用原可靠本地队列即时更新，不重新挂载工地卡片、侧栏项目或整个工作空间。

## 后续调整：页面进入与侧栏空间

人员模块改为直接加载，考核权限及记录加载期间使用不可操作、不可见的完整布局占位（无闪烁动画），避免先出现单行加载提示再将人员档案顶下去。权限依旧由原API检查，确认前无法操作打卡。三态下拉增加绿/红/灰渐变底色、描边和静态阴影；不增加位移动画。侧栏版本历史、备份、保存和云端工作空间的上下间距及高度统一压缩，正常保存与同步期间占用高度一致。

新增浏览器验证会延迟权限响应，对比加载前后人员档案纵坐标，检查等待期间禁止操作、侧栏固定区高度小于170px，并验证三态下拉底色及阴影。

本次验证：前端/API构建通过，182项单元测试通过，6项考核及5项静默交互浏览器场景通过（新增加载布局专项修正工具栏不足1像素高度差后复测通过）。未执行生产部署或生产数据操作。
