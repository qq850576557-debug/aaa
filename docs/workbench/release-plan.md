本轮仅交付独立分支候选，不执行阿里云更新或上传微信审核。1.2.2继续走原审核，原下载地址与生产runtime保持固定。不能从此分支直接运行chunmo-update或旧sidecar首装脚本。

## 审批前完成的成果

工作台原生页面、单一共享业务源、受限传输适配、实际电脑浏览器/小程序客户端采购闭环、现有2756068后端兼容、旧PWA专项回归、审计及退役记录。没有新增业务表、迁移SQL、付费服务。旧PWA入口与未保存照片保持可访问。

## 仍阻止生产切换的事项

1. validation.md中全量浏览器失败需要逐项评审处理；当前不能宣布完整回归通过。
2. 需要创始人批准“隔离候选HTTPS路由+独立候选sidecar服务”的具体方案，复核服务器实际端口、Node、Nginx、原API SHA及空间；没有SSH权限，未假称核对现场。
3. 真实微信开发工具及三类手机验收；尤其账号键盘和拍照像素/相册保存不能只看模板截图。

## 推荐的候选接入（待审批，不是已执行命令）

- 优先沿用现有HTTPS域名，但新建精确前缀/api/mini-photo-candidate/，代理到新回环端口，并重写上游为/api/mini-photo/。新端口须现场探测，不能假定4012空闲。
- 独立chunmo-mini-workbench-candidate用户/服务、root私有候选env及持久运行目录；复用同一个AppID/AppSecret及原员工API，密钥只在服务器隐藏输入，不复制到代码/聊天。新sidecar不持有数据库凭据。
- 开关CHUNMO_MINI_WORKBENCH_ENABLED=1只用于候选服务；原服务、原/api/mini-photo/路由及原网站API保持不动，不开放公网端口，不放宽CSRF/Origin/微信proof。
- 开发工具候选工程config.js设相同HTTPS origin与apiPrefix:'/api/mini-photo-candidate/'，不改变AppID，不创建第二个小程序。没有候选路由时不要拿生产1.2.2接口报错误认为工作台已接入。
- 候选sidecar构建命令npm run build:workbench-sidecar，输出dist-workbench/sidecar.cjs及manifest。旧首装脚本固定旧SHA，不能用于替换此运行包。实际安装事务/备份脚本须在审批现场范围后另行制作并隔离演练。
- 生效前备份候选单元/私有env及Nginx现有文件（root私有权限），nginx -t后HUP；失败只撤销本次候选路由/服务，验证原API、网站和1.2.2相机路径仍正常，保留审计及照片，不强制覆盖其他管理员改动。

## 验收顺序

1. 先在隔离_test业务库上用真实微信候选验证登录、今日/明日/逾期及项目/日期筛选。
2. 再在批准的环境按“电脑新增采购→小程序同ID显示→小程序改状态→电脑同步变化”录像/截图留证；不要用构造示例写进生产。
3. 验证另一账号并发、重试回执、断网/重开、会话过期、401/403/409、事项历史与旧备注保留。草稿拒绝覆盖时需要明确核对，不自动套新基线。
4. 验证旧PWA草稿/照片可恢复，候选入口不会清任何本地数据。
5. iPhone、Android、HarmonyOS微信各测拍照/相册/20张连续拍摄及实际尺寸，确认恢复入口可用。
6. 创始人认可代码审查、完整回归及真机结果后，才决定是否上传下一版微信审核；不能撤回正在审核的1.2.2来替换。
7. 新版审核通过并获发布批准后再发布及调整公众号入口；旧网页入口先保留/隐藏，不自动删除存储或未同步文件。

## 回退

候选未上线时不合并/不部署即可。候选路由和服务如后续安装，回退仅移除该候选入口、恢复备份并核验原服务，不回滚共享业务数据库里的真实采购/事项修改。真实业务修订继续通过原权限/历史/CAS安全机制处理。Git按阶段revert，不force push、不重置原开发分支。
