# 小程序 30 天登录与上线核对

员工首次用现有账号密码登录，服务端签发绑定当前微信身份的独立 30 天恢复凭证。小程序重新打开时通过微信身份与恢复凭证获取新的短期 Cookie，沿用现有工作台和拍照接口。员工退出会移除本机凭证并尝试撤销服务端凭证。修改密码、停用账号及超过 30 天后需要重新登录。网站的登录期限为 8 小时。

业主首次通过住宅邀请和微信手机号登录，服务端签发最长 30 天的业主会话。小程序重新打开后验证会话和最新住宅授权，再进入业主端。撤销授权、注销会话或重新绑定后继续执行现有访问限制。首次切入新版时，员工需要登录一次才能取得恢复凭证。

## 发布范围

- 从正式版本 `4a6ff34497c67bed7bd71e2e89f4ac6339be1cff` 构建。应用代码复用既有 `auth_session` 和 `owner_portal.session`，无新增迁移。018 和旧数据保留。
- 登记正式 AppID 的微信身份服务凭据。员工接口使用正式 API 的 `CHUNMO_MINI_APP_ID` 与 `CHUNMO_MINI_APP_SECRET`，也可读取同一 AppID 的成对 `CHUNMO_OWNER_WECHAT_APP_ID` 与 `CHUNMO_OWNER_WECHAT_APP_SECRET`。凭据存于服务器受限配置。
- 正式小程序继续用既有员工工作台版本为基底。正式协议请确认服务主体、联系渠道、生效日期和留存口径，并在微信后台核对员工拍照和业主手机号、相册及采购图片所对应的隐私用途。
- 正式业主 API 需要独立数据库登录账号、业主专用加密密钥和成对微信配置。上线前复验该账号仅可使用已审阅的业主权限。确认试点正式住宅与成员，由负责人逐项发布获准公开的采购。

固定发布 SHA 确认后，沿用 Workbench 构建、校验和回滚流程。纯代码阶段的入口为 `deploy/owner-release/deploy.sh --deploy-mini-monthly <完整SHA>`，回退为 `--rollback-mini-monthly <完整SHA>`。这一阶段要求 018 已就绪且业主入口保持关闭。更新正式小程序前，用正式域名的体验版核对两类身份冷启动恢复、变更密码、退出及撤销权限。正式微信发布以平台审核结果为准。
