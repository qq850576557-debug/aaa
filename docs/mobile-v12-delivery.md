# 手机版 V1.2 验证与更新说明

本轮仅修改手机体验、静态图标及保存时间显示的格式兼容，不更改电脑端业务、权限、云端记录结构或生产数据。没有连接阿里云部署，没有新增费用、服务器照片目录或数据库迁移。

## 已完成

- iOS 180、PWA 192/512、Android maskable 512 均为完整不透明绿色画布。直接使用用户原始绿色底图导出，避免旧圆形透明图标产生的白角及抠图轮廓；未重绘品牌图案、未修改正式源文件。透明原版单独保留，网站圆形 favicon 仍使用该原版。生成脚本和源文件 SHA256 见 `scripts/build-pwa-icons.mjs`、`public/brand/pwa-icons-v12.json`。
- 所有新图标使用 `-v12` 文件名；HTML apple-touch-icon、manifest 路径已更新。Manifest 引用附加 `20261110-v12`，Service Worker 的静态缓存按每次构建 HTML 哈希更新。缓存更新只清理旧静态 shell CacheStorage，不清除 IndexedDB、照片、登录资料或待同步草稿。
- 事项/采购各有 54px 右下角悬浮加号，位于导航栏及安全区上方。直接带入各自类别，继续使用原有表单、权限、日期/工地必填及保存机制。弹窗打开时隐藏 FAB。
- 最新保存显示单行 `最新保存：YYYY-MM-DD HH:mm`，按北京时间格式化真实服务器确认时间。同步中、本地待同步、失败及点击重试独立显示。修复服务器 Date 字符串与 ISO 字符串直接比较可能令保存时间停留在旧值的问题。
- 相机与定位并行初始化；首帧可先显示，但有效 GPS 和高德地点签名未确认时快门不可用。连续会话保留同一后置摄像头。有效地点仅在同一次会话短暂复用，30秒后重新定位/识别，仍受原有90秒位置与服务器签名有效期限制；未增加后台持续定位。
- 原图先写入 IndexedDB，成功后恢复快门。水印通过串行 Worker/OffscreenCanvas 队列处理；兼容性不足时走原有主线程安全降级。原图不覆盖、不放大、不强制降到1080P，保留原有大图安全上限与明确降级尺寸提示。
- 复用原始Logo、生成小缩略图、只更新发生变化的照片，减少重复解码、读取整库与改写原图。Worker仅2649字节，不重复加载校验库。上传继续使用原请求ID、分片回执及服务器真实身份校验；新照片在正在上传时加入，完成后会继续处理，不必等60秒定时器。
- 拍照页重新打开时检查已持久化但未完成水印的任务；上传失败保留原图/水印，联网或下次打开时检查待上传队列。不承诺PWA退出后持续运行，不宣称自动写入iPhone系统相册。

## 前后实测

环境为Linux Chromium模拟摄像头，摄像头/定位预先授权；GPS回调人为增加250ms、模拟高德签名接口增加250ms。不是物理iPhone、真实GPS、高德公网或阿里云网络数据。每项使用同条件10连拍；启动耗时为该次会话单次观测，照片阶段取中位数。原始测量摘要见 `mobile-v12-performance.json`。

| 阶段                  |  优化前 |  优化后 |
| --------------------- | ------: | ------: |
| 点击拍照→预览就绪     | 622.2ms | 171.8ms |
| 点击拍照→快门可用     | 622.3ms | 513.1ms |
| 快门→原图本地事务提交 | 353.1ms | 116.5ms |
| 快门→可继续拍摄       | 485.8ms | 116.4ms |
| 水印合成              | 126.1ms |  83.0ms |
| 原图本地写入阶段      |   2.6ms |   3.6ms |
| GPS回调阶段           | 251.3ms | 251.9ms |
| 模拟高德识别接口      | 258.6ms | 259.4ms |
| 摄像头初始化          |  42.7ms |  50.0ms |

主要收益来自移除快门中的重复GPS等待、把相机与定位并行准备，并将水印移出快门等待链；没有把GPS或摄像头设备本身变快。授权弹窗预先完成，没有测量真实系统授权耗时。优化后的相机权限查询约11.1ms；浏览器不支持查询时不增加串行阻塞。

前后均10/10成功，同一会话均只初始化摄像头1次；GPS回调从11次降至1次，高德接口均1次。采样期间前后均未观测到超过50ms的UI长任务，最大动画帧间隔均约16.8ms；不能据此承诺真实iPhone无卡顿。

模拟相机原图、水印图均3840×2160。另使用4000×3000、EXIF方向6的合成JPEG验证：原图字节完全相同，水印3000×4000（方向纠正），保留1200万像素。不是手机硬件照片分辨率证明。

本地隔离API另验证3张上传确认（非真实云端网络）：约1581ms、861ms、2212ms，包括分片传输、服务端水印重生成及确认。上传不阻塞下一张拍摄。见 `mobile-v12-upload-performance.json`。

## 验证范围与未验证项

- 211项单元测试、12项手机浏览器回归、11项电脑端布局/保存/并发回归、照片API的3项权限/原图/12MP/EXIF/分片重试/关联CAS测试均通过；生产构建和部署工具构建通过。最后轻量化Worker后再次验证了12MP、十连拍、断网续传和照片API。
- 覆盖320/390宽度FAB固定、对应类别、保存失败/重试与服务器时间一致、定位失败禁拍、定位识别未完成时只预览、10连拍、Worker与禁用Worker的降级、水印失败留原图、本地空间失败阻止继续拍摄、断网续传及避免重复照片。
- PWA Manifest、Service Worker注册/更新及静态缓存已在Chromium验证；更新前写入的待上传照片字节在更新后仍然存在，API响应不进入CacheStorage。
- 未连接真实iPhone，未安装真实iOS/Android桌面应用；Safari/WebKit实机相机、内存压力、Home指示条/键盘、系统相册分享、真实定位/高德公网、阿里云移动网络和已安装图标自动刷新均未验证。不能保证已安装iOS图标打开一次网页就刷新。

## iPhone安全更新图标

先保留旧PWA和Safari网站数据，联网核对本机照片已上传、云端原图和水印可打开，同时保留原图及未同步内容的独立备份。只看“最新保存”不能证明照片队列已全部上传。

若旧图标没有刷新，从Safari打开HTTPS网站，分享→添加到主屏幕；系统允许时可另加新图标，并先保留旧图标。尚未核对同步和备份完成前，不删除旧PWA、不清除Safari网站数据、不重置本地存储。实际图标缓存刷新由iOS管理。

## 手动服务器更新

本轮没有部署。确认准备更新时，在现有服务器执行：

```bash
sudo /usr/local/sbin/chunmo-update
```

这不是跳过现有审计、备份与迁移批准检查的命令；本轮没有新增生产数据库迁移。
