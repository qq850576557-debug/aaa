# 新增记录界面与历史记录兼容验收

日期：2026-10-31。开发基线：`bb899d729789ecd27a5368542b522047a61f5889`，分支 `feat/chunmo-project-manager`。

## 实际问题与修改边界

旧版今日事项、明日提醒、备忘和施工跟进共用 `Data.notes`，通过 `kind/date/reminder/done` 区分；项目长期说明位于 `projects[].notes`。采购清单已经保存在 `Data.purchases`，由现有采购页面直接读取。新版事项管理单独读取 PostgreSQL `work_record`，此前没有从旧 Note 到该表的映射，因而一部分旧内容在新版看板中不可见。这是代码中可证实的遗漏原因，不是对生产数据的推测。

本次没有访问生产数据库，因此无法报告真实工作室可迁移和待确认的数量。页面会按当前登录工作室、逐工地提供只读预览和现有目标数量。历史快照只作为历史保留，不把已删除、仅存在于旧快照的事项自动复活。

“新增记录”的采购与事项分类、保存 API 和权限保持原样。只把两种表单嵌入同一个弹窗，类别选择器一直在上方，表单在其下展开；采购为琥珀色、事项为青绿色，使用紧凑尺寸、键盘焦点和减少动态效果支持。详情/历史页签统一为绿色圆角分段控件。其他编辑窗口默认行为不变。

## 分类与去重规则

- 优先采用原结构化类别，再判断购买、订货、到货和检查、协调、质量等动作。材料名称本身不足以分类；“检查灯具安装位置”归事项。
- 原类型与文字矛盾、购买与检查混合、内容不足、采购没有计划日期等均进入待确认，不猜日期或负责人。参考资料保留为资料，不产生待办。
- 稳定来源键由来源类型、工地 ID、原记录 ID 组成；目标 ID 可重复计算。来源哈希、不可修改的映射和请求回执共同保证重复调用、并发重复请求不再建记录。
- 同工地同标题的多个旧来源需要人工确认。与现有目标完全相同且唯一的记录可以沿用；其他可能重复项需要明确选择沿用或确认不同事项。界面可核对候选的日期、状态、负责人及内容；已删除目标不能沿用，接口也会拒绝。不同工地绝不互相去重。
- 原始 Note 和项目说明不删除、不改写。原文、负责人、日期、完成状态和任务关联原样留存在来源与备份中；新目标保存适配后的字段。可获得的真实历史与快照保留，迁移操作使用当前登录身份与服务端时间，不伪造原创建时间。
- 首页只隐藏“已建立映射、旧来源未变且本地没有未保存修改”的重复投影。修改后的旧来源重新进入核对视图；新目标可继续正常编辑和完成。

## 备份、事务与数据库兼容

增量结构迁移为 `server/migrations/012_legacy_classification.sql`，仅新增 `legacy_migration_batch` 和 `legacy_record_link`，不自动迁移业务内容、不重置旧表。001—011 未修改。

负责人先下载原始 JSON 备份，核对分类及实际操作对象，二次确认后才提交。服务器在同一事务中再次保存迁移前的完整工作空间、版本历史、看板记录与历史、采购追溯和现有来源映射。备份直接读取数据库原始载荷，包含仍存于数据库、但已超出普通界面保留期的历史，不使用截断后的界面历史替代原始备份。任何一条失败，目标写入、映射、历史、批次全部回滚。成功后的前置备份可再次下载。

预览签名绑定工作室、当前账号、工作空间与看板内容、来源映射及十分钟有效期；其他客户端更新后拒绝旧预览，要求重新核对。真实重复请求先读回执，既不会重复创建，也不会因已成功提交而误报过期。

运行账号仅具有新表 SELECT/INSERT 和序列权限；UPDATE/DELETE 被撤销并有数据库不可变触发器。部署授权代码已增加这两个表和序列；此次只对本地独立测试库应用了 012。部署脚本测试仅使用临时目录、测试证书和本机服务，没有执行生产部署。

生产环境仍须在后续部署阶段核对 012 与最小授权，并在取得创始人确认、完成可恢复数据库备份后，另外执行历史业务迁移。不能把提交代码、应用结构迁移或打开预览等同于历史数据已迁移。成功迁移后的恢复应由负责人结合完整数据库备份和后续新写入制定恢复操作，不能将旧 JSON 整体覆盖当前工作空间。

## 独立测试样本（不代表生产数量）

API 代表样本包含 8 条旧 Note 和 1 条项目说明，共 9 条来源：建议采购 3、事项 2、资料 2、待确认 2。

首次确认 7 条明确来源，实际新增采购 2、看板事项 1、沿用现有目标 2、保留资料 2；随后人工确认剩余 2 条。所有原始 Note 和施工任务保持不变，完成状态保留。另一个案例覆盖同名旧来源、跨工地隔离、预览后并发新增人员、旧来源再次编辑和目标删除后的幂等保护。

## 验收入口和人工检查

1. 今日/明日新增记录：先选采购或事项，检查同一位置向下展开、切换确认及保存；桌面 1440/1280、手机 390/320 已有自动几何断言。
2. 事项管理 → 历史数据分类与兼容：先预览；负责人核对项目、原文、分类、重复候选，下载备份后确认选中项。普通员工只能读取，不能迁移或下载完整备份。
3. 筛选待确认，批量选择并确认归属；参考资料在历史资料筛选保留；采购编辑和事项历史可核对原始来源。
4. 实际手机软键盘、Safari/微信内置浏览器、生产数据分类抽样及备份恢复演练仍需人工验收。本地 Chromium 自动化不等于这些环境都已验证。

若已迁移的旧来源又被修改，程序明确标记待人工核对，不覆盖新目标、不创建第二条；当前不提供自动双向同步。历史中原本没有的创建人、时间或更早快照无法补造。规则分类不是语言模型推断，模糊内容保守留待确认。
