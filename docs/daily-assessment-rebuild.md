# 师傅每日考核：兼容映射与数据边界

开发前已检查 006_daily_assessments.sql、server/assessments.ts 和旧考核界面。现有记录键为工作室＋日期＋人员唯一ID＋项目唯一ID＋工种ID，状态为 pending/yes/no；人员/项目/工种名称是记录快照，created*/updated* 由服务端填写，assessment_history 为不可变修改历史。

新版共用 daily_assessment、assessment_history、assessment_submission 和原账号授权，不建第二套业务记录表，不改原迁移SQL，不访问或修改生产数据库。生产数量、来源及是否存在同日多工种记录尚未核查，测试数据不能代表生产数据。

兼容映射：

- 只有一条来源的“日期＋人员＋项目”直接读取。
- 同日多工种来源在界面只读按天分组。相同非待记录状态按一个人日计算；同时存在 yes/no 的项标记为待核对，不计完成天数，也不算失败。所有工种来源和历史保留可查看。
- 新建记录使用原表的 daily 工种标记；服务端在既有工作室授权锁内禁止继续新建第二条同项目同人同日记录。旧多来源记录仍可按其原工种及版本编辑，不自动改键或迁移。
- 手动更改某人日的一项时，仅对该人日现有来源的这一项记录修改，保留其余字段、原始名称和首次录入信息；逐条追加服务器历史。不是启动时的数据迁移或自动合并。
- 删除/退出人员、项目后仍从记录快照读取历史，不因当前分配或档案状态丢失统计。
- 统计按项目人日计数，pending 与 no 分开；跨工地总计标明“工地天次”，并另列覆盖自然日，避免同一天多个工地被当作多个公司自然日。

备份与回退：发布沿用既有加密数据库备份和代码发布回退，不清空表、不删除旧记录。旧API/导出仍能读取全部原始来源；新 UI 替代旧大表格。任何后续物理合并、删除或生产数据迁移都需要另列清单并获得具体授权。

## 保存、协作与本地缓存

复用原有事项待同步数据库与精确回执传输，追加 assessmentDrafts 本地意图存储（IndexedDB版本1→2，不清除 pending）。这不是第二套业务考核数据库，也不是服务端SQL迁移。每条人日保留不可改写的上传快照及后续本地点击；上一快照确认后才使用确认版本继续上传，避免快速连续点击自行触发版本冲突。账号、工作室与记录键均隔离。

网络失败保留快照并安全重试同一回执；真正的409或权限/校验失败保留全部本地选择，行内显示云端值及待提交项。只有用户核对后才按最新版本重试，且旧失败回执在替代提交确认前继续保留。确认响应校验身份键、版本及本次字段值后才清除队列。普通项目备份不新增考核数据；显式下载“未同步内容”时包含本账号的考核草稿与未确认快照。

服务端沿用原工作室授权锁、单记录版本、幂等回执及逐次历史。不同工地/人员修改不会以整个考核列表覆盖；新记录按人日唯一，旧多工种记录按其原键编辑。复用现有SSE连接通知有权查看的界面，授权与撤销也自动刷新，并保留30秒读刷新兜底。页面只读统计使用同一批确认来源；待同步项明确提示，不虚标为云端成功或计入完成天数。

## 生产核查边界

没有连接生产数据库、迁移或合并生产记录、删除真实数据或自动部署阿里云。生产旧记录的实际数量、分组来源及是否存在异常格式尚未直接核查；发布后仍需以真实工作室数据核对。若需物理合并或修复异常历史记录，必须另列清单、备份和回滚方案并取得批准，不能把本轮UI只读汇总当作此类授权。

可由运维针对目标工作室进行以下只读库存核查（$1为工作室ID参数），不要用测试数量替代其结果：

```sql
SELECT count(*) AS original_records,
       count(DISTINCT (work_date, person_id, project_id)) AS daily_groups,
       count(*) FILTER (WHERE work_date > (now() AT TIME ZONE 'Asia/Shanghai')::date) AS future_legacy_records
FROM daily_assessment WHERE workspace_id=$1;

SELECT work_date, person_id, project_id, count(*) AS source_count
FROM daily_assessment WHERE workspace_id=$1
GROUP BY work_date, person_id, project_id HAVING count(*) > 1;
```

现有正常006结构记录可直接由新版读取。未来日期的旧记录仍保留在原表和原读取/导出API，不作为今天前的累计或允许新增的未来打卡。代码回退不需要撤销表结构；本地队列追加存储仍保留原待同步数据，使用旧版缓存代码的标签页应刷新后再继续操作。
