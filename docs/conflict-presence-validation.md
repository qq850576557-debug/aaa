# 冲突提示与在线状态

日期：2026-11-03（北京时间）。基线 `3a0e781079915ecd46e786b8f1c5a2dba6a0937e`，分支 `feat/chunmo-project-manager`。

## 实现

施工工期标题右侧、日期和操作按钮左侧显示浅橙色圆角提示。单条仅显示人员姓名及两个工地，多条显示“人员冲突 × N”。点击展开列表和详情，悬停条目可查看原生提示；详情保留人员ID、地址/房号、工种、任务、日期、重叠天数和核对任务入口。点击外部或Escape收起，无冲突不显示。

原 `staffConflicts`、人员唯一ID、实际任务日期和继承/独立分配规则均未修改。同名或同工种不会自动当作同一个人。历史不确定关联保留在人员管理的小型折叠区，不伪装成已确认冲突。

顶部本人头像和在线人员头像恢复同尺寸绿色、黄色、灰色状态点及状态悬停提示，保留原名片和照片布局。绿为前台可见、聚焦且最近5分钟有操作；隐藏、失焦或空闲5分钟为黄。返回前台本身不更新活动时间，之后鼠标、键盘、滚轮等交互才恢复活跃。

每次SSE连接有随机标签页ID。客户端仅上报状态和距上次交互时长，不采集鼠标轨迹或操作正文。正常心跳每30秒一次，状态切换合并到至多约每750ms一次；1秒本地检查不会每秒请求。服务端复用现有账号、会话、CSRF及工作空间边界，拒绝替其他连接/会话上报状态；状态变化通过原SSE通知其他用户。列表每60秒兜底读取，SSE每30秒校对，回到前台立即刷新。

同一账号跨标签页、独立登录设备按“任一活跃→绿，否则任一忙碌→黄，否则离线”汇总。明确注销或关闭连接后剔除相应连接，不影响其他设备。连续180秒无心跳按离线展示；仅在线租约过期，不删除登录会话、不关闭业务SSE、不影响IndexedDB保存和后台同步。新心跳可恢复在线。180秒窗口容纳常见后台分钟级计时器节流；系统彻底冻结页面超过该窗口仍可能按心跳超时离线，这是客户端无法继续证明连接活跃的情况。

在线租约仅保存在当前API进程内存，无新表、迁移、付费服务或业务写入。服务重启后现有EventSource重连并重新上报；沿用现有每账号连接数量上限。未来若改为多个API进程，需要共享在线租约存储，当前单API部署不受影响。

## 需要人工验收的桌面环境行为

运行环境没有有界面的桌面及窗口管理器。无头Chromium不会可靠地把切到其他标签页转成hidden，因此不能把注入事件的测试冒充真实OS窗口验收。真实浏览器标签切换、最小化、Alt-Tab切换其他App与返回，需在Windows/macOS桌面由人工补验；测试点为黄点持续、返回并操作后变绿、其他账号同步以及多设备汇总。上述人工项目未记为自动化通过，也不意味着缺少事件处理实现。

浏览器不能精确识别所有被其他App部分遮挡的情况：若没有失焦/hidden信号，只能依据空闲时长判断，不宣称能检测屏幕遮挡。测试时不要清除网站IndexedDB，避免损失未同步内容。
