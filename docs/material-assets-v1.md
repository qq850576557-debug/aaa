# 材料资产、消耗分析与预警 V1（2026-10-28）

本轮沿 `feat/chunmo-project-manager` 增量开发，未连接或部署 ECS，未修改 main、IndexedDB 或已有业务记录。以下为实际实现口径；校准概率、机器学习和自动处罚均未实现。

## 入口与权限

云端登录后左侧「材料资产管理」，有材料总览、工地材料台账、采购/领用/库存流水、跨工地余料调拨、材料消耗分析、异常预警与处理记录、历史统计及 CSV 七个子页面。

负责人始终有权。普通员工默认没有材料 API、CSV、历史和预警读取权；负责人在「材料权限」中分别授权材料管理人。该授权不包含员工隐私、账号管理或考核权限。材料管理人可登记和核查本工作室材料；规格字典、冲销及重开仅负责人操作。身份、工作室范围、CSRF、关联关系均在服务端检查，不能通过前端参数指定操作人。

## 关联及迁移

- `007_member_cards.sql`：部门、员工名片，入职日期仅本人及负责人通过 API 获取。部门停用保留历史，已分配部门禁止删除。
- `008_material_assets.sql`：材料规格 `material_item`、项目比较条件 `material_project_meta`、施工核算对象 `material_context`、不可变流水 `material_event`、核查事项 `material_alert`、追加历史 `material_history`、材料权限 `material_operator`。
- 项目比较条件附着现有项目 ID；核算对象引用现有项目、工种、任务、人员 ID，流水可关联现有采购事项 ID。服务器验证关联，未另建一套项目/师傅目录。班组名称是本次核算标签，不新建人员身份。
- 材料规格 ID 代表类别、规格、性能、单位和换算规则的固定组合；一旦被引用，不能修改这些比较条件，须新增规格。可修改名称或停用，原流水保留名称、单位、数量、换算、操作人当时名称和服务器时间。
- 已应用迁移不修改；部署白名单同步批准两项增量迁移及最小 SQL 权限。全新表不回填虚构历史或把旧采购计划自动当成入库。
- 流水/历史禁止运行时 SQL UPDATE、DELETE，并有数据库不可变触发器。主工作空间事务锁串行提交库存修改；配置及预警使用版本冲突检查，过期操作明确拒绝；请求 UUID + 内容摘要实现安全重试。

## 可审计的核算规则

数量精度为 0.001，单价为元/基准单位、两位小数；内部使用 BigInt 数量和微元价值，移动加权成本随库存转移，仅展示时四舍五入。单价由凭据人工录入，零单价按零入账，成本分析前须核实，系统不自动推定市场价。

| 流水          | 库存/消耗影响                                                                                    |
| ------------- | ------------------------------------------------------------------------------------------------ |
| 期初库存      | 仅允许该工地规格的首条库存流水，增加现场资产                                                     |
| 采购订单      | 只累计订单量，不增加库存，不作为实际使用                                                         |
| 采购入场      | 增加现场数量和账面价值，可关联现有采购事项                                                       |
| 领用/班组退回 | 在现场和对应阶段/班组保管库存间转移，非实际消耗                                                  |
| 确认实际使用  | 从班组库存扣减，计入该核算阶段已使用量和成本                                                     |
| 现场/班组损耗 | 必须明确施工核算对象，单独累计确认损耗及其成本                                                   |
| 供应商退货    | 扣减现场资产，非实际使用；现金退款金额尚无独立财务模块                                           |
| 跨工地调拨    | 单条不可变流水、同一事务增减双方，同数量同账面价值；不足或接收台账关闭则整体回滚                 |
| 现场/班组盘点 | 记录实存及账实差，不自动当损耗或擅自改账；后续正常库存移动结转已知实存                           |
| 核实盘盈/盘亏 | 必须关联最新盘点，方向及数量受待核差额约束；盘亏可部分确认为损耗，其他差异单独调整，不重复扣实存 |
| 清仓关闭      | 项目已完工且现场、班组余料和未核实差异均为零才能关闭；重开仅负责人                               |
| 冲销          | 追加反向记录，不删除；有后续未冲销库存操作或更晚盘点时拒绝，先核查后续流水或按盘点调整           |

所有流水记录实际发生日期，不能未来记账；现有采购计划继续承担未来采购安排。库存流水按该工地/规格日期顺序追加，不回写过去余额。调拨同时检查两端日期。领用、消耗及损耗校验真实核算对象；任何操作不能使账面数量/价值或已知盘点实存为负。

期间数量勾稽：期初 + 本期期初建账 + 入场 + 调入 − 调出 − 供应商退货 − 实际使用 − 确认损耗 + 核实调整 = 期末账面。领用/班组退回仅改变保管地点。没有期末当天完整实盘时，期末实存显示尚未完整盘点，不用账面冒充实存。三位小数不能精确表达的单位换算拒绝提交，未知单位不换算。

## 比较及预警口径

建筑面积、实际施工面积、区域面积、项目类型、户型、档次及设计条件独立记录。耗量分母**显式选择**实际施工区域面积、实际长度或涂刷面积×遍数，建筑面积不自动替代。监理维护实际进度，不由日历推定工程完成百分比；核算完成需进度100%且关联任务或项目已完成。

实际总耗 = 已确认使用 + 已确认损耗；同时分别显示两者。损耗率 = 确认损耗 / 实际总耗；单位基数耗量 = 实际总耗 / 实际施工基数。单位面积成本仅对面积基数给出，长度材料不冒用建筑面积。预算差额及成本偏差基于人工确认预算和库存结转成本，不将采购数量/金额代替耗量。

历史样本必须：其他项目、同材料规格 ID、同阶段/基数种类/涂刷遍数/工艺/铺贴方式/项目类型/户型/档次/设计条件；核算完成、实际施工面积及基数有效、无未核实盘点差异和班组未退余料、有真实总耗。一个项目多个可比区域按施工基数加权合成**一个项目样本**，不按流水或区域数量冒充项目样本。

至少5个独立可比历史项目才显示均值、中位数与 `max(0,Q1−1.5IQR) … Q3+1.5IQR` 参考区间。分位数采用线性插值；这是可复核统计范围，并非置信区间或校准概率。进度不足20%或当前资料不全不推算完工超耗；其余按 `实际总耗 / 进度` 线性外推，仅供现场核查，不宣称预测模型验证。预算已超可独立触发预警，不依赖历史样本；未核实盘点差异单独触发。

每项预警包含来源、条件、样本数、参考项目、缺失数据、风险级别和建议。始终不显示虚构精确概率。状态「待核查 → 核查中 → 已确认正常/异常 → 已处理 → 已关闭」按允许路径处理，负责人/授权人可指定本工作室责任账号，每次理由必填、CAS、保留操作人和前后历史。源条件消失不自动关闭，变化时重新提示核查。

提醒中心读取**同一 material_alert**，不复制成互不关联的备忘录。统计入口可追溯原始流水/操作历史，CSV 包含稳定 ID、原始/基准单位及换算、引用、成本和服务器操作元数据，并处理电子表格公式注入。月/年趋势按规格及项目类型分开，不将不同规格单位强行合计或排名。趋势图按同一规格及项目类型分组，不混用数量单位；点击柱条或统计行按对应月份/年度及项目类型追溯原始流水。经过历史验证的概率模型仍待后续积累数据。

闲置提示基于近30天无现场出入库且有现场余料；调拨建议基于同规格余料、接收工地预算缺口及已有任务计划，仅是需人工核对的候选，多个建议共享同一源库存，不代表可同时全部执行。实际提交由数据库库存检查约束。

## 备份与恢复边界

项目 JSON、15天项目版本只包含原有业务图谱，**不包含**材料台账、独立考核、账号名片、入职日期或授权。项目版本恢复不会覆盖、级联删除这些记录；引用原项目暂时移除时保留原始快照并提示缺失，不自动生成另一个项目。恢复项目后核查材料比较条件并点击刷新核算。若任务/工种关联或完工状态已变化，分析会标记待复核并排除该历史样本，不静默拿旧核算结论比较。

完整备份使用既有服务器 AES-256-GCM 加密 pg_dump，动态覆盖新表；密钥与备份需按现有流程分别保管，受限权限，不放Git。CSV为统计凭据副本，不是完整恢复格式。材料误操作走追加更正；数据库灾难恢复必须先在新隔离库验证，再按原有授权恢复流程操作，禁止自动覆盖生产。

本轮在本地 PostgreSQL17 新建的隔离库实际执行原 backup/restoreCheck：包含9张新表的正样本、名片私密日期、完整数量/微元成本、授权及历史均原样恢复，所有表行数、外键约束和加密校验通过，原库及验证库保留。没有操作 ECS。

## 验收步骤

1. 负责人登录 → 材料资产管理 → 新增规格（如瓷砖m²，明确箱换算），登记项目比较条件及施工核算阶段，关联原有工种/任务/师傅，填真实基数、预算、工艺。
2. 登记期初/入场 → 领用 → 确认使用，检查采购订单不增库存、领用不算使用；退余料/供应商退货/调拨后核对两工地数量和价值。
3. 记录现场/班组实盘，检查差异未自动变损耗；关联盘点分别确认损耗、核实调整。零库存且项目完成后才清仓关闭。
4. 分析页看预算差额、成本及样本提示；使用5个独立已核算同类项目验证均值/中位数/IQR，改变工艺/规格/基数确认不再混比。可从参考项目跳原始流水。
5. 超预算或盘点差异 → 预警，指定责任账号、填写核查原因/确认/处理/复核关闭，查看修改历史；提醒中心使用同一条记录。导出原始及趋势CSV核对真实行数和引用。
6. 两个账号同时超库存调拨：只能一方成功；同请求重复发送只记一次。未授权员工直接调用材料/导出/历史API拒绝；授权不扩大隐私权限。
7. 刷新网页、15天恢复原项目后核对独立流水不变；完整备份应在隔离库恢复验证，不能拿项目JSON当数据库恢复。
