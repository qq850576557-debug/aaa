# 头像、个人名片与全局按钮验证

本轮基于 `feat/chunmo-project-manager` / `f02ec456c27954bd502f1476e8aa384a69a6f0f6` 开发，开始时工作区干净。仅本地修改与隔离测试，不提交发布、不部署、不连接生产数据库。

## 原错误的实际原因

原接口允许小于 2MB、名片照片长边最多 1024px 的 PNG；`005_account_avatar.sql`、`009_experience_v11.sql` 中两张头像表均限制图片字段不超过 524288 字节。较大 PNG 经旧验证器通过后，触发 PostgreSQL `23514` 检查约束，错误中间件把它显示为“记录冲突或关联校验失败”。

已用 HEAD 中的旧验证器、700×700 测试噪声 PNG 和本地隔离测试库复现：验证器接受 **1677068 字节**，数据库拒绝 `23514 card_avatar_png_check`，事务失败后无无效记录。日志 `/tmp/chunmo-avatar-root-cause.log`。

头像接口一直使用当前认证账号 ID，未使用员工/人员 ID，也没有参加 workspace 的全局 CAS。本轮仍保持独立接口、现有会话/CSRF/权限及审计；未修改此前多人保存合并逻辑。

## 分辨率与裁切规则

开发中用户明确调整为“720也可以，反正就不留边后能保持清晰一些”。因此新规则为：

- **原图短边至少720px**，建议1080px以上；前端立即检查，后端解码真实像素再次检查。不是仍执行最初的1080px硬门槛。
- PNG、JPEG、WebP 原图最大10MB，沿用1600万像素处理上限；拒绝活动格式、多帧图片、损坏文件及越界裁切。
- 直接上传所选原文件，不先缩成旧版256/1024px缩略图。服务器处理方向信息、解码、裁切、去元数据，再编码保存。
- 个人名片读取实际照片框宽高比进行裁切；没有留边，没有拉伸，没有将低像素放大。系统在线头像使用独立正方形裁切。
- 裁切框为圆角矩形，支持鼠标/触控拖动、滚轮/按钮/滑杆缩放、实时预览、重新裁切、重新选择、取消及保存。
- 缩放上限由源图实际像素决定。比如720px宽的竖图裁满横向框时，输出高度会小于720px；界面显示真实裁切尺寸，不虚构1080px输出。
- 保存宽度最多1440px且从不放大；前端控制裁切宽度至少720px，服务器还拒绝过窄/像素不足的裁切。不同构图输出高度随比例变化。
- 服务端以 JPEG 质量90→60逐档压缩到**现有512KiB限制以内**，不通过继续降低像素来凑体积。无法满足时明确拒绝并保留候选图。历史 PNG 原字节不改动、仍可读取；读取接口根据实际格式返回 MIME。
- 使用新增的 `sharp` 处理 JPEG/WebP/PNG 的真实解码与方向，锁文件已更新；没有数据库迁移或上传目录/文件权限变更。未来发布需完整安装新的运行依赖，不能只替换前端静态文件。

应用能保证本链路不放大像素，无法可靠鉴别用户事先用外部软件放大过的文件，不声称能验证照片原始真实性。

## 保存可靠性与权限

失败后候选原图、位置、缩放及预览保留，可直接重试。前端用同步提交锁与禁用状态防止连击；服务端条件 upsert 和内容摘要版本使重复图片不重复创建记录或审计。同一账号的系统头像和名片照片独立保存。

不接受客户端指定其他账号 ID；跨工作室读取仍拒绝。图片超过存储限制会在服务端处理阶段被拦截，不等待数据库抛通用关联错误。测试还验证照片更新与工地数据保存同时成功、工地 revision 不因照片更新递增。

## 名片和公共按钮

- 唯一“更换照片”入口位于主照片右下角。底部重复设置区及重复文件选择控件删除；保存、取消及恢复默认操作集中到裁切流程。
- 账号设置与部门管理移到独立的正常流操作区。错误与分辨率提示为普通文档流，桌面、手机均验证无覆盖。
- 仍使用 `/brand/chunmo-plant.png` 原始资产；调整 SJD/春茉字重、间距和基线，编辑名片使用浅绿胶囊按钮。
- `src/buttons.css` 统一主/次/危险/完成操作及图标按钮背景，悬停上浮、按下缩放、禁用、加载、键盘焦点和减少动态效果。
- 交互过渡150–180ms，采用 CSS translate/scale；没有 JavaScript逐帧动画。任务条和颜色控件保留原本业务颜色；拖动热点不套用按钮上浮/缩放。
- 已按七个主要页面逐个检查可见按钮背景：项目工作空间、事项管理、采购管理、提醒中心、已完工项目、人员管理、材料资产管理；另覆盖账号、名片、部门、裁切、确认弹窗、甘特图、日期面板和导出操作。
