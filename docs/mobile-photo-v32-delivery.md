# 照片缩略图、多选与逐张保存 V3.2

## 交互与保存方式

全屏连续拍摄保持原有流程。完成拍摄后显示三列水印缩略图、拍摄数量和全选，默认全部选中。点缩略图切换选择，右下角图标保存该张照片；底部固定「保存选中照片（N张）」并避开手机导航和安全区域。保留继续拍摄，已有文件不会因继续拍摄被清理。

- **批量**：按选择提前从IndexedDB准备完整高清JPEG File，在用户点击中直接检测并调用Web Share。准备文件和水印处理不插在系统分享调用之前。不支持时提示「当前浏览器不支持批量保存，请逐张保存」；数量或大小受限时提示减少选择分批处理。File缓存预算64MiB，超预算不会默默只导出一部分，不降低输出分辨率。
- **单张**：已准备文件优先系统图片分享；不支持时，兼容安卓/桌面浏览器发起一次JPEG下载，提示到Downloads/下载目录确认。iPhone或缺少下载能力时在当前页面显示完整照片供长按保存。未缓存的单张先异步准备预览，再通过新的明确点击发起分享/下载，保留有效用户手势。
- **失败**：权限、参数、数据限制及取消显示具体原因。系统分享长时间不返回也有提示，单张下载/预览仍可使用。没有顶层Blob导航，没有连续触发多张下载，也不把分享返回或下载请求当作系统相册成功。
- **删除**：分享、下载、取消、关闭或返回均不自动删照片；只有点「删除选中照片」并确认范围后才删除这些ID的本机暂存。处理中禁止删除，确认取消保留文件和选择。原始捕获处理失败时仍保留唯一原文件及恢复出口。

拍摄完毕界面示例见[三列缩略图及保存按钮](screenshots/photo-v32/selection-and-save-390.png)，图片和账号为隔离测试资料，示例显示已请求单张下载后的状态。

## ZIP清理与存储兼容

删除 `photo-zip.ts`、页面ZIP按钮/说明、ZIP专用单元测试和样式。本轮没有新增压缩依赖，之前也没有外部ZIP依赖，因此无需调整依赖清单。生产源码没有ZIP导出入口或打包实现。

| 原存储                                    | 新版处理                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `chunmo-photo-batches` v1 / `photos`      | 保持账号、工作空间、照片ID及原有 `meta/original/output/mime/error`；新增可选小型 `thumbnail` Blob，不改ID、不复制业务照片、不提升数据库版本 |
| 旧版已生成水印但无缩略图的记录            | 可见时逐张生成派生缩略图；事务只补该字段，原高清字节与元数据保持不变，不重新生成水印                                                        |
| 未处理/失败的原始捕获记录                 | 继续恢复处理或保留原文件导出；不因界面更新清理                                                                                              |
| `chunmo-site-photos` 旧照片库及旧上传队列 | 保留，不迁移、不重分类、不删除                                                                                                              |
| 上轮OPFS派生ZIP或用户已下载ZIP            | 不再创建，不扫描或删除已有文件                                                                                                              |

没有新增数据库、服务端表、云端照片库或生产迁移。本轮无法读取用户手机和生产实际照片，真实数量、来源及存储占用均未核查，不能拿测试数量代替。回滚前端代码至上一提交可继续读取相同照片库；代码回滚不清空数据，也不能恢复用户明确删除的文件。任何实际清理前由用户先导出保管。

Service Worker静态缓存模板更新到v14，构建仍生成内容哈希缓存名；仅清理旧CacheStorage，不清理IndexedDB。旧照片库与待导出库的保留有浏览器回归覆盖。

## 性能与像素

- 当前照片在生成水印的同一Canvas上顺带生成最长边240px的JPEG缩略图。导出仍读取原完整水印文件，不重新解码、加水印或压缩。
- 缩略图按可见区域加载，离开区域释放Object URL；旧记录的补生成串行处理，支持时复用水印Worker与OffscreenCanvas，兼容路径一次只解码一张。
- 相机会话内复用完整尺寸水印Canvas和摄像头；退出拍摄且处理完成后释放大Canvas，短时保留预热Logo和Worker。捕获与水印继续使用原有队列、背压及可靠暂存。
- 选择变化只准备对应File，不把全部高清文件长期转为Base64；单张长按预览才创建一个完整Data URL，退出后释放引用。真实本地写入失败保留内存恢复与明确提示。

最终Linux Chromium模拟20张连续拍摄：首帧145.9ms（单次），快门至本地可靠暂存中位63.1ms/p95 90.0ms，水印中位77.2ms/p95 105.6ms，缓存缩略图读取中位3.3ms。10张观测到0次、20张观测到1次超过50ms主线程长任务。完整分段见[性能记录](mobile-photo-v32-performance.json)。这些不是华为/vivo/iPhone硬件实测或受控前后对比，不能据此承诺所有手机无卡顿。

模拟视频输出3840×2160；静态回归4000×3000。单张实际下载JPEG可以解码，像素为4000×3000，并与IndexedDB完整水印文件逐字节相同。缩略图不参与最终导出文件构造。

## 验证与限制

- 227项单元测试通过：包含账号隔离、准确删除ID、派生缩略图缓存不改源文件/元数据，以及原业务逻辑。
- 29项手机浏览器回归通过：三列布局、全选/多选、实际JPEG下载和字节/像素核对、10/20连拍与选择保存、取消保留、系统分享异常和不返回、原生手势、无分享接口、iPhone式长按预览、继续拍摄、删除确认、刷新恢复、旧记录补缩略图的Worker/兼容两条路径，以及原事项采购和PWA缓存更新。
- 类型检查、生产前端/API构建和部署工具构建通过。未修改电脑端业务布局、服务器接口、数据库结构或生产数据。
- **华为、vivo、iPhone实机均未连接验证**。自动化模拟只证明接口分支与本机文件下载，不证明系统分享菜单或相册已保存。iOS长按菜单、安卓厂商下载管理器及真实相册结果需要现场验收。

部署后建议用实际浏览器各拍两张：确认缩略图和多选，尝试批量分享；不支持则点角落按钮，核对下载文件或长按相册结果。未导出前不要清理网站数据或卸载PWA。没有生产部署、生产数据库操作或未经确认的照片删除。
