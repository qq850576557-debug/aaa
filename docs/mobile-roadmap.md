# .cn、公众号与移动端后续路线图（规划，未上线）

2026-10-27。本轮仅完成师傅手工考核闭环的代码与测试，尚未执行生产部署；以下功能未开发、未部署，不能宣称已接通公众号、可安装App或具备实时拍照防伪能力。

## 配置与 .cn 域名切换

已检查应用 `src`、服务端配置和Vite代理：没有写死生产服务器IP。浏览器请求使用同源 `/api` 和同源SSE；`APP_ORIGIN`是服务端允许的唯一安全来源，Vite开发代理使用现有 `CHUNMO_API_TARGET`（默认仅本机4000）。域名/API部署边界保持同源，不另建跨域前端服务或放宽CORS。

域名、备案/审核、DNS和受信任证书就绪后，先用独立测试配置验收，再经负责人确认同步更新现有公网Nginx主机名/证书和运行环境 `APP_ORIGIN`（协议、域名、端口必须完全一致）。保留原IP15001及localhost8443回退入口的受控方案；不能把多个来源随意通配放行，也不能在正式切换时遗忘旧来源校验。Node与PostgreSQL继续本机监听，不自动修改安全组或关闭防火墙。

新域名的Cookie是新的host-only会话，默认让用户重新登录；不通过URL传Token，不扩大Cookie Domain，不关闭Secure/HttpOnly/SameSite或CSRF。检查密码变更/授权撤销、SSE重连、代理缓冲、健康检查、备份和回滚。切换不迁移项目或账号内部ID。本轮未切换地址或证书。

## 微信公众号

第一步可先用公众号菜单打开同一HTTPS登录页，继续当前账号密码、服务器权限。是否允许公众号菜单使用相应域名，须在获得真实账号后台能力后核验。

未来授权登录作为独立增量流程：后端保存AppID/密钥及票据，回调域名白名单；一次性state/nonce、防重放、明确用户确认；用 `(AppID, OpenID)` 唯一关联已有账号，UnionID仅在实际具备条件时使用。首次绑定须验证已有账号身份，不能按昵称/手机号猜测关联，不自动授予负责人或监理权限；解绑、离职和账号停用须撤销相关会话并审计。

保留现有密码登录与找负责人重置的方式。OAuth回调单独评估微信跨站导航下SameSite行为，可使用仅回调流程的短时受控状态凭据；不能为接OAuth整体降低当前管理系统Cookie安全属性。JS-SDK签名与票据留服务端，明确服务域名和授权范围。没有真实AppID、密钥、域名授权和测试账号，不写虚假配置、不声称已接通。

## PWA 优先，原生移动端按能力再决定

现有React/TypeScript适合渐进增加manifest、品牌图标和快捷入口，无需重写。前提是手机真正信任HTTPS；当前私有CA需要安全安装与核验，不能以“忽略证书警告”代替PWA安全条件。域名公共可信TLS更适合后续推广。

先仅提供启动外壳离线页面，认证、业务、考核、人员、审计及导出均不进入Service Worker缓存，不离线伪造保存成功。升级缓存按版本处理，退出和权限撤销及时清除应用管理的临时敏感副本，但不清理用户原有IndexedDB。浏览器/系统不同，iOS通常需手工“添加到主屏幕”，微信内置浏览器未必支持安装，不能承诺一键通用安装。

通知采用后端统一提醒数据源，客户端只展示/确认同一来源ID；Web Push或公众号消息须逐平台评估授权、可用性与送达状态，不新增互不关联的待办副本。先完成“快捷入口→安全登录→工作台”一条流程，再考虑消息推送、移动考勤。若未来相机/相册原生能力不足，可评估Capacitor封装及必要原生插件，而非另写全部业务或提前发布不受控安装包。

## 现场实时拍照：后续独立流程

**本轮不创建现场拍照页面、照片上传入口或定位采集，不把当前“已拍照”监理标签当作照片证据。**

未来数据关系：`CaptureSession`关联工作室、项目、房号、账号、短期一次性随机挑战及服务器签发/截止时间；`SitePhoto`保存会话、权限范围、原始文件对象ID、服务端接收时间、设备报告时间、经纬度/精度/失败原因、原图SHA-256及大小/媒体类型；`PhotoDerivative`关联原图、不可变水印元数据、展示图对象与摘要。操作审计只记必要标识，不把精确定位或私密对象地址写进普通审计/项目JSON。

拍摄优先应用内相机，拒绝仅以文件选择器 `capture` 属性承诺实时拍摄：浏览器仍可能提供相册，设备、模拟摄像头、GPS和时间也可伪造。需要更强约束时再增量引入原生相机插件。不能承诺绝对防伪；单一水印、EXIF或定位不是真实性证明。

上传由服务端验证账号、项目范围、会话挑战有效期、幂等键、文件大小/格式及完整解码；限制次数和并发，检查重复内容哈希、过期/重复挑战及可疑时间/位置差异。原图私有保留，展示水印由受控服务生成并绑定同一不可变记录，防止上传自行改水印的图片直接替换原图。定位失败、精度不足、设备时间偏差、离线和重试分别标识；不填假坐标或把设备时间当服务器时间。

原始高清文件保存在受权限保护的对象存储（如OSS），不塞进PostgreSQL、业务JSON或当前2GB内存ECS的Node主线程。数据库只存关系和摘要；原图、展示图的访问用短期授权URL并检查权限，异步低并发处理缩略图/水印，合理定义额度、生命周期、备份和恢复演练。公开Bucket或可猜的永久URL不可作为权限方案。

提供用户主动操作的“保存到手机相册”：PWA先检测文件分享/下载能力，明确提示系统差异；网页不能保证直接写入iOS相册或静默落盘。原生封装可在取得系统许可后保存高清文件。原图与展示版本可分别导出，避免用低分辨率Canvas截图冒充高清。精确定位属于敏感信息，需用途说明、最小采集、独立访问边界和保留策略。

## 分阶段验收约定

先独立完成域名测试切换，再做PWA快捷入口，后做OAuth绑定或现场拍照，每次只验收一条完整业务流程。所有变更增量迁移、最小权限、受控导入、并发校验和数据库/对象存储配套备份；使用独立测试账号和数据库。现有项目、账号、人员、15天历史、采购、考核和生产访问不被重写或自动覆盖。每阶段通过实际移动浏览器与后端权限测试后，由负责人另行确认部署。
