# 春茉业主 V1.0 · 第四阶段采购联调

电脑采购管理继续使用原采购主记录和状态。现有采购编辑窗口加入业主协同设置，新增窗口可一次保存内部记录与经确认的对外设置。未配置的旧采购及普通新增采购保持内部可见。只发布责任方为业主的条目，撤回保留原记录及购买反馈。没有读取生产业务行。

| 现有来源                                             | 本阶段接入                                                                                               |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `workspace_state.data.purchases`、`purchase`、`task` | 主记录不变。从现有投影取得当前最迟采购日和公司完成状态，外部名称、说明、规格、数量、参考链接须明确确认。 |
| `purchase_record`、`purchase_action`                 | 保持现有变更及完成记录。业主协同增加独立操作历史，记录操作者、时间、前后值和幂等编号。                   |
| `owner_portal` 会话与住宅授权                        | 每次读取和写入均核对有效授权、项目服务及发布状态。业主数据库角色只有经过校验的采购函数执行权。           |
| `project_permission`                                 | 创始人及具备该项目写权限的员工可操作协同。重新开启已完成采购仅限创始人，并填写原因。                     |

手机端继续使用 V1.4 页面。在打开首页、列表、详情和返回前台时读取所选住宅的采购。业主确认、修改、撤销后先等服务器保存，再重新读取；已完成记录只读。电脑端在采购卡片和提醒中心显示反馈，采购编辑窗口可以查看品牌、型号及备注，复制备注里的商品链接，并代为确认、退回待采购、确认完成或重新开启。当前仅提供消息页面内提示。

## 隔离测试

- `node scripts/test-owner-portal.mjs` 使用回环地址的临时 PostgreSQL 17。覆盖默认隐藏、原记录发布、显式项目权限、对外字段白名单、跨住宅拒绝、撤回后拒绝、家庭成员并发、相同请求重试、日期联动、公司确认、重开和删除恢复时保持未发布。
- 设置 `CHUNMO_OWNER_BROWSER_ARTIFACTS` 后，同一套测试启动 Chromium，基于实际隔离 API 查看采购窗口并保存截图。验证表单对齐、发布、普通员工隐藏与降低动态效果。
- `npm run test:miniprogram` 回归开发态预览、员工拍照和小程序 API；采购业主测试验证住宅切换、网络结果未确认时复用原请求及授权撤销。真机用实际微信登录和测试站采购做下一轮核验。

## 测试站升级与回退

仅适用于已运行身份版 `bf028df` 的 `owner-test.chmsj.cn`。从审核过的完整 Git SHA 运行 `deploy/owner-test/upgrade-purchases.sh <SHA>`。升级前确认隔离测试服务路径、数据库名和回环端口，备份测试库。017 SQL 增加协同记录、只追加操作历史、限流、查询视图、受控函数和撤下触发器。迁移记录中同时保存两份 SQL 的 SHA-256；再次执行会校验该记录。没有数据回填、自动发布或生产迁移。

测试站单独启用 `CHUNMO_OWNER_PURCHASE_ENABLED=1`。脚本切换测试 API 和 ZIP，验证测试 HTTPS、未认证拒绝、ZIP 字节、测试负责人权限及正式版本一致后输出 PASS。失败会切回身份版服务。正常回退从同一审核提交执行脚本的 `--rollback`，关停采购能力并切回原测试页面和 API，保留 017、业务记录和备份。回退前检查活动文件是否有后续变更。
