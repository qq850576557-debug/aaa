## 变更及审批边界

- 公司端沿用项目授权、一次性邀请、采购可见和代为确认。小程序沿用独立业主会话和单／多住宅切换。真实登录使用微信的登录凭证和手机号授权码，服务端核对 AppID、手机号及有效项目授权。
- 购买反馈增加独立的 HTTPS 链接及一张选填图片，和品牌、型号、备注一起保存。服务端限制输入 512 KB，将单帧 JPEG、PNG 或 WebP 重新编码为最长边不超过 1200 像素的 JPEG，剥离 EXIF。图片按内容去重，审计只存标识。移除图片后旧版本仍在归档范围内，当前采购接口不返回旧版本。
- 018 增量 SQL 及分权保持在 `server/proposed`。原 016/017、正式迁移清单、原采购记录和员工小程序入口保持原样。018 应和新代码一同验收，生产执行需单独审批。迁移在单事务执行，数据库属主应用，备份角色仅增加读取权限。应用回退可保留新字段、照片及历史。任何正式库恢复或结构回撤需另行核准。

## 真实手机联调

1. 先在隔离域名 `https://owner-test.chmsj.cn/api/health` 确认 `environment=test` 及目标 SHA。018 和同提交的网页/API 需要先安装到隔离站。已有 `deploy/owner-test/upgrade-purchases.sh` 会先备份 `chunmo_test`，核对测试套接字、存量版本及正式站版本，并校验 018 哈希与角色。隔离站 SHA 分叉时暂停核对。
2. 在微信后台确认测试 AppID 对应账号拥有手机号快速验证额度，配置 `https://owner-test.chmsj.cn` 为 request 合法域名。测试服务使用与 AppID 匹配的服务端配置。导入隔离测试 ZIP，使用开发或体验成员的微信扫码，保留合法域名校验。
3. 负责人在隔离站开启测试住宅服务，授权两位体验成员并生成一次性邀请。用开发工具自定义路径 `owner-login/pages/welcome/index?invite=当次口令` 预览，成员用自己的微信授权手机号。测试口令只私下发送。
4. 负责人在电脑端对原采购勾选「业主可见」并保存。手机检查重进、切前台、下拉都能看到变更。填写品牌、型号、HTTPS 链接、备注和一张样图，保存后在电脑端查看同一条采购及图片，再测试公司代确认。
5. 第二位家庭成员验证同一住宅可读。隔离站可另外授权第二住宅做切换测试。取消可见后，清单和原图片地址都应不可访问。撤销其中一位成员的该住宅权限并重试，核对其余项目和成员仍按授权访问。真机须核验不同手机的选图、压缩、图像显示和重新进入。

## 单住宅试点

真机和权限验收通过后，另行批准一个确切正式住宅、两位已核对的成员及两三条已确认公开的原采购。由负责人逐项核对公开内容，验证发布、反馈、代确认、撤回和权限撤销。审核记录仅保留测试结果。若项目范围、图片访问或采购同步异常，立即停用该项目的业主服务并保留记录。正式开关、018 与微信提审分别以批准的范围执行。
