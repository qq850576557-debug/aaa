# 春茉业主小程序 · 身份及授权隔离验收

## 源码与数据边界

本次基于业主分支 V1.4（`98221dc`）。员工入口、Cookie、CSRF、员工拍照链路、原采购和事项路由沿用现有实现。采购现有主数据为 `workspace_state.data.purchases`，关系投影为 `purchase`，事项为独立的 `work_record`。隔离库从空库实际应用 001–015。未查询生产行数或秘密，生产结构、启用范围和微信后台状态待审批后核实。

电脑端在已保存项目的编辑窗口提供「业主授权」。现有工作空间最高负责人身份是唯一管理员条件。服务端从员工会话取工作空间和负责人身份，继承原有来源及 CSRF 校验。支持默认关闭的项目开关、多家庭成员登记、掩码手机号、24 小时一次性邀请、单项目撤销以及重绑。重绑清除该成员所有现有会话与邀请，其他家庭成员继续有效。

业主登录入口为 `/api/mini-owner/v1/auth/login`。服务端用微信 `jscode2session` 和 `getuserphonenumber` 分别验码，并核对返回的 AppID。首次绑定须有对应手机号及项目授权的一次性邀请。已绑定身份可继续使用单独的 Bearer 会话，或以同一微信身份重新验证。业主令牌不被员工 Cookie 鉴权接受。项目接口只返回 `id`、`title` 和 `phase`，每次校验当前授权与开关。撤销一个住宅后其余授权继续有效，重绑立即使旧会话失效。

本阶段真实模式仅有身份及项目查询。真实登录后的采购区域保持空清单，业主演示模式继续使用虚构采购。已确认的 V1.4 样式和现有下载包保持原样。当前没有可用的获批微信实测凭据，官方接口使用固定域名的服务端实现，验收使用可控的微信响应与虚构手机号。微信官方真机手机号兑换、实际审核能力和费用没有核验。

## 隔离运行与验证

在有本地 Docker、已缓存 `postgres:17-alpine` 和仓库依赖的开发环境，运行：

```bash
node scripts/test-owner-portal.mjs
npm test --prefix miniprogram/chunmo-photo
npm run build
```

测试脚本每次启动只绑定本机回环地址的临时 PostgreSQL，校验所有连接均指向固定名称的隔离库，再使用不同的服务账号启动实际 HTTP 路由。通过后清理本次测试容器。验证项包括非创始人和缺 CSRF 拒绝、跨工作空间拒绝、无效邀请免调用微信、邀请重放、绑定冲突、多成员和多住宅、授权撤销、重绑及旧会话失效、员工/业主凭据隔离、项目删除恢复不复活授权、手机号掩码及数据库角色禁读内部表。

后续经批准的微信隔离联调需要独立测试 AppID、已开通的手机号能力、已审核的用途说明及获批 HTTPS 域名。AppSecret、数据库用户凭据和独立加密密钥只存测试服务的秘密配置。服务端以 `CHUNMO_OWNER_PORTAL_ENABLED=1` 启用，读取 `CHUNMO_OWNER_DATABASE_URL`、`CHUNMO_OWNER_DATA_KEY`、`CHUNMO_OWNER_WECHAT_APP_ID` 和 `CHUNMO_OWNER_WECHAT_APP_SECRET`。小程序单独的联调工作副本在 `owner-live-config.js` 填测试 HTTPS origin 和公开 AppID，只有对应 AppID 的开发版或体验版可进入真实登录。测试邀请通过调试编译路径传入，仅向该成员单独提供；正式邀请分发入口另行审批。

## 迁移与回滚待审方案

- 新增 SQL 在 `server/proposed`，现有迁移文件、批准清单和部署入口无修改。新增 `owner_portal` 模式，包含成员、项目服务、授权、邀请、会话、限流和项目字段白名单视图。项目投影删除触发器只关闭对应项目的新增授权，避免恢复同一个 ID 时旧权限复活。迁移不回填、不公开历史采购，也不修改已有业务行。
- 上线前记录目标库、已有迁移校验、实际角色及对象数量，确认加密备份及隔离恢复。审核固定提交和 SQL 哈希后，由授权迁移角色在单事务应用；独立创建非继承、非超级用户的业主数据库角色，按授权 SQL 分别授予员工运行账号与业主账号，业主角色只可用新增表和安全视图。若数据库已收回 PUBLIC CONNECT，显式向业主角色授予目标库连接。确认员工路由及两类角色的正反向权限，再考虑启用开关。
- 回滚先关闭功能并切回审核过的应用版本。保留新增授权及审计用于核查，不恢复整库覆盖正常业务写入。已向真实用户开放后，如需作废会话或移除触发器或数据，分别审批并备份。此次没有操作生产。
