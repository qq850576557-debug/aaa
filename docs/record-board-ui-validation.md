## 实际实现

### 记录状态看板

导航“记录状态看板”，默认按现有项目分列；支持状态分组、项目/状态/全文筛选及节点日期正反序/最近更新。每组显示真实数量，顶部和列底均可新增。项目列新增自动绑定项目；空状态不伪造记录。横向滚动限制在看板内部。

白色卡片展示项目、完整标题、节点日期、状态及最多三行备注/跟进摘要。点击在当前页打开右侧抽屉。详情中编辑标题、日期、状态、备注和跟进后显式保存；历史标签显示可信创建/修改人、时间、状态与日期变化及修改字段。

抽屉保持本地草稿，失败不关闭；多人更新产生版本冲突，禁止静默覆盖；提供二次确认重新读取。关闭、切换记录、离开模块及刷新时保护未保存草稿。通过复用原SSE连接的独立records事件刷新其他会话，不增加业务workspace revision，不干扰正在编辑的采购/工期。

删除前轻量二次确认；只软删除工作记录。历史和幂等记录由数据库追加保护，业务SQL账号无物理删除权限。项目投影被重建、删除或恢复后不级联清除看板记录；已移除项目的记录以项目名称快照分组，仍可收尾编辑，不支持误移到其他项目。

### 全局视觉及名片

- `workbench.css`建立统一色彩、12px卡片圆角、轻边框/阴影、字体层级和控件规则。保留品牌Logo、中文品牌字体与绿色，不使用全局zoom或批量缩字。
- 首页与其他主要页面复用同一状态分组；同步/错误/冲突/备份操作完整保留。标题、导航、统计、项目上下文、工具栏和卡片统一排版。
- 四卡保留原地展开、内部滚动和业务处理；空内容不被邻列长内容撑出大量留白，手机空卡片保持紧凑。
- 甘特保留原日期宽度、工种/任务映射及业务事件；手机日期工具栏统一44px，保持横向滚动、边缘拖动、合并和调整决策。
- 人员筛选的日期与下拉框统一真实标签间距和高度；考核授权的勾选与姓名对齐。材料子页、台账表格、采购卡片、账号标签页及常用弹窗使用一致规范。
- 名片照片区域是可键盘/触摸操作的“点击更换照片”按钮，直接打开现有文件选择器及预览。仍须点击保存后提交原授权API；拒绝无效/过大图片，保留原256px居中裁切，不宣称原始高清照片功能。
- 名片与在线头像分开存储、缓存和显示。桌面名片采用约1:1.618分栏与卡片比例，手机纵向排列并允许内容滚动。浮窗加入浅鼠尾草绿、暖米色，状态用雾蓝/暖砂/柔红少量区分；未新增聊天功能。

## 数据、权限与兼容

新增 `010_record_board.sql`：

| 表                | 用途                                                    | 保护                                                   |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------------ |
| work_record       | 项目关联、正文、状态、版本、软删除、创建/修改可信元数据 | workspace范围；普通业务SQL账号可查/增/改，不可物理删除 |
| record_history    | 创建/修改/删除事件及安全字段差异                        | 追加式触发器；无UPDATE/DELETE权限                      |
| record_submission | 请求UUID、操作账号、摘要和重试结果                      | 追加式；避免双击/网络重试重复创建                      |

无旧表改写，不修改001–009内容。沿用当前工作空间成员的业务协作权限，不授予账号管理、材料管理、考核或隐私权限。所有路由在既有认证、Origin和CSRF中间件之后；跨工作空间查询/写入被拒绝。严格输入schema不接受伪造操作人、时间、版本历史；服务器使用当前认证账号及数据库now()。

写入与项目操作采用同一workspace锁顺序；记录版本核对、正文、履历、审计及请求防重在同一事务中提交。重要自由文本历史只标记修改字段，不复制旧正文；历史并非全文版本恢复。账号展示名变化后，新事件使用新名称，既有名称快照保留。

记录状态不驱动采购完成或入库，不新增库存数量，不参与工期顺延；这些现有流程保持独立。没有改动生产公网HTTPS15001、Cookie、数据库监听、备份密钥或防火墙。

010已仅在本机隔离测试库和新建的恢复验证库应用，源测试库未清空。生产未连接或迁移。旧代码可以保留新表，但不会显示新看板；不要在未备份/未验收前自行切换生产版本。看板不在项目JSON或15天项目快照内，完整恢复使用现有加密PostgreSQL全库备份。

## 主要验收步骤

1. 负责人和员工各自登录，打开“记录状态看板”；每列应来自已有项目，数量随筛选准确改变。
2. 顶部新增手选项目；列内新增自动关联该项目，录入事项、日期、备注和跟进并保存。
3. 点击卡片打开右侧面板，改状态和日期、保存；重新打开历史，核对操作人/时间/安全差异；刷新和重新登录后仍一致。
4. 两会话打开同一记录，B留草稿、A保存；B收到变更提示，尝试旧版本保存被拒，草稿不丢。确认重新读取后再提交。
5. 关闭/切换记录/离开模块时取消放弃应保留草稿。删除先取消，再确认；看板移除记录、服务端履历保留，其他业务不减少。
6. 操作项目/状态/搜索/排序，横向滚动查看更多列；在手机上触摸新增、填写和保存，不应发生整页横向溢出或底部按钮遮挡。
7. 点击本人头像→个人名片→点击照片→选择→预览→保存；账号设置内修改系统头像后，两张图不同且刷新/重新登录保留。检查部门、岗位及入职日期仍按原权限显示。
8. 对照截图检查首页、采购、材料、人员、账号、甘特；继续验证采购完成/删除、材料调拨、工期拖动/合并/图片导出和15天项目恢复。

## 范围与人工验收

- 看板初版不包含卡片拖拽、跨项目移动、日历视图、聊天或全文历史恢复。
- 看板需要真实云端登录；本地开发模式只显示说明，不伪造服务端历史，不迁移/清空IndexedDB。
- 自动化使用真实Chromium的桌面尺寸、手机尺寸及触控模拟；没有实体Windows/iPhone/Android、Safari或微信内置浏览器验收。最终品牌观感由负责人确认。
- 两个官网受网络限制未能读取；参考原则来自本轮明确要求。
- 本轮不执行ECS部署/迁移/重启，线上网页尚不会自动变化。验收后再安排010迁移与现有安全部署流程。
