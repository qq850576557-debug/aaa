# 春茉拍照1.2候选版交付

## 修改

- 账号普通文本编辑控件兼容iOS输入法；密码保持安全输入。第三方键盘受iOS及微信策略控制，不能保证可强制启用。
- 快门回调后显示180ms短暂定格，最长800ms自动清理；保持相机流，不再次编码。
- 原生高清按钮调用wx.chooseMedia，sourceType仅camera、sizeType仅original、一次一张；不从相册导入，不静默回退到内嵌相机。不承诺该接口必定是系统相机或必定返回4K。
- 保留内嵌相机original连续拍摄、16:9预览和放大品牌水印，正式成品不为匹配预览裁切或放大。
- 原生高清接口没有精确快门时间，记录调用开始至返回时段并在水印上显示“拍摄时段”；不拿回调时间冒充精确快门时间。GPS及地点凭据仍保留原采集时刻，不宣称原生相机期间持续定位。
- 结果页显示原图与成品尺寸；水印渲染记录source-pixels及最终尺寸，导出像素不匹配即报错保留原图。相册始终保存marked.jpg而不是240px缩略图。

## 验证结果与限制

16项自动测试通过；包括20次内嵌回调、一例原生原图回调及取消、所有权/CSRF/地点、队列恢复和重复保存保护。全部相机/相册回调是测试模拟，不能作为iPhone画质或相册验收。没有本次实机照片，不声称已解决1080P输出瓶颈。

用户提供旧成品1080×1917、416KB。现有original配置不能证明手机实际拍出更高像素。新版需在同一光线/固定场景对焦后分别用大快门和“原生高清”拍一张，在结果页和系统相册对照尺寸、100%细节。若两入口均只返回约2MP，不扩大像素假冒4K，应按微信版本/手机型号继续排查或使用已开发的原生App。超过现有24MP/8192边长安全合成范围时原图保留且明确提示，未擅自降低分辨率。

## 1.2.1修订与正式交付

账号textarea在真机表现高度异常且不能解决第三方键盘问题，已恢复标准type=text单行input，与密码框复用完全相同的field尺寸。密码继续安全输入；iOS/微信可能使用系统键盘，代码不能保证调用微信输入法。若系统普通文本输入也无法切换，用户在iPhone设置→通用→键盘→键盘中检查已添加微信输入法，在账号框长按地球图标切换；密码框仍可能强制系统键盘。不得称第三方键盘已修复。

结果页继续拍摄改为底部固定68px圆形深绿色按钮，带相机图形与文字；与保存按钮并排，预留安全区和列表底部空间，不覆盖照片。忙于保存时禁用，沿用现有continueCapture方法，不清理旧照片。

原生高清入口使用chooseMedia(camera,count=1,original)，每次一张返回；不能保证原生界面连拍多张后一起返回，不自动重复弹相机。页面大快门支持保持相机会话连续拍摄，完成后批量保存。两种模式明确区分。原生界面也可能受微信/设备分辨率限制，当前缺少真机尺寸报告，不能宣称已经解决高清问题。

最终Workbench发布的只是版本化源码下载地址，微信小程序需管理员导入新目录、真机测试、上传1.2.1、提交审核、审核通过后发布，才是同事使用的正式版本。无需chunmo-update、无需重装sidecar、无需修改AppSecret或数据库。不要删除手机小程序/清除存储以更新源码，保护未保存照片。

## 1.2.2：独立账号页与密码页

1.2.1真机仍未出现第三方键盘，不声称已修复。1.2.2将账号和密码拆为两个独立页面：pages/login/index只有普通text账号输入与下一步，redirectTo销毁账号页后进入pages/password/index；该页展示不可编辑账号及安全密码输入。修改账号时清空密码并redirectTo退出密码页。不用textarea、不混排两个输入框、不降低密码安全性，也不以键盘受限为理由改员工账号或密码。

账号仅通过App实例内存临时传递，不放URL、日志或永久存储；密码仍仅用于既有登录接口，切后台清空输入，认证/CSRF/权限/旧照片恢复未变。新版客户端无需更新sidecar、网站或数据库。

17项测试通过，新增独立页面测试覆盖中文账号、空账号、账户修改、密码切后台清空、认证失败/成功、直接进入密码页的守卫及原有地点页面跳转。WCC编译7份WXML、WCSC编译8份WXSS通过（工具包miniprogram-compiler 0.2.3所带编译器，不代替当前开发工具真机验收）。无iPhone实机，不能保证此次规避安全输入分组一定使第三方键盘出现；iOS/微信可继续限制键盘扩展。用户需在新账号页验证键盘地球菜单，若仍不出现，不再声称通过代码可以强制启用微信输入法。
