# 春茉工地拍照｜微信小程序 V1.0 交付与验收

开发基线：`315769e8a0c28ce7afb8be03b6d207bf9c89c9ea`。本轮新增独立 `miniprogram/chunmo-photo` 和默认关闭的服务端窄适配层。不修改原网页/iPhone拍照流程、Android/Harmony工程、数据库结构或旧照片。

## 1. 当前交付范围

- 原生小程序四页：品牌登录、附近地点、沉浸相机、三列照片结果。没有 WebView、ZIP、云端照片上传、工期/采购等无关页面。
- 使用现有员工账号，不使用微信 openid 创建第二套人员资料。真实姓名来自原会话和 `/api/site-photos/config` 的交叉校验，不提供编辑姓名入口。
- `getLocation(type:wgs84)` 获取真实定位，精度不超过100米。服务端继续完成 WGS84→GCJ02、2公里POI筛选、签名、账号绑定及90秒有效期；无手填地点。搜索/分页/去重/按距离排序；刷新GPS时重置分页，防止混用不同位置的距离。
- 确认地点后打开一次 CameraContext，按快门使用 `quality:original`；完成一张不重建camera。地点凭据临近过期时重新获取GPS并调用原续期接口，仍在有效范围内才继续；过期、精度不足或拒绝定位时暂停拍摄。
- 快门→平台文件→专用用户目录完整复制及摘要核对→串行水印→相册保存逐张回执。结果页支持选中保存、单张保存、重试、继续拍摄和明确确认后删除指定本机副本。
- 相机停止/切后台时不伪装继续拍摄。返回后显式继续取景；正常连拍不反复申请权限。

这是一份可导入开发者工具、接入真实AppID后验收的工程，不是已经发布的小程序。未取得AppID/配置测试服务前，无法承诺真实微信扫码可用。

## 2. 能力核查与边界

核查来源：微信官方公开 `wechat-miniprogram/api-typings` 声明（隔离工具安装 `miniprogram-api-typings@5.3.1`），WCC/WCSC来自 `miniprogram-compiler@0.2.3`。官方文档网站在当前执行环境被网络策略拒绝，未冒充已完整访问最新版文档；上架前需在微信后台复核权限准入和对应基础库。

| 能力                                                                                                                      | 本轮实现/限制                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [CameraContext.takePhoto](https://developers.weixin.qq.com/miniprogram/dev/api/media/camera/CameraContext.takePhoto.html) | 正式接口支持high/normal/low/original。使用original取得实际照片文件，不截取预览放大。没有公开声明保证固定连拍速率或所有手机输出系统相机最大像素；20张实机待验。                           |
| [Canvas2D导出](https://developers.weixin.qq.com/miniprogram/dev/api/canvas/wx.canvasToTempFilePath.html)                  | 使用原照片像素创建Canvas，JPEG质量0.95；再次检查实际输出尺寸，发现缩小就拒绝冒充原像素。没有Web Worker处理Canvas的虚假承诺。                                                             |
| [保存相册](https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.saveImageToPhotosAlbum.html)               | 采用兼容范围较广的逐张API，串行调用、逐张日志和success回执。没有使用最新基础库才支持的批量API。授权状态有效时复用；系统/微信撤销授权后需重新授权，不能保证永久授权或绝不再出现平台提示。 |

| iPhone/Android/鸿蒙微信                                                                                                   | 源码采用同一正式小程序API；当前没有三类手机或DevTools连接，不能推定鸿蒙相册一定与安卓等价。分别核对相册实存结果。                                                                        |
| 方向                                                                                                                      | JPEG仅在派生解码副本将EXIF方向归一，再进行1–8矩阵旋转/翻转；原始文件不改。PNG正常方向直接处理；无法安全判断的格式/方向明确失败并保留原图。必须用各平台实际相机文件再验。                 |

当前安全处理上限：单张24MP、最长边8192；超限保留原图并提示，不静默压到1080P，不放大低清预览。Canvas分配/编码失败也保留原图。相机原始输出是否超过此限制需真机确认，再依据测量调整，不为了速度默认压低所有安卓画质。

正式照片使用原稿Logo（SHA-256 `611a63cc6e1e5f8e4271f94e55b449e1f48f074648c7996fa5d1878afcffb831`），圆形裁切、品牌字号32/正文24的原设计比例，底板不透明度0.55。字段为春茉设计、选定地点、拍摄时刻及服务端姓名，不自动加“附近”。预览按同一布局计算文字；原生camera取景裁切因机型不同，不能用预览尺寸冒充最终成片尺寸。

拍摄时间记录实际快门请求时刻（ISO原值），显示Asia/Shanghai。当前跨平台 CameraContext 不保证提供硬件曝光时间，未使用上传/相册写入时间替代。原始EXIF留在原图，不对其伪造。

## 3. 认证与后端适配

原网页要求可信Origin。微信请求不能依赖浏览器Origin和自动Cookie，不应关闭CSRF、允许任意Origin或把客户端伪造Origin作为唯一信任。

新增 `server/miniprogram-photo.ts`，默认关闭：

1. `POST /api/mini-photo/bootstrap` 接收一次性 `wx.login` code，服务端向微信 `jscode2session` 验证；限制来源Referer、JSON大小、IP/全局频率及并发。AppSecret仅在服务端，code/openid/session_key不记录日志。
2. 返回10分钟、带独立用途HMAC的传输凭据。不返回openid/session_key，不落微信身份表，不授予员工权限。
3. 小程序后续发送 `X-Chunmo-Mini-Proof`，服务器核验签名/有效期后，仅将精确白名单路径转给原有处理链；原网页Origin校验保持不变。员工Cookie、登录限速、CSRF、有效会话/账号权限仍照常校验。
4. 白名单只开放：`login→auth/login`、`session→auth/session`、`logout→auth/logout`、`identity→site-photos/config`、`nearby→site-photos/location`、`renew→site-photos/place`。不代理任意路径、工作空间写入、账号修改或照片上传。
5. 客户端仅内存持有Cookie、CSRF和微信凭据；不持久保存密码/会话。仅收到服务器明确“凭据过期、原处理尚未执行”的错误时重验重试；网络错误不盲目重复登录等操作。

待负责人批准后在**隔离HTTPS测试服务**配置，以下仅是变量名，不含真实密钥：

```text
CHUNMO_MINI_PHOTO_ENABLED=1
CHUNMO_MINI_APP_ID=wxb48a7abb3858a252
CHUNMO_MINI_APP_SECRET=由负责人通过服务器安全配置填写
```

现有APP_ORIGIN、PRIVATE_DATA_KEY、数据库账号和高德配置继续沿用该测试环境设置。私钥、AppSecret不得填写到小程序代码/Git/聊天。新增服务端出站仅为标准微信HTTPS code验证，不开放新公网端口、不购买服务。

本轮实际仅对本地 `_test` 数据库、模拟微信/高德响应验证；没有访问真实微信凭据、启用生产适配或部署阿里云。代码回滚/关闭功能开关可停用新入口，原系统照常；无需生产数据库迁移。

## 4. 照片可靠性与恢复

本机目录：`USER_DATA_PATH/chunmo-photo-v1/<workspaceId>__<actorId>/<photoId>/`。独立于旧PWA IndexedDB、Android私有目录、Harmony日志和系统相册，不扫描、迁移或清空这些旧数据。无法访问员工手机，真实历史数量未核查。

状态：`capturing → raw → ready → saving → saved`；另有 `failed/unknown/cancelled`。raw和marked写入后校验大小和摘要；每个编号日志采用先写临时文件、读回检查、再rename的方式，保留先前有效版本。成功回执先记录，未成功落日志不冒充已保存。

- 原图/水印图/缩略图和GPS/地点来源保留在专用目录。当前没有自动删除已存相册的本机副本，只有用户明确选择并确认删除指定ID；节省空间可在核实相册后操作。
- 重新登录同一账号时恢复日志，提示待处理照片。不同工作空间、不同账号不显示对方暂存；初始化失败不能沿用上一账号的engine。
- 平台保存中退出、回执超时、异常结果或日志损坏：标记unknown，先核对相册，明确确认未存后才重试。已确认saved自动跳过，不以打开分享界面表示成功。
- 平台API没有可供小程序查询相册所有照片的事务/幂等接口；在“系统实际写入但回执/日志丢失”的窗口，无法保证数学意义上exactly-once。代码采用unknown人工核对，不能强行再保存来冒充无重复。
- 原图写入失败时暂停快门、保留当前临时路径和内存恢复入口。此时若系统终止微信，尚未可靠落盘的临时文件仍可能丢失，明确提示勿退出；不能声称空间不足时也能永久保存。
- 小程序受系统后台限制，不承诺退出微信后持续处理。下次打开并登录同一账号后恢复。删除/清理微信小程序数据前必须先核对相册和待处理文件。

一次最多4张待合成原图作为背压，处理完成后自动恢复快门，没有固定总张数限制。一次只解码/合成一张高清图片，Logo缓存，小缩略图懒加载；原图不转Base64堆积。Canvas2D及异步编码在部分机型仍可能卡顿，不能将合成测试当手机性能结论。

## 6. 三平台真机验收（全部待执行）

先将操作者加入开发者/体验成员，通过已配置AppID的小程序体验版扫码。iPhone、普通Android（至少vivo）及Pura70 HarmonyOS 6.1.0/API24分别执行：

1. 记录手机型号、系统版本、微信版本、基础库版本；不收集IMEI、序列号、密码或Session。
2. 拒绝定位、相机、相册各一次：定位失败不允许新拍；相册拒绝保留本机照片，开放设置后可保存。
3. 在可检索POI地点确认最近排序、搜索/滚动加载、禁止手填。停留超过90秒，核对GPS/凭据续期；移动超出有效地点范围应要求重新选择。
4. 竖屏连续拍20张；再横屏拍2张。记录快门是否黑屏/相机重建，核对已拍/待处理/相册回执计数。完成页核对三列照片、选择及单张重试。
5. 打开**系统相册**逐张检查20张确实存在、Logo无变形、地点和人员正确、时间为拍摄时刻；读取文件详细信息/原文件确认像素，并与结果页尺寸比较，不能只看预览。
6. 临时关闭相册权限/模拟存储空间不足后重试；不得为模拟空间不足删除真实资料。不能受控注入时标待测，不虚称已通过。
7. 在合成阶段切后台/关闭小程序，重新登录相同账号检查恢复；保存中退出的unknown先人工核对，确认尚未保存再重试，不重复处理已确认saved。
8. 换另一个测试账号，确认看不到原账号暂存；回原账号文件仍在。原网页、APK和Harmony已有照片不受影响。
9. 结果页“复制性能记录”提供camera-init（initdone，不等于实际首帧）、camera-file、raw-durable、watermark-draw、photo-encode、watermark-and-durable、album-receipt等数值。记录不包含姓名/GPS/token；如要采集开发者工具网络日志须先脱敏，不上传凭据。
