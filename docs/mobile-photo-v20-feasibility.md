# 拍照极简化 V2.0：可行性与待审批实施方案

日期：2026-11-11（Asia/Shanghai）。本次交付为实施前技术判断及方案，不代表原生开发获批；尚未修改拍照功能、数据库、历史照片或未同步队列。

## 结论

当前iPhone Safari及安装后的PWA不能同时满足全部目标。实时水印预览、连续拍摄、原像素范围内的水印合成可实现；自动写入系统照片相册、并可靠确认写入成功，需要原生能力。网页下载、IndexedDB、分享完成均不等于系统相册写入成功。安卓纯PWA也没有通用可靠的相册直接写入能力。

| 能力                          | 现有PWA可行范围                                                                             | 原生拍照模块                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| GPS、附近地点、搜索、手动名称 | 复用V1.3，先确认地点后再申请相机                                                            | 复用相同服务端地点接口                                                   |
| 连续相机预览、实时水印        | 网页后置相机预览加水印覆盖层                                                                | 原生相机预览加水印覆盖层                                                 |
| 高清输出                      | 使用设备实际提供像素；浏览器不保证原生相机最高静态照片画质，iOS未必提供ImageCapture静态拍照 | 使用AVCapturePhotoOutput/CameraX实际静态照片尺寸，处理方向、清晰度及内存 |
| 连续拍摄                      | 可以，前台会话内保留相机；有内存及平台限制                                                  | 可以，保留相机会话并使用受控处理/相册写入队列                            |
| 自动写入系统相册              | 不支持；须用户通过系统分享/保存操作                                                         | 授权后通过PhotoKit/MediaStore写入并取得系统回执                          |
| 可靠识别相册成功              | Web Share不能确认用户选择了保存图片，也不能确认相册资产创建                                 | iOS相册变更成功回调；Android完成媒体库写入并发布                         |

安装为PWA不会赋予网页原生PhotoKit权限。单纯套上Capacitor或调用标准Camera.getPhoto()也不会自动获得“实时水印＋自定义连续拍摄＋水印结果写相册”的完整流程，需要对应原生模块。标准Camera插件的Web实现明确没有图库保存能力。

## 方案A：最简PWA（有明确能力缺口）

流程：点击拍照 → GPS及附近地址弹层 → 确认地址 → 全屏相机 → 连续拍摄 → 完成拍摄 → 系统分享/导出。

- 地址弹层只有搜索、地点行、手动名称、确认/取消；默认最近，分页加载。确认前不开启相机，取消返回原管理页。
- 相机页只有后置相机、实时水印、快门、已拍数量、完成。将水印覆盖在实际预览影像区域，使用与输出一致的排版数据；最终照片按捕获时刻重新合成，不能把屏幕截图放大成高清。
- 水印固定为原始Logo、春茉设计、工地定位、实际拍摄时间和登录姓名。照片文字删除“附近”；手动/POI来源、GPS、精度、原定位时间仅保留为元数据，不宣称精确验证建筑位置。
- 新照片不加入云端照片队列，不提供常驻照片管理列表，不保留长期原图/水印双份。解码/合成结束后可释放原图临时数据；保存未确认前保留水印图的可恢复副本。
- 完成拍摄后以用户手势唤起分享，平台支持时尝试多文件分享。iPhone通常仍需用户在系统界面选择“存储图像”；格式、数量和目标应用支持不一，失败时可分批导出。只能显示“已交给系统分享”，不能显示“已存入相册”。
- PWA无法判断用户是否实际保存。分享返回后不自动清除待导出照片，须用户明确确认已经在相册看到，才清理本次副本。失败、取消、关闭或重开时保留待导出内容；不能只保留易丢失的内存。

该方案可消除逐张保存及常驻照片列表，但仍有一次系统分享/保存操作和未确认照片恢复入口，不能作为“自动入相册”的完整验收版本。网页存储还可能受系统空间回收影响，不能保证与原生持久文件相同的可靠性。

## 方案B：推荐——Capacitor容器＋轻量原生拍照/相册模块

复用现有手机管理页面、登录、权限、GPS/地点服务；仅把相机、水印合成、短暂文件、相册写入放入原生模块，不新增业务数据库、云端照片服务或付费地图服务。

### iPhone实现

1. 复用地点弹层，确认后进入Swift AVFoundation后置相机。实时预览水印与输出水印使用同一品牌资产及排版参数。
2. 使用原生静态照片输出，按实际尺寸合成水印，处理横竖屏/EXIF方向及色彩；不承诺所有镜头模式都达到系统相机相同的计算摄影效果。
3. 请求相机、使用期间定位及相册添加权限；优先使用PhotoKit addOnly，仅添加新照片，不要求读取用户全部相册。权限拒绝时禁止冒报成功，提供重试授权或导出。
4. 每张使用唯一任务ID，生成水印图后写入App私有的待保存目录，再通过PHPhotoLibrary变更事务添加系统照片。收到成功回调并记录回执后，才标记“已存入相册”并清理该任务临时文件。
5. 原图只用于本次处理，水印结果完成且可恢复后释放原图。合成失败尚无水印结果时，暂保留唯一原始捕获文件用于重试，不能直接丢弃；已有水印结果时仅保留待保存水印图和任务状态，不新建长期双份照片管理系统。
6. 相机持续开启，合成及相册写入限流排队；后台处理不阻塞正常取景。队列饱和或设备内存不足时暂停快门并明确提示，不能接受拍摄后丢图。
7. 回执不确定时不盲目重复创建相册资产，先标为待核查/导出；不能把系统事务当作跨进程天然幂等接口。任务账本保留唯一编号、相册资产标识和提交/确认状态，用真机强退测试验证恢复边界。
8. 点击完成返回进入拍照前的事项/采购/首页。已提交任务继续在App允许的执行时间内处理；被系统挂起的未完成任务下次启动恢复，不承诺退出后无限后台运行。仅失败/待确认任务显示紧凑恢复入口。

原始GPS、精度、定位时间及manual/POI来源应写入最终照片可支持的EXIF/XMP元数据，并保留按账号隔离的最小本机任务/资产回执，以便区分来源及恢复不确定任务；不把手动地点标成地图验证。相册再导出对自定义元数据的保留须真机验证。不新增云端照片上传；如需要额外持久化云端拍摄元数据，须另列范围再审批，不能把未存储的信息说成后台已保留。

### Android实现

复用Capacitor界面及地点服务，拍照实现采用CameraX，保存实现采用MediaStore。Android 10及以上创建自有照片可使用媒体库插入及IS_PENDING发布流程，避免不必要的全相册读取权限；更老版本须单独评估存储权限与最低支持版本。失败及中断保留私有待保存文件，确认媒体库写入成功后才清理。不能直接复用iOS的PhotoKit代码。

## 旧照片保护与切换

已检查当前代码：`PhotoAssistant.tsx`将原图、水印图和元数据写入`chunmo-site-photos` IndexedDB；`photo-queue.ts`在后台分块上传；`MobileAssistant.tsx`还有联网同步触发器。只删照片列表不会停止这些链路。

获批实施时：

- 新流程不再调用旧照片入队/上传。旧IndexedDB、私有云端照片目录、元数据、关联和未同步文件全部保留，不执行数据库迁移或删除。
- 旧照片自动重试须从新流程中隔离，旧数据处理作为单独的历史恢复入口，不在新相机中展示管理列表；不会把历史待同步改成成功，也不擅自合并到新会话或静默清理。
- 新的待相册保存/待导出任务使用独立标识及状态，仅承载失败恢复，不复用旧上传状态冒充系统相册状态。
- 不要求用户删除PWA、清除Safari网站数据或卸载旧应用。PWA与原生App的私有存储不共享，安装原生包不会自动带走PWA待上传文件；须保留旧环境直至其资料安全处理。
- 回滚只切换新流程入口，保留两套待处理文件，不自动清理任何历史资料。完整影响清单、导出及恢复方式在实际切换前核对；当前未连接或盘点生产照片数量。

## 真机验收门槛

每个获批平台：真实GPS授权/拒绝、住宅及农村等多类型地点、选择确认后进入相机、10张以上连续拍摄、横竖屏、真实像素与清晰度、逐张时间/地点/人员、无“附近”字样、在系统照片App中实际找到全部照片、拒绝相册权限/空间不足/强退恢复不丢图、失败重试不盲目重复、完成返回原页、历史照片及其它业务不变。

PWA方案验收必须明确记为“用户通过系统保存/导出”，不能勾选“自动写入相册”。没有iPhone真机时只可报告代码与模拟测试，不宣称上述真机门槛通过。本轮没有进行新功能真机测试。

## 依据与审批点

已读取官方仓库：

- [W3C Web Share规范](https://github.com/w3c/web-share/blob/main/index.html)：分享需要transient activation；分享目标由浏览器提供，不能把Promise完成等同相册资产创建。
- [Capacitor官方Camera文档](https://github.com/ionic-team/capacitor-plugins/tree/main/camera)：`Photo.saved`说明Web没有图库，始终为false；原生保存仍受授权影响。

实现时参考：[Apple PhotoKit](https://developer.apple.com/documentation/photokit)、[Android共享媒体存储](https://developer.android.com/training/data-storage/shared/media)。本次环境访问这些站点及Apple价格页被网络策略拒绝，未声称核验其最新页面内容。

按需求第六条“提交创始人批准后再进行原生开发”，建议批准方案B，先iPhone、再按需要追加Android；需明确平台范围、签名分发方式及账号/设备预算。若只批准方案A，应同时接受手动系统保存及其无法可靠确认的限制。批准前不开始原生开发、创建收费账号或部署。
