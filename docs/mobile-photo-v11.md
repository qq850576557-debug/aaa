# 手机版拍照V1.1与Safari故障修复

## 行为变化与数据兼容

名称统一为“春茉后台管理（手机版）”，主屏幕简称“春茉后台”。原始Logo、标题左对齐，账号和@通知保留，顶部/快门/底部适配安全区域。事项、采购、今日/明日记录继续原有业务流程。

底部“拍照”直接新建会话：本次高精度定位→服务端逆地理编码→网页后置相机预览。快门自动保存原图，再合成水印并保存，随后可继续拍摄，不必选择项目或确认每张照片；完成拍摄后可选归档工地。网页相机不可用时，提供已定位后的系统相机入口，需要用户再次点击以满足Safari文件选择器的手势要求。删除相册导入和“不使用定位”入口，不增加原生App。

位置请求 `maximumAge:0`，精度≤100米，定位凭据最长90秒；短会话内可复用30秒且每次快门重新检查当前位置，移动超过25米重新识别。定位失败、过期或地点无法识别阻止快门，支持重试。相机退出、页面隐藏或组件卸载立即停止媒体流，无后台追踪或IP定位。系统相机停留过久导致定位失效时仅暂存原图并标识未生成有效水印，不能用后来位置冒充拍摄时位置。

照片先以ArrayBuffer+MIME写入原本的IndexedDB photos对象库，沿用版本1，不清库、不改旧对象库版本。老Blob记录兼容读取，成功读取才可转换；读取失败保留原记录，已上传者可恢复云端副本。未完成水印的原图单独标为captured，队列不上传未完成水印；合成可重试，不靠云端保存成功保图。

已有云端完成照片不重画、不覆写。V1尚未上传、无地址凭据的照片仍可按“历史照片·未核实现场定位”兼容存档，不会变成V1.1有效定位拍摄。新拍摄live-camera/native-camera必须验证服务端地点签名，不能用客户端改名或伪造地点文字生成新格式水印。

归档只更新照片元数据，沿用现有audit_event记录关联变更与CAS版本；不重写照片字节或水印，重试去重。不关联项目也能拍摄。下载权限收紧为拍摄账号本人或同工作室负责人；其他普通账号直接请求他人照片返回403，跨工作室仍拒绝。事项/采购权限不受影响。

## Safari错误原因与相册保存

旧代码创建短期blob URL并通过a.download点击下载，Safari/PWA可能把该URL作为顶层WebKitBlobResource资源打开；对象生命周期、Safari下载支持和旧IDB Blob句柄都可能触发“错误1”。本次移除照片顶层blob导航、a.download、window.open；预览改用应用内img/data URL，新照片按字节存储，重建有效MIME的图片。水印渲染的SVG也以内嵌data URL加载，不再依赖临时blob URL。

“存入相册”在用户点击时调用系统文件分享（canShare/share）；无法分享时保持图片可长按保存。原图和水印均可内部查看。UI明确区分“已保存到应用本地”“已上传云端”和“系统分享已结束，请在照片App核对”；不把分享回调当作已写入iPhone相册，不承诺静默自动写入。

## 地点服务、密钥与费用方案（待审批配置）

采用高德Web服务 `/v3/geocode/regeo`，WGS84 GPS只为查询转换到GCJ02，原GPS/精度/获取时间不改写。查询优先住宅/楼宇AOI及neighborhood名称，过滤过远或无关商铺。返回中心点/距离不构成边界证据，因此当前均显示“附近：小区名”，不宣称已验证人在该小区内。未知或无可靠小区名称时阻止拍摄，不用项目名、IP或随机最近POI代替。

API Key只在服务端 `CHUNMO_AMAP_KEY`，还需明确配置 `CHUNMO_AMAP_ENABLED=1`。默认不开启外部请求；本轮未注册、购买、调用真实高德Key，也没有开通OSS/付费服务。高德当前免费额度、商业许可与超额费用须由创始人按控制台/合同确认，不能承诺商用免费。默认每进程每日最多200次查询，属于安全限额，进程重启会重置，不能代替高德平台的硬配额/费用控制。建议在高德控制台设置配额、余额/超额拦截，并按真实ECS出口IP配置允许来源后再批准启用，不假设旧截图IP仍有效。

坐标/名称/匹配来源/解析时间/有效期由服务端绑定账号与工作空间签名，上传验证拍摄时的有效期，不因离线上传延迟过期。普通账号不能改签名内地点或拍摄人。浏览器和GPS本身不能提供硬件级防伪证明，不能把该定位当作严格考勤证据。

## 云端照片未启用：原因与生产审批

V1生产上传刻意默认关闭；未设置CHUNMO_PHOTO_DIR即返回503。本轮无阿里云登录权限，未核查真实ECS目录、磁盘或备份，不能把本地测试结果当成生产已启用。配置检查接口现可区分disabled、unprepared-or-unwritable、low-space、ready；未准备时队列不会反复提交所有照片，原图和水印保留在本机。

继续使用现有ECS私有目录，不加数据库表、不做迁移、不购买OSS。建议 `/var/lib/chunmo-staging/site-photos`，既有API专用用户chunmo-staging-api独占0700/0600，不放在public/dist/nginx静态目录。单原图50MiB、48MP解码、每工作空间默认2GiB，水印保留实际尺寸或明确告知降级尺寸；单实例处理高像素图片，沿用640MiB服务预算，启用前需实际负载与中文字体检查。原图与水印常见每张合计5–20MiB，2GiB约容纳100–400张，实际以现场手机输出为准。

部署前需创始人批准：

1. 目录、服务用户权限、现有空闲容量、配额和告警。
2. 目录整体备份、保密/加密方式、备份位置与恢复演练；现有数据库备份不包含照片文件。备份窗口需暂停API写入或使用经过验证的一致性文件系统快照，不能把活跃上传目录的任意复制当作完整备份。
3. 高德Web服务Key、商业许可/配额和是否允许持续费用，未批准不启用。
4. 服务器字体、640MiB预算下单实例照片处理验证。

可在获准只读检查后执行 `node scripts/check-photo-store.mjs /私有目录`，仅输出数量、容量、校验错误，不输出GPS、姓名、密钥，不删除文件。恢复时暂停写入、恢复整个目录并校验全部完成照片SHA256，保留旧目录副本，失败回退目录，不回滚业务数据库。

审批后由管理员准备目录、备份并在root可读0600的服务环境文件中安全填写密钥和变量，不把Key发到聊天或写入Git。配置变量包括CHUNMO_PHOTO_DIR、CHUNMO_PHOTO_QUOTA_BYTES、CHUNMO_AMAP_KEY、CHUNMO_AMAP_ENABLED、CHUNMO_AMAP_DAILY_LIMIT。现有systemd使用/etc/chunmo-staging/runtime.env，该文件可能被现有更新器重新生成，因此应通过经过审批的systemd drop-in EnvironmentFile加入独立photo.env，不直接追加到runtime.env，以免更新时丢失配置；不能自动覆盖现有运行配置。重启/启用由管理员在批准窗口执行，本轮代码不自动部署或启用生产。

## 验证边界

实际运行隔离测试库、临时目录及生产前端构建。地图响应模拟，不消费真实Key；浏览器相机使用Chromium fake media device，不是iPhone硬件。验证位置门槛、连续三张、自动字节本地保存、短期有效定位下离线拍摄/重连续传、分享/长按提示、旧Blob读取、签名与身份防篡改、归档CAS及原照片字节不变。

真实iPhone Safari及主屏幕PWA、系统相册保存动作、真实镜头画质和实际小区匹配均未实机验收。网页视频帧不等于原生最高像素或计算摄影，保留系统相机兼容入口；不把模拟相机输出当作iPhone画质通过。长时间断网无法进行新的地址解析，会按强制定位规则阻止新拍摄，已有照片不丢弃。旧照片如果已被操作系统清理或底层Blob无法读取且未上传，本轮不能凭空恢复，但不会删除或覆盖这些记录。

本地存储失败时，下一次快门禁用，内存原图保留；应用内导航被阻止，并注册离开页面提示，直到重试保存成功，或用户明确确认已自行备份后放弃本次未保存副本。不会因系统分享回调直接清除原图。操作系统强制终止进程时无法保证尚未写入本机的内存内容，不能虚称此时已经安全保存。

审批后的配置模板（仅示例，不自动执行）：

```ini
# /etc/chunmo-staging/photo.env，root管理、0600
CHUNMO_PHOTO_DIR=/var/lib/chunmo-staging/site-photos
CHUNMO_PHOTO_QUOTA_BYTES=2147483648
CHUNMO_AMAP_ENABLED=1
CHUNMO_AMAP_KEY=<管理员在服务器安全填写Web服务Key>
CHUNMO_AMAP_DAILY_LIMIT=200
```

```ini
# /etc/systemd/system/chunmo-staging-api.service.d/photos.conf
[Service]
EnvironmentFile=/etc/chunmo-staging/photo.env
```

创建目录、填密钥、daemon-reload、重启和实际启用均等待创始人批准；本文不会执行这些命令。旧主屏幕图标名称是否随Manifest更新需iOS实机核对，不要为改名清空网站数据或删除尚有待处理照片的PWA。
